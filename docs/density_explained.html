確率密度とは何か

連続的な行動を扱うと「確率」が使えなくなる。 なぜ使えないのかと、代わりに何を使うのかを、 数字を追いながら確かめる。

35 分 Step 8-a の補助 数学の前提なし
00

この教材について

この教材のねらい

8-a で log_prob（確率密度の対数）が出てきました。 「確率」ではなく「確率密度」と書きましたが、その違いを説明していませんでした。

この教材は1 つの問いだけを追いかけます—— なぜ連続値では確率が使えないのか。 そこが分かれば、密度は自然に受け入れられます。

ゴール

この 3 つが言えるようになることです。

  1. 連続値では「ちょうどこの値になる確率」は厳密に 0
  2. 密度は高さ、確率は面積
  3. だから密度は 1 を超えてよい（確率は超えない）
01

離散なら簡単だった

この節のねらい

比較の出発点として、うまくいっていた場合を思い出します。 5-a の gridworld です。

マス目では行動が 4 択でした。ランダム方策はこう書けます。

行動確率
up0.25
right0.25
down0.25
left0.25
合計1.00

4 つの数を並べれば方策になりました それぞれが「その行動が選ばれる確率」で、足すと 1。 up が選ばれる確率は 0.25 と、はっきり言えます。

5-a で書いたこと

「マス目では行動が 4 択なので、確率を並べれば方策になりました。 トルクは連続値なので、並べられません。」

並べられないのは選択肢が無限にあるからです。 0.3 も 0.30001 も 0.300000001 も全部別の行動。 表に書き出すことができません。

02

連続にすると確率が消える

この節のねらい

「並べられない」だけでなく、確率そのものが 0 になってしまうことを数字で見ます。 ここが今回いちばん大事な節です。

方策が N(平均 0, 標準偏差 1) だとして、 トルクがちょうど 0.5 になる確率を考えます。

いきなり「ちょうど」は難しいので、幅のある範囲から始めて、だんだん狭めます。

範囲の幅範囲その範囲に入る確率
1.00.0 ∼ 1.00.3413447461
0.10.45 ∼ 0.550.0351955335
0.010.495 ∼ 0.5050.0035206423
0.0010.4995 ∼ 0.50050.0003520653
0.00010.49995 ∼ 0.500050.0000352065
0ちょうど 0.50

幅を 1/10 にすると、確率も 1/10 になります 0.0352 → 0.00352 → 0.000352。 幅を 0 にすれば、確率も 0です。

直感的にも納得できるはずです

「トルクがちょうど 0.5000000000... になる」というのは、 無限に続く桁が全部ぴったり一致するということです。 0.5000000001 ではダメ。そんなことは起こりません。

ダーツの的に投げて「座標がちょうど (0, 0) に当たる確率」と同じです。 的には当たりますが、数学的な 1 点に当たる確率は 0 です。

これでは方策が作れません どの行動も確率 0 なら、「この行動のほうが選ばれやすい」が言えません。 8-c で使う「更新前と後で確率がどう変わったか」も計算できない （0 ÷ 0 になってしまう）。

03

確率を幅で割る

この節のねらい

§02 の表をもう一度見ます。確率は 0 に消えていきますが、 消えない量が隠れています。

さっきの表に「確率 ÷ 幅」の列を足します。

幅確率確率 ÷ 幅
1.00.34134474610.341345
0.10.03519553350.351955
0.010.00352064230.352064
0.0010.00035206530.352065
0.00010.00003520650.352065

右の列が落ち着きます 確率は 0 へ消えていくのに、幅で割った値は 0.352065 に収束します。 これが確率密度です。

いちばん大事な語確率密度
何をするもの
「幅あたりの確率」。確率そのものではなく、確率の濃さ。 幅を掛けると確率に戻る。
なぜ必要か
連続値では1 点の確率が 0 になってしまうから。 幅で割ることで消えずに残る量を取り出している。
どこに効くか
log_prob はこれの対数。 8-c の PPO のクリップ目的関数が、 この量の比を使って更新の大きさを測る。

人口密度とまったく同じ関係です

人口確率
密度6,400 人/km²0.352065（幅あたり）
掛けるもの面積 [km²]幅
結果人数 [人]確率

「6,400 人/km²」は 6,400 人がいるという意味ではありません 同じように、「確率密度 0.352」は確率が 0.352 という意味ではありません。 どちらも掛け算しないと実際の量になりません。

人口 = 人口密度 × 面積
確率 = 確率密度 × 幅

検算してみます。

x = 0.5 での確率密度 = 0.352065

密度 × 幅 = 0.352065 × 0.01 = 0.00352065
正確な確率            = 0.00352064     # ほぼ一致

高さと面積を見比べる

この節のねらい

密度＝高さ、確率＝面積。この対応を目で確かめます。 幅を狭めると面積だけが消えて、高さは残るのを見てください。

teal の曲線が確率密度。塗った部分の面積が確率。 縦の線が中心での高さ＝密度。

触ってほしいところ ① 幅を 0 に近づける → 確率（面積）は 0 に消えるのに、密度（高さ）は変わりません。 これが §02〜§03 の話そのものです。 ② 「密度 x 幅」と「確率」を見比べる → 幅が狭いほど 2 つが一致します。 ③ std を 0.05 まで下げる → 密度が 8 を超えます。 確率は決して 1 を超えないのに、密度は超える——次の節で扱います。

05

密度が 1 を超える理由

この節のねらい

log_prob が正の値になることがあります。 「確率の対数なら負のはずでは？」という疑問に答えます。

std を変えて、中心の高さと全体の面積を並べます。

std中心の高さ（密度）全体の面積（確率）
2.00.19951.000000
1.00.39891.000000
0.50.79791.000000
0.13.98941.000000

高さは変わるのに、面積はいつも 1 です 山が細くなると高さが増え、幅が減るので、面積は保たれます。 確率の合計が 1 になるのは絶対のルールですが、 高さには上限がありません。

人口密度で言えば

人口 100 人の村を考えます。

面積人口密度人口
10 km²10 人/km²100 人
1 km²100 人/km²100 人
0.01 km²10,000 人/km²100 人

密度はいくらでも大きくなりますが、人数は 100 人のまま。 確率密度と確率の関係もこれと同じです。

だから log_prob は正になりうる

std=1.0   中心の密度=0.3989   log_prob = -0.919   # 1 未満なので log は負
std=0.5   中心の密度=0.7979   log_prob = -0.226
std=0.2   中心の密度=1.9947   log_prob = +0.691   # 1 を超えたので log が正
std=0.1   中心の密度=3.9894   log_prob = +1.384

異常ではありません logstd_explained.html で見たとおり、 log は「1 より大きいと正、1 より小さいと負」でした。 密度が 1 を超えれば、その対数は正になります。 log_prob が正だからといってバグではありません。

06

log_prob に戻る

この節のねらい

8-a のコードに戻って、いま何を計算していたのかを確認します。

dist = torch.distributions.Normal(mu, std)
action = dist.sample()                        # 分布から 1 つ引く
log_prob = dist.log_prob(action).sum(-1)      # その行動の「高さ」の対数

やっているのは高さを読むことです サンプリングした action の位置で、曲線の高さを読んで対数を取る。 実験室の縦線がその高さです。

なぜ高さで十分なのか

「確率が 0 なら比べられない」と §02 で書きました。 高さなら比べられます。

行動高さ（密度）解釈
0.00.3989いちばん出やすいあたり
1.00.2420その 6 割くらい
3.00.0044ほとんど出ない

「どちらが出やすいか」は高さで判断できます 確率はどちらも 0 ですが、高さには差があります。 比較に使うぶんには、高さで何も困りません。

8-c で使うのは「比」です

PPO は更新前と更新後で、その行動の出やすさがどれだけ変わったかを見ます。

比 = 新しい密度 / 古い密度 = exp(log_prob_new - log_prob_old)

比を取ると幅が打ち消し合います—— どちらも同じ幅を掛けるはずだったので、割り算で消えるのです。 だから密度のままで正しい比が出ます。

これが 7-b で読んだ approx_kl（更新の大きさ）の元になる量です。

07

まとめ

この教材のまとめ
  1. 離散（4 択）なら確率を並べれば方策になった。合計 1
  2. 連続値では「ちょうどこの値」の確率は厳密に 0。 幅を 1/10 にすると確率も 1/10 になるので、幅 0 なら 0
  3. 確率を幅で割ると消えずに残る。それが確率密度（0.352065 に収束した値）
  4. 人口密度と同じ関係。 確率 = 密度 × 幅／人口 = 人口密度 × 面積
  5. 密度＝高さ、確率＝面積。山が細くなると高さは 1 を超えるが、面積は必ず 1
  6. だから log_prob は正になることがある。バグではない
  7. 比較には高さで十分。比を取れば幅が打ち消し合うので 8-c でもこのまま使える
