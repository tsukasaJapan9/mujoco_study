Step 3 · 補助教材

timestep と積分器は、何をしているのか

<option timestep="0.002" integrator="Euler"/> の 2 つの値。 片方は「何秒ごとに計算するか」、もう片方は「その 1 回で次をどう見積もるか」。 この 2 つがどう噛み合って、なぜ硬い系だけが壊れるのかを最後まで追う。

この補助教材のねらい

Step 3 の §02 は「どの integrator を選ぶか」の結論と実測表を与えている。 だが結論だけでは、表に無い条件——自分が組んだロボットモデル——に出会ったとき何もできない。
ここで扱うのは機構のほう。1 ステップの更新式が実際にどう書かれていて、 誤差がどういう条件で増幅されるのか。到達点は 「この設定は壊れるか」を実行前に手で計算できるようになること。
Step 3 の課題 1 に取りかかる前か、課題 1 で発散を観察した直後に読むのがよい。

01

そもそも、なぜ「積分」なのか

物理エンジンが直接計算できるのは加速度だけ。 だが画面に描くために欲しいのは位置。この距離を埋める作業が積分。

ニュートンの運動方程式が与えてくれるのは、いまこの瞬間の加速度ひとつだけ。 振り子なら、いまの角度 θ といまの角速度 θ̇ を入れると角加速度 θ が出てくる。

M(θ) · θ = −m g lc sin θ − kp(θ − θ目標) − kv θ̇

ここから位置を得るには、加速度を 2 回積分しなければならない。 ところが加速度は θ と θ̇ に依存し、その θ と θ̇ は積分の結果として決まる。 ぐるぐる回っていて、手で解くことはできない（振り子は単振り子ですら解析解が楕円積分になる）。

そこで時間を細切れにして、加速度が一定だと思い込んで少しだけ進める。 進んだ先で加速度を計算し直して、また少し進める。これを延々繰り返す。 この「少し」の幅が timestep、「どう進めるか」の手続きが integrator。

2 つの値の役割

timestep（Δt） 1 回の計算で進める時間。0.002 なら 2 ミリ秒 = 1 秒間に 500 回計算する。
integrator その 1 回で、次の θ と θ̇ をどの式で見積もるか。 同じ Δt でも、式が違えば結果も安定性も変わる。

02

1 ステップの中身を、式で見る

4 つの integrator の違いは、たった数行の更新式の違いでしかない。 a(θ, θ̇) は運動方程式から出てくる角加速度とする。

陽的オイラー法 — 教科書の最初に出てくるが、MuJoCo は使わない

θ̇新 = θ̇ + Δt · a(θ, θ̇)
θ新  = θ + Δt · θ̇   ← 古い速度を使う

いまの加速度でまっすぐ進めるだけ。単純だが、振動する系ではエネルギーが必ず増え続け、 どんなに Δt を小さくしても最後には発散する。

Euler — MuJoCo の既定。semi-implicit（準陰的）

θ̇新 = θ̇ + Δt · a(θ, θ̇)
θ新  = θ + Δt · θ̇新   ← 更新した速度を使う

違いは 2 行目の 1 箇所だけ。更新したばかりの速度で位置を進める。 このわずかな差でエネルギーが暴走しなくなり、振動系に対して桁違いに強くなる。 MuJoCo が単に Euler と呼んでいるのはこちら。

RK4 — 1 ステップで加速度を 4 回評価する

ステップの始点・中点 2 回・終点で加速度を計算し、重み付き平均で進める。 誤差は Δt4 に比例するので精度は圧倒的。ただし計算コストは 4 倍。 そして後で見るとおり、精度が高いことと壊れにくいことは別物。

implicitfast — 速度依存の力だけを「次の時刻の速度」で評価する

θ̇新 = θ̇ + Δt · [ f位置(θ) − kv · θ̇新 ] / M   ← 未知数が両辺に出る
整理して   θ̇新 = ( θ̇ + Δt · f位置(θ)/M ) / ( 1 + Δt · kv/M )

減衰やアクチュエータの kv のような速度に比例する力を、 「進んだ後の速度」で評価する。未知数が両辺に現れるので連立方程式を解く必要があるが、 その代わり分母 (1 + Δt·kv/M) が必ず 1 より大きくなり、 Δt をどれだけ大きくしても速度が増幅されない。これが安定性の正体。

ここが分岐点

陽的な方法（Euler・RK4）は「いまの状態から未来を予測する」。 予測が外れると誤差が生まれ、その誤差が次のステップで増幅されると発散する。
陰的な方法（implicitfast・implicit）は「その式を満たす未来を逆算する」。 解くコストはかかるが、増幅が原理的に起きない。

03

なぜ壊れるのか — 増幅率がすべてを決める

発散するかどうかは、実は手計算で予測できる。 そして予測値は MuJoCo の実測と小数点以下まで一致する。

まず 1 ステップを手で追う — ブレーキが効きすぎて逆走する

いちばん単純な形で見る。ばね（kp）をいったん忘れて、 ダンパ（kv）だけの世界を考える。減衰の力は速度に比例するブレーキ。

θ̇新 = θ̇ + Δt · (−kv · θ̇) / M = θ̇ · ( 1 − kvΔt / M )

次の速度は、いまの速度に ( 1 − kvΔt/M ) を掛けただけ。 この掛け算の係数がすべてを決める。 stiff_pendulum.xml の値（M = 0.0567、kv = 40）で計算してみる。

ΔtkvΔt / M速度に掛かる係数1 ステップ後
1 ms0.705+0.29530% に縮む → 安定
2 ms1.410−0.410逆向きだが 41% に縮む → 安定
2.84 ms2.000−1.000ちょうど境界。減りも増えもしない
5 ms3.525−2.525逆向きに 2.5 倍 → 発散
10 ms7.049−6.049逆向きに 6 倍 → 即死
何が起きているのか

ブレーキの仕事は速度をゼロに近づけること。ところがシミュレータは 「ステップ開始時点のブレーキ力が Δt の間ずっと一定」だと思い込んで進める。
Δt が長すぎると、ゼロを通り過ぎて逆向きに走り出す。 通り過ぎる量が元の速度の 2 倍を超えると、 ブレーキをかけたのに元より速くなる。次のステップではもっと強いブレーキがかかり、 もっと大きく行き過ぎる。これが発散の正体。
境界は kvΔt/M = 2、つまり Δt = 2M/kv。

掛け算なので、超えた瞬間から指数関数的に膨らむ。実際に Δt = 5 ms で 初速 1.0 rad/s から始めると:

step 1 → −2.52   step 2 → +6.37   step 3 → −16.1   step 4 → +40.6
step 5 → −103    step 6 → +259    step 7 → −654    step 8 → +1651

符号が毎回ひっくり返りながら 2.5 倍ずつ増えていく。 3 秒 = 600 ステップ後には inf。ばねを一切使っていないのに壊れることに注目。 「硬さ」はばね定数だけの話ではない。

「硬さ × timestep」が一定を超えると壊れる

境界の式 Δt = 2M/kv を裏返すと kv · Δt = 2M。 つまり硬さと刻み幅の積に上限がある。 片方を 2 倍にしたら、もう片方を半分にしないと同じ場所に留まれない。

この表の読み方

1 行目と最終行を比べる。kp と kv を両方 2 倍（2000/40 → 4000/80）にしたら、 しきい値は 2.67 → 1.38 ms とちょうど半分になった。硬さ × Δt が保存量だという意味。
実測は常に 2M/kv より少し小さい。 ばねの分がわずかに上乗せされるから。だがどの行でも 2/ω より 2M/kv のほうが 小さく、実測はそちらに寄り添っている——効いている制約は一貫してダンパのほう。
kv を 40 → 10 に下げるだけで、しきい値は 2.67 → 6.81 ms に広がる。 発散したとき timestep を下げる前に、まず kv を見直すべき理由がこれ。

更新式はどれも「いまの状態 (θ, θ̇) に行列を掛けて次の状態を出す」形に書ける。 この行列の固有値の絶対値の最大 |g| が増幅率。

|g| < 1  →  誤差は毎ステップ縮む  →  安定
|g| > 1  →  誤差は毎ステップ膨らむ  →  発散

|g| がわずかに 1 を超えるだけで十分に致命的。1.01 でも 1500 ステップ（3 秒）後には 106 倍になる。これが「気づいたら NaN」の中身。

2 つの上限が同時にかかる

硬い position アクチュエータには kp（ばね）と kv（ダンパ）の 2 つがある。 陽的な方法では、それぞれが独立に Δt の上限を課す。

由来上限の式意味
ばね kpΔt < 2 / ω   (ω = √(kp/M)) 1 周期を最低 3 ステップ程度で刻めないと振動を追えない
ダンパ kvΔt < 2M / kv 減衰が強すぎると、1 ステップで行き過ぎて逆向きに大きくなる
意外な事実 — 効いているのは kp ではなく kv

models/stiff_pendulum.xml（M = 0.0567 kg·m²）に kp=2000 kv=40 を入れると：
ばね由来の上限 = 2/187.7 = 10.65 ms　／　ダンパ由来の上限 = 2×0.0567/40 = 2.84 ms
厳しいのはダンパのほう。MuJoCo の実測しきい値は 2.67 ms で、ダンパ側の予測とほぼ一致する。 「kp を上げたら壊れた」と思っていたものの正体は、多くの場合セットで上げた kv のほうだった。
そして implicitfast が陰的に扱うのは、まさにこの速度依存項＝kv。 効いている制約をピンポイントで外すから、あれほど劇的に効く。

自分で再現する

下のスクリプトで上の表を再現できる。d.warning を見るのがポイント。 MuJoCo は発散を検知すると警告を出して自動的に状態をリセットするので、 qpos が有限かどうかだけを見ていると発散を見逃す。

# 発散のしきい値を二分探索する
import numpy as np, mujoco

def diverges(dt, integ, kp, kv, T=3.0, q0=0.5):
    m = build(dt, integ, kp, kv)          # option/actuator を差し替えて MjModel を作る
    d = mujoco.MjData(m); d.qpos[0] = q0
    for _ in range(int(T / dt)):
        mujoco.mj_step(m, d)
        # MuJoCo は発散すると警告を立てて状態をリセットする。ここを見ないと見逃す
        if d.warning[mujoco.mjtWarning.mjWARN_BADQACC].number > 0:
            return True
        if not np.isfinite(d.qpos).all() or abs(d.qpos[0]) > 1e3:
            return True
    return False

lo, hi = 1e-4, 0.05
for _ in range(40):                        # 40 回で十分な精度が出る
    mid = (lo + hi) / 2
    if diverges(mid, "Euler", 2000, 40): hi = mid
    else:                                 lo = mid
print(f"しきい値 = {lo*1000:.2f} ms")
06

XML のどこに書くか

<option> は <mujoco> の直下。 body ごとに書き分けるものではなく、シーン全体で 1 つだけの設定。

<mujoco>
  <statistic extent="1.5" center="0 0 0.5"/>
  <compiler angle="radian"/>

  <!-- ここ。物理エンジン全体の設定 -->
  <option timestep="0.002" integrator="Euler"/>

  <visual> ... </visual>
  <asset> ... </asset>
  <worldbody> ... </worldbody>
  <actuator> ... </actuator>
</mujoco>

トップレベル要素の順序は MJCF の仕様上は自由だが、慣例は compiler → option → visual → asset → worldbody → actuator → sensor。 読む人（半年後の自分を含む）のために揃えておく。

ここに書いた値は Python から model.opt.timestep / model.opt.integrator として読み書きできる。 課題 1-2 で実行時に書き換えているのは、まさにこの <option> の中身。

実務上の指針

迷ったら integrator="implicitfast"、timestep="0.002" から始める。 これがロボット RL の実質的な標準。
発散したら、まずゲイン（特に kv）を下げられないかを疑う。 timestep を下げるのは最後の手段——Step 10 で数千環境を並列に回すとき、 timestep はそのまま学習時間に跳ね返るから。
