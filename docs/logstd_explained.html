00

この教材について

この教材のねらい

8-a で log_std というパラメータが出てきました。 「標準偏差を対数で持つ」と書きましたが、そもそも対数とは何なのかを 説明していませんでした。

高校数学を思い出す必要はありません。 exp と log を2 つの変換器として捉えるところから始めます。

ゴール

この 1 行が「なるほど」と読めるようになることです。

std = log_std.exp()

そして 7-b で見た std = 0.602 という数字の意味も、 「行動の 1 割がはみ出して切られている状態」として読めるようになります。

01

exp — 「かけ算を繰り返す」変換器

この節のねらい

exp を1 つの変換器として見ます。 入れた数だけ、ある数をかけ算する——それだけの機械です。

まず e という数

e = 2.71828... という定数があります。 円周率 π と同じで、割り切れない特別な数です。

なぜ 2 でも 10 でもなく 2.718 なのか いまは気にしなくて構いません。 微分すると自分自身になるという便利な性質があり、数学の都合で選ばれています。 「そういう定数がある」で先に進めます。

exp は「e を何回かける？」という質問への答え

exp(0) = 1                    # 0 回かける = 1（何もかけない）
exp(1) = e         = 2.71828  # 1 回
exp(2) = e x e     = 7.38906  # 2 回
exp(3) = e x e x e = 20.08554 # 3 回

では exp(-1) は？ 「−1 回かける」＝1 回わると考えます。

exp(-1) = 1 / e         = 0.36788
exp(-2) = 1 / (e x e)   = 0.13534
exp(-3) = 1 / (e x e x e) = 0.04979
入力出力読み方
−30.049793 回わった
−10.367881 回わった
01.00000何もしない
12.718281 回かけた
320.085543 回かけた
いちばん大事な性質

出力は絶対に負になりません。 正の数を何回かけても、何回わっても、正のままだからです。

exp(-100)  = 0.0000...（0 に極めて近い正の数）
exp(-1000) = 0.0（計算機では 0 になるが、数学的には正）

0 に限りなく近づきますが、0 にも負にもなりません。 §04 で、この性質だけが理由になります。

入力が 1 増えると、出力は 2.718 倍

exp(1)=2.718、exp(2)=7.389、exp(3)=20.086。 足し算の入力が、かけ算の出力になっています （7.389 ÷ 2.718 = 2.718、20.086 ÷ 7.389 = 2.718）。

これが exp の本質で、「一定の割合で増える／減る」を表すのに使われます。

02

log — exp の逆向きの変換器

この節のねらい

log は exp の逆をたどる機械です。 新しい概念ではなく、同じ関係を逆から見ているだけだと確認します。

exp が「e を何回かけるか → 結果」だったのに対し、 log は「結果 → e を何回かけたのか」を返します。

exp(2)     = 7.38906        # 2 を入れたら 7.389 が出た
log(7.389) = 2              # 7.389 を入れたら 2 が返る
stdlog(std)exp() で戻す
0.1−2.302590.10000
0.5−0.693150.50000
1.00.000001.00000
2.0+0.693152.00000

行って帰ってくると元に戻ります exp(log(x)) = x。これが「逆の操作」という意味です。 足し算と引き算、かけ算とわり算と同じ関係です。

log の入力は正の数だけ

exp の出力が必ず正だったので、その逆である log は 正の数しか受け取れません。log(-1) や log(0) は定義されません。

この非対称性が §04 の鍵になります。

3 つの目印を覚えれば十分です

log の値元の数覚え方
負1 より小さいわり算した
0ちょうど 1何もしていない
正1 より大きいかけ算した

この 3 つだけで log_std は読めます log_std が負なら std は 1 より小さい、 0 なら std はちょうど 1。 8-a の初期値が torch.zeros() だったので、std は 1.0 から始まります。

03

なぜ対数が便利なのか

この節のねらい

log_std の話に入る前に、対数という道具の使いどころを掴みます。 あなたはもう使ったことがあります。

掛け算の世界を、足し算の世界に移す

「2 倍」「4 倍」「8 倍」は、かけ算では飛び飛びですが、 対数を取ると等間隔になります。

stdlog(std)間隔
0.25−1.386——
0.5−0.693+0.693
1.00.000+0.693
2.0+0.693+0.693

2 倍するたびに、対数は同じ幅だけ増えます これが「倍率で考えるべき量を扱うときに対数が便利」な理由です。

あなたはすでに使っています

7-c の「2〜3 倍単位で動かす」

ハイパーパラメータの作法として 「learning_rate は 2〜3 倍単位で動かす。10% の調整に意味はない」 と書きました。

3e-4 → 1e-3 は約 3.3 倍。これは対数スケールで動かしているということです。 3e-4 → 3.3e-4（10% 増）に意味がないのは、 対数で見るとほとんど動いていないからです。

5-b の割引率 γ

γ = 0.9 / 0.99 / 0.999 と刻みましたが、 0.9 と 0.91 は近く、0.99 と 0.999 は遠い—— 実効地平が 10 歩 / 100 歩 / 1000 歩 と 10 倍ずつ変わったとおりです。

これも対数的な感覚です。γ は「1 から引いた残り」で見るべき量でした。

04

なぜ std を対数で持つのか

この節のねらい

ここが本題です。理由はたった 1 つ—— §01 で見た「exp の出力は絶対に負にならない」という性質だけです。

標準偏差は負になってはいけません

std は「散らばりの大きさ」です。 大きさに負はありません。身長が −170cm の人がいないのと同じです。

PyTorch も拒否します。

Normal(平均=0, 標準偏差=-0.3)

ValueError: Expected parameter scale ... to satisfy the constraint GreaterThan(0)

ところが、学習は値を自由に動かします

ニューラルネットの学習は「いまの値を少し動かす」の繰り返しです。 どちらへどれだけ動くかは、勾配が決めます。

もし std を直接学習したら
std = 0.10 から始める
「もっと小さくすべき」という勾配が来る → std = 0.05
また来る → std = 0.01
また来る → std = -0.04 ← ここで壊れる

止める方法がありません 「0 より下に行くな」という制約を勾配に伝える仕組みが、標準的な学習にはありません。 値を直接クリップする方法もありますが、そこで勾配が消えて学習が止まります。

対数で持つと、この問題が消えます

log_std = -50   ->  std = 1.93e-22   # 極小だが正
log_std =   0   ->  std = 1.00       # ちょうど 1
log_std = +50   ->  std = 5.19e+21   # 極大

学習が log_std をどこへ動かしても安全です -1000 になっても +1000 になっても、 exp() を通せば必ず正の std が出てきます。 制約を「式の形」で満たしているわけです。

ここが発想の転換です

「負になってはいけない」という制約を、学習に守らせようとしない。 代わりに何を入れても大丈夫な形に変換してから渡す。

学習が扱うのは log_std（何でもあり）、 分布が受け取るのは std = exp(log_std)（必ず正）。 境界で変換を挟むだけで、制約が自動的に満たされます。

この手口は機械学習のあちこちで出てきます。 「0〜1 に収めたい」なら sigmoid、 「合計 1 の確率にしたい」なら softmax——全部同じ発想です。

もうひとつの利点：動きやすさが揃う

§03 で見たとおり、対数で持つと「倍率」が「足し算」になります。

動かす量std を直接log_std 経由
1.0 から −0.11.0 → 0.9（10% 減）1.0 → 0.905（9.5% 減）
0.1 から −0.10.1 → 0.0（100% 減）0.1 → 0.0905（9.5% 減）

同じ「−0.1」の効き方がまるで違います std を直接動かすと、小さい値のときだけ致命的になります。 log_std ならどこにいても同じ割合で動くので、 学習率を 1 つ決めれば全域でうまくいきます。

06

学習中に何が起きていたか

この節のねらい

7-b で読んだ std の推移を、いまの理解で読み直します。 あの数字が何を意味していたかが分かります。

stepstd（7-b の実測）log_std（逆算）はみ出す割合
01.0000.00031.7%
16k0.966−0.03530.1%
115k0.762−0.27218.9%
303k0.602−0.5089.7%

学習されていたのは真ん中の列です log_std が 0.000 → −0.508 と動いた結果、 std が 1.000 → 0.602 になりました。 ネットは std を直接触っていません。

右端の列が実用的な意味です 最初は3 回に 1 回が範囲外で切られていました。 30 万ステップ後には10 回に 1 回まで減っています。 「無駄撃ちが減った」と読めます。

はみ出しは無駄なのか

切られた行動は ±1 ちょうどになるので、完全な無駄ではありません—— 「全力で押す」という行動として実行されます。

ただし +1.5 と +3.0 が同じ結果になるので、 その差を学ぶことができません。学習の解像度が落ちるという意味では損です。

7-c で ent_coef が効かなかった理由

7-c で ent_coef=0.01 を試して効きませんでした（−250 対 −254）。

ent_coef は「std を下がりにくくする」パラメータです。 しかし 30 万ステップ時点で std = 0.602、まだ1 割がはみ出すほど広い。 探索が足りないという症状が出ていないのに、探索の薬を出しても効きません。

この教材を読んだいまなら、7-c の結果は試す前に予測できたはずです。

07

まとめ

この教材のまとめ
  1. exp は「e を何回かけるか」。入力 1 増えるごとに出力 2.718 倍。 出力は絶対に負にならない
  2. log は exp の逆。負なら 1 より小さい、0 ならちょうど 1、正なら 1 より大きい
  3. 対数は倍率を足し算に変える。7-c の「2〜3 倍単位で動かす」も 5-b の γ の刻み方も、この感覚
  4. log_std を使う理由はただ 1 つ—— 学習がどこへ動かしても std が正になるから
  5. おまけの利点: どの大きさでも同じ割合で動くので学習率を 1 つ決めれば済む
  6. 7-b の std = 0.602 は「行動の 1 割がはみ出して切られている状態」
8-a に戻るときに

この 1 行が読めるようになっているはずです。

std = log_std.exp()

「学習が自由に動かしている log_std を、 必ず正になる形に変換して分布に渡す」——それだけの行です。
