Curriculum · 2026-08-31

振り子ひとつを、実機まで育てる

MuJoCo・強化学習・Sim2Real を、題材を分散させずに学ぶ 12 ステップ。 1 自由度の振り子から始め、同じ題材に物理モデリング・古典制御・PPO・ドメインランダマイゼーションを 順に積み上げて、最後に自作ハードウェアへ載せる。

週 10h × 約 3.5〜4 ヶ月 前提: Python / NumPy MuJoCo 3.x + Gymnasium + SB3 Ubuntu 22.04 / RTX 4050 6GB
設計方針

なぜこの順番なのか

題材は 1 つだけ

教材を渡り歩くと「動かしたことはあるが分かっていない」状態になる。振り子を 12 ステップ通して育てることで、 各技術が何を解決したのかが差分として見える。

RL の前に古典制御

PD 制御で先に立たせておく。これが RL の性能ベースラインになり、さらに実機で 「方策だけが壊れたのか、ハードが悪いのか」を切り分ける物差しになる。

失敗を意図的に起こす

発散させる。報酬をハックさせる。ドメインランダマイゼーション無しで壊す。 各ステップに「壊す課題」を置き、成功例だけを見て終わらせない。

ステップ詳細

各ステップの中身

各ステップには完了条件チェックリストがある。埋まるまで次に進まないことが、 この講座の唯一の必須ルール。

Phase A

MuJoCo を手足にする

30h / 約 3 週間
01

環境構築と最初のシミュレーション

4h

物理エンジンが「何を定数として持ち、何を状態として更新しているか」を掴む。

学ぶこと
  • MjModel（設計図・不変）と MjData（状態・毎ステップ更新）の分離
  • mj_step() が 1 回で行う 6 つの計算
  • nq と nv が一致しない場合（free joint）
  • viewer の launch_passive と実時間同期
→ sim/hello_mujoco.py, sim/view_pendulum.py
02

MJCF モデリング入門

8h

シミュレータに与えるモデルを自分の手で書く。Sim2Real で最初に効くのはここ。

学ぶこと
  • body ツリーと親相対座標、pos / quat
  • joint の種類: hinge / slide / ball / free
  • 慣性の自動計算と <inertial> による明示指定
  • SI 単位系（m, kg, s, N·m）の徹底
→ models/pendulum.xml, models/cartpole.xml
03

物理の中身とアクチュエータ

10h

シミュレーションが壊れる原因・実機と合わない原因を、エンジン側から理解する。

学ぶこと
  • timestep と積分器（Euler / implicitfast / RK4）、発散の境界
  • 接触モデル solref / solimp / 摩擦
  • アクチュエータ motor / position / velocity と実機モータ制御方式の対応
  • gear, ctrlrange, forcerange、センサ定義
→ sim/step_experiments.py
04

古典制御でウォームアップ

8h

RL 抜きで振り子を立たせ、後の比較基準と Sim2Real の物差しを作る。

学ぶこと
  • PD 制御とゲイン調整の感覚、トルク飽和の影響
  • 制御周期と物理周期の分離（実機は制御 50–500Hz / 物理 500–2000Hz）
  • エネルギー整形によるスイングアップ → 上端で PD にスイッチ
→ control/pd_balance.py, control/swingup.py
Phase B

強化学習の基礎

40h / 約 4 週間
05

MDP と強化学習の言葉

8h

論文と実装を読むための語彙を揃える。ニューラルネット無しで RL の心臓部に触れる。

学ぶこと
  • MDP、収益、割引率 γ、V / Q / アドバンテージ A の関係
  • ベルマン方程式が「何を言っているだけ」なのか
  • 探索と活用、on-policy と off-policy（データの使い回しの差）
  • 方策勾配定理の直感
→ toy/gridworld_q.py（表形式 Q 学習）
06

自作環境の Gymnasium 化

10h

自分の MuJoCo モデルを RL ライブラリに繋ぐ。自作ロボット RL の分岐点。

学ぶこと
  • reset / step / observation_space / action_space
  • terminated と truncated の違い（混同すると学習が静かに壊れる）
  • 角度の周期性と sin/cos 表現、行動スケーリング、frame skip
  • check_env による自己診断
→ envs/pendulum_env.py
07

SB3 で学習を回す・実験管理

10h

「学習が回る」を再現可能にする。ログを読む癖をここでつける。

学ぶこと
  • PPO と SAC の使い分け、主要ハイパーパラメータの意味
  • VecNormalize による観測・報酬の正規化（効果が大きい）
  • TensorBoard: ep_rew_mean / explained_variance / entropy / approx_kl
  • 1 シードの結果を信じない評価プロトコル
→ train/train_ppo.py, train/eval.py
08

PPO を自分で実装する

12h

ブラックボックスを消す。Sim2Real でのカスタマイズにはここの理解が必須。

学ぶこと
  • Actor-Critic、対角ガウス方策と log_std
  • GAE と λ、クリップ目的関数がなぜ必要か
  • 論文に書かれない実装詳細（アドバンテージ正規化・直交初期化・勾配クリップ・LR アニーリング）
→ algos/ppo_min.py（単一ファイル 300 行）
Phase C

実践的な RL エンジニアリング

24h / 約 3 週間
09

報酬・観測・行動空間の設計

12h

学習失敗の 8 割は設計ミス。原因を切り分ける力をつける。

学ぶこと
  • sparse / dense、シェーピング、指数型報酬 exp(-k·e²) が扱いやすい理由
  • 報酬ハッキングを意図的に発生させて観察する
  • トルク直接指令 vs 目標位置＋PD（実機では後者が圧倒的に安定）
  • action rate ペナルティ（実機のガタつきと発熱を抑える）
→ 報酬項の ablation 実験と比較レポート
10

高速化と大規模化

12h

歩行など重い課題に手が届く状態にする。GPU が初めて効いてくる。

学ぶこと
  • CPU 並列（SubprocVecEnv）の限界
  • MuJoCo MJX: JAX 実装で GPU 上に数千環境を並列展開
  • MuJoCo Playground の既製ロボット環境（四足・アーム・二足）
  • JAX の jit / vmap / 関数純粋性を最小限
→ MJX 版環境と学習スクリプト
Phase D

Sim2Real

42h+ / 約 4 週間〜
11

ギャップの理論と対策

12h

「シミュでは完璧、実機で転ぶ」の原因を分類し、対策を打てるようにする。

学ぶこと
  • ドメインランダマイゼーション: 何を、どの範囲で振るか（振りすぎると保守的すぎる方策になる）
  • システム同定: 実機ログからシミュのパラメータを最適化
  • アクチュエータネット（ANYmal の手法）
  • 非対称 Actor-Critic、観測履歴 / Teacher-Student 蒸留
→ DR 付き環境・遅延モデル・同定スクリプト
12

実機を作って載せる

30h+

自作ハードで RL 方策を動かす。ここまでの全部を使う。

学ぶこと
  • CAD → MJCF 化（質量・慣性を実測と CAD から取る）
  • マイコンとの通信、制御ループの実時間性
  • 方策のデプロイ（TorchScript / ONNX / C への埋め込み）
  • 安全機構: トルクリミット・角度リミット・非常停止・ウォッチドッグ
→ 実機 + デプロイ済み方策 + 同定ループ
Phase D の背骨

Sim2Real は片道ではなく閉ループ

「シミュで学習して実機に載せる」は 1 回では成功しない。実機ログでシミュを直し、 直したシミュで学習し直す。この反復が Sim2Real の実体であり、Step 12 で回す輪。

分類具体例主な対策
アクチュエータサーボの応答遅れ、トルク上限、バックラッシュ、減速比の損失実測による同定、アクチュエータネット、トルクリミットの再現

Step 12 の選択肢

最初の自作ハードウェア候補

選定基準は「安い・壊れない・ギャップの原因が特定できる」。1 → 2 の順を推奨。 四足やアームは、この 2 つを通した後で十分に間に合う。

候補構成部品費この題材で学べること
1. 回転型倒立振子
Furuta pendulum		 モータ 1 + エンコーダ 2 + マイコン1〜2 万円 最小構成。ギャップが摩擦とバックラッシュに集約され、原因分析が容易
2. 2 輪バランスロボット モータ 2 + IMU + マイコン1〜2 万円 IMU ノイズ・姿勢推定・制御遅延。転んでも安全
3. リアクションホイール振子 BLDC + FOC ドライバ + IMU2〜3 万円 トルク制御が素直。アクチュエータモデル学習に最適
4. 小型ロボットアーム
3〜5 自由度		 シリアルバスサーボ 5 + 3D プリント部材3〜5 万円 接触・把持・多自由度の協調。次の段階
Step 12 に入る前の絶対条件

実機で最初に走らせるのは RL 方策ではなく PD 制御。配線・通信・制御周期・安全機構が 正しいことを、方策の良し悪しと切り離して確認しておく。ここを飛ばすと、実機で失敗したときに 原因がハードなのか方策なのか永久に分からなくなる。

技術スタック

使うもの、あえて使わないもの

役割採用理由
物理シミュレータMuJoCo 3.x接触・関節の数値安定性が高く、ロボット RL の事実上の標準
モデル記述MJCF (XML)MuJoCo ネイティブ。URDF より表現力が高い
環境 APIGymnasiumRL ライブラリが前提とする共通規格
RL アルゴリズムStable-Baselines3信頼できる実装を基準として持つため。中身は Step 8 で自作する
学習フレームワークPyTorchSB3 の中身であり、自作 PPO でも使う
実験管理TensorBoardRL はログが読めないとデバッグ不能
高速化（後半）MuJoCo MJX / PlaygroundGPU 上で数千環境を並列実行
先に知っておくべき事実

SB3 + MuJoCo の標準的な学習（小さな MLP 方策）では GPU はほとんど効かない。 ボトルネックは物理シミュレーションであり CPU 側にある。GPU が本当に効くのは Step 10 の MJX 以降。 「GPU があるのに速くならない」で悩む必要はない。それが正常。

共通ルール

全ステップに適用する 5 つの約束

  1. 完了条件が埋まるまで次に進まない。飛ばした穴は Phase D で必ず塞がれる。
  2. 数値は必ず理論値・実測値と比較する。「動いた気がする」を潰す。
  3. 失敗を 1 回は意図的に起こす。発散させ、報酬をハックさせ、DR 無しで壊す。
  4. コードは自分で書く。提示されるのは骨格だけ。写経ではなく、埋めながら理解する。
  5. 分からない用語はその場で聞く。用語の霧を残すと Sim2Real で確実に詰まる。
