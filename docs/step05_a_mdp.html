強化学習は何を解く問題か

強化学習の教科書に必ず出てくる「MDP」という枠組みを、 4×4 のマス目を歩くだけの例で理解する。数式は最後に 1 つだけ出てくる。

前回までと、今回の問い

前回までで分かっていること
  1. MuJoCo で振り子を作り、data.ctrl にトルクを書けば動かせる
  2. PD 制御を自分で書けば上端で立たせられる。ただしトルクが足りないと引き込み領域の外からは戻せない
  3. 真下から立てるにはエネルギー整形が要る。どちらの制御則も、人間が式を考えて書いた
この教材が答える問い

1. 制御則を人が書かないとしたら、代わりに何を用意すればいいのか？

2. 強化学習の論文に必ず出てくる MDP とは、結局のところ何を並べたものなのか？

今回の進め方。 先に 4×4 のマス目を歩くプログラムを動かして、目で見てから言葉を導入します。 用語は出てくるたびにその場で説明します。 MuJoCo も振り子も出てきません。振り子に戻るのは Step 6 からで、 それまでは「小さくて全部が見える例」で言葉を揃えます。

なぜ振り子を離れるのか

振り子は状態が連続値（角度も角速度も小数）なので、 中で何が起きているかを表にして眺めることができません。 マス目なら状態が 14 個しかないので、全部を 1 枚の表に書けます。 言葉を覚える段階では、全部見えるほうが速い。

02

いま起きたことに名前をつける

この節のねらい

§01 で見たログの各部分に、強化学習の用語を割り当てます。 新しいことは何も起きません。もう見たものに名前がつくだけです。

さっきのログの 1 行を取り出します。

t=6   a=up   s=(2, 1)   r=0.0

ここに 4 つの言葉が全部入っています。

用語ログのどこマス目での意味
状態（state）s=(2, 1)いまどのマスにいるか。全部で 14 通り
行動（action）a=upそこで選んだ動き。上・右・下・左の 4 通り
報酬（reward）r=0.0その 1 手でもらえた点数。ゴールのときだけ 1.0
ステップ（step）t=6何手目か

そして、ログには直接現れないけれど決まっているものが 2 つあります。

用語マス目での意味
遷移（transition） 「この状態でこの行動を取ると、次はどの状態になるか」の決まり。 今回は (3,0) で up なら必ず (2,0)。 壁に向かえばその場に留まるのも遷移の一部
方策（policy） 「この状態ならこの行動を選ぶ」という選び方そのもの。 今回は「4 つから等確率でランダム」という方策を使った。 強化学習が探しているのは、この方策
いちばん大事な語方策（policy）
何をするもの
状態を受け取って行動を返す関数。それだけ。 行動 = 方策(状態) と書けるものは全部が方策で、 Step 4 で書いた PD 制御も方策の一種（角度と角速度を受け取ってトルクを返した）。
なぜ今出るか
強化学習で「学習する」と言ったとき、学習されるものがこれだから。 報酬でも状態でもなく、方策が改善されていく。 この一語がぶれると、以降の話が全部ぼやける。
どこに効くか
Step 7 で SB3 を使うと、保存されるファイルの中身はまさに方策。 Step 12 で実機に載せるのも方策。最終成果物の名前だと思ってよい。

方策には 2 種類ある 決定的（deterministic）な方策は、同じ状態なら必ず同じ行動を返します（PD 制御がこれ）。 確率的（stochastic）な方策は、「上 70%、右 30%」のように確率で返します。 今回のランダム方策は「4 方向を 25% ずつ」という確率的方策です。 学習中は確率的であることが重要で、その理由は Step 5-f で扱います。

03

まとめて MDP と呼ぶ

この節のねらい

§02 で出した言葉を並べるだけです。 MDP という新しい概念があるのではなく、もう見たものの呼び名だと確認します。

MDP（Markov Decision Process / マルコフ決定過程）とは、 次の 5 つを並べたもののことです。これだけです。

記号読み方マス目では振り子では（Step 6 で使う）
S状態の集合14 個のマス角度と角速度の組
A行動の集合上・右・下・左の 4 つトルクの値
P遷移「上に行けば 1 つ上のマス」mj_step() そのもの
r報酬ゴールで 1.0、他は 0.0自分で決める（Step 9 の主題）
γ割引率まだ出てきていない同左

γ だけ後回しにします 5 つ目の γ（ガンマ）は「未来の報酬をどれだけ重視するか」を決める数で、 次の教材（5-b）の主役です。ここでは「5 つ目があるらしい」とだけ覚えてください。

「マルコフ」とは何か

名前の真ん中にある マルコフ性 とは、 「次に何が起きるかは、今の状態だけで決まる」という性質のことです。 どういう経路でそのマスに来たかは関係ない、という意味。

なぜわざわざ言うのか マス目では当たり前に見えますが、成り立たない状況を作るのは簡単です。 たとえば状態を「今いるマス」ではなく「今いるマスの色」にすると、 同じ色のマスが複数あるせいで次にどこへ行くか決まらなくなります。 状態に何を入れるかを間違えるとマルコフ性が壊れる—— これは Step 6 で観測を設計するときに実際に起きる失敗です。

振り子での実例（Step 6 の伏線）

振り子の状態を「角度だけ」にすると、マルコフ性が壊れます。 同じ角度 0.5 rad でも、右に回っている途中か左に回っている途中かで次の瞬間が違うから。 角速度を足して初めて「今の状態だけで次が決まる」ようになります。 状態に角度と角速度の両方を入れる理由がこれです。

04

振り子を MDP で書くと

この節のねらい

マス目で覚えた枠組みを、すでに知っている振り子に当てはめてみます。 Step 4 で書いたコードが、実は MDP の部品でできていたと分かれば、この節の目的は達成です。

Step 4 の pd_balance.py のループを、MDP の言葉で読み直します。

for i in range(6000):
    if i % decimation == 0:
        phi = wrap(data.qpos[0] - np.pi)              # 状態 s を読む
        u = np.clip(-kp * phi - kd * data.qvel[0], ...)  # 方策 pi(s) が行動 a を決める
    data.ctrl[0] = u                                   # 行動 a を環境に渡す
    mujoco.mj_step(model, data)                        # 遷移 P が次の状態を作る
MDP の部品Step 4 のコードStep 7 以降どうなるか
状態 sdata.qpos, data.qvelそのまま（観測の設計は Step 9）
行動 adata.ctrl[0] に書くトルクそのまま
遷移 Pmj_step()そのまま。MuJoCo が P の役
方策 π-kp * phi - kd * omegaここがニューラルネットに置き換わる
報酬 r存在しない自分で書き足す必要がある

足りないのは 1 つだけ あなたはすでに MDP の 5 つのうち 3 つ（S・A・P）を Step 4 で扱っています。 方策は PD 制御という形で持っていて、本当に無いのは報酬だけ。 「強化学習を始める」というのは、 PD の式を消して、代わりに報酬の式を書くという作業だと思ってください。

段階 1

マス目を定義する

この段階ですること ファイルを作って、マス目の形を書くだけ。まだ動きません。

toy/gridworld.py を新規作成します（toy/ フォルダも作ってください）。

import numpy as np

GRID = [
    "...G",
    ".#..",
    "....",
    "S.#.",
]
ACTIONS = ["up", "right", "down", "left"]
DELTA = [(-1, 0), (0, 1), (1, 0), (0, -1)]   # 行,列 の増分。上は行が減る

N_ROW, N_COL = len(GRID), len(GRID[0])


def find(ch):
    for r, row in enumerate(GRID):
        for c, x in enumerate(row):
            if x == ch:
                return (r, c)


START, GOAL = find("S"), find("G")
print("START =", START, " GOAL =", GOAL)

確認方法 実行して START = (3, 0) GOAL = (0, 3) と出れば OK。

なぜ状態を (行, 列) のタプルにするのか あとで「この状態の価値はいくつか」を辞書で引くことになるので、 ハッシュできる型にしておく必要があります。 リストだと辞書のキーにできません。

段階 2

遷移 P を書く

この段階ですること 「状態と行動を渡すと次の状態が返る」関数を 1 つ書きます。 これが MDP の P にあたります。

def step(state, action):
    dr, dc = DELTA[action]
    r, c = state[0] + dr, state[1] + dc

    if ???:                       # ← ここだけ考える
        r, c = state              # 動かずにその場に留まる

    nxt = (r, c)
    reward = 1.0 if nxt == GOAL else 0.0
    done = nxt == GOAL
    return nxt, reward, done

穴埋めはここ 1 箇所だけです。 「その場に留まる」のは 2 つの場合です。ひとつはマス目の外に出ようとしたとき、 もうひとつは壁（#）に入ろうとしたとき。 この 2 つを or で繋いだ条件を書いてください。

答えと解説を見る
    if not (0 <= r < N_ROW and 0 <= c < N_COL) or GRID[r][c] == "#":
        r, c = state

順番が大事です 範囲チェックを先に書いてください。逆にすると、 GRID[r][c] で範囲外を読もうとして IndexError になります。 Python の or は左が真なら右を評価しないので、この順番なら安全です。

なぜ 0 ≤ c は要るのか GRID[3][-1] は Python ではエラーにならず、行の末尾を返します。 左端から左に出たつもりが右端に瞬間移動する、というバグになります。

確認方法 次を実行して (2, 0) と (3, 0) が出れば正しく書けています。

print(step((3, 0), 0))   # 上に動ける   -> ((2, 0), 0.0, False)
print(step((3, 0), 3))   # 左は外なので留まる -> ((3, 0), 0.0, False)
段階 3

ランダム方策で 1 エピソード歩かせる

この段階ですること §01 のログを再現します。 エピソード（episode）とはスタートから終わりまでの 1 回の試行のこと。 この語は以降ずっと使います。

rng = np.random.default_rng(0)
state, total = START, 0.0

for t in range(1, 31):
    action = rng.integers(4)              # これが「方策」。4 つから等確率
    state, reward, done = step(state, action)
    total += reward
    print(f"t={t:<3} a={ACTIONS[action]:<6} s={state}  r={reward}")
    if done:
        print(f"ゴール到達  合計報酬={total}  ステップ数={t}")
        break
else:
    print(f"30 ステップで届かず  合計報酬={total}")

確認方法 rng のシードを 0 にしてあるので、 §01 のログと完全に同じ出力になるはずです。 最後が 30 ステップで届かず 合計報酬=0.0 なら一致しています。

環境と方策の境目を見てください step() が環境（＝世界のルール。こちらは変えられない）、 rng.integers(4) が方策（＝行動の選び方。こちらを改善していく）。 強化学習で書き換わるのは後者だけです。 この 2 行が分かれていることを確認したら、この課題の目的は半分達成です。

段階 4

2 万回まわして平均を出す

この段階ですること 1 回では運の要素が大きすぎるので、 たくさん試して平均を取ります。強化学習では常にこの見方をします—— 1 エピソードの結果ではなく、平均で良し悪しを判断する。

rng = np.random.default_rng(1)
steps = []

for ep in range(20000):
    state = START
    for t in range(1, 501):               # 上限 500 歩
        state, reward, done = step(state, rng.integers(4))
        if done:
            steps.append(t)
            break

print(f"成功率 = {100 * len(steps) / 20000:.1f} %")
print(f"平均ステップ数 = {np.mean(steps):.1f}")

確認方法 成功率 = 100.0 %、平均ステップ数 = 64.6 前後になります。

この 64.6 という数字を覚えておいてください 最短は 6 歩なので、10 倍以上の遠回りをしています。 5-e で Q 学習を実装すると、この数字が 6 に近づくのを自分の目で見ることになります。 今日の 64.6 が、これから改善していく出発点です。

まとめ

今回で分かったこと
  1. MDP は新しい概念ではなく、状態・行動・遷移・報酬・割引率の 5 つを並べた呼び名
  2. 強化学習が探しているのは 方策（状態を受け取って行動を返す関数）ひとつだけ
  3. Step 4 の PD 制御も方策の一種。振り子の MDP で足りないのは報酬だけ
  4. マルコフ性＝次は今の状態だけで決まる。状態に何を入れるかを間違えると壊れる
次回（5-b）でやること

今回は「ゴールで 1 点」というルールを与えただけで、 それがどう「良い方策」に繋がるのかは一切説明していません。 ここが次回の主題です。収益と割引率 γ という 2 つの言葉で、 「遠回りは損だ」ということをプログラムに伝わる形にします。
