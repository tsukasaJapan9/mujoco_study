02

それが価値関数 V

この節のねらい

§01 の表に名前をつけます。新しい計算は出ません。

価値関数（value function）とは、 「この状態から始めたら、収益はいくらになりそうか」を状態ごとに持った表のことです。 V(s) と書きます。

V(s) = その状態 s から始めたときの、収益 G の平均
いちばん大事な語価値関数 V(s)
何をするもの
状態を受け取って「その先の見込み」を返す関数。 報酬が「今もらった点」、収益が「最後までの合計」なのに対し、 価値は「これからもらえそうな合計の予想」。
なぜ今出るか
収益 G は最後まで歩かないと分からないから。 64 歩あるいて数字が 1 つでは学習が進まない。 1 歩ごとに判断できる材料が要る。それが価値。
どこに効くか
Step 8 の PPO では、この V をニューラルネットで近似します （Critic と呼ばれる部分がそれ）。 マス目なら 14 個の表で済むものが、振り子では表にできないのでネットにする—— 違いはそれだけ。

「平均」が入っていることに注意 5-b と同じ理由です。方策が確率的なら収益は毎回変わるので、 価値はその平均として定義されます。

Vπ(s) の肩の π は「どの方策で測ったか」を表します。 Vπ と書いたら「方策 π に従ったときの価値」。 V*（V スター）と書いたら「最善を尽くしたときの価値」で、 これが全方策の中で最大です。 肩の記号を落として書かれている文章を読むときは、どちらの話か自分で判断する必要があります。

04

行動まで込みで測る Q

この節のねらい

V だけだと「どう動くか」を決めるのに一手間かかります。 それを解消するのが Q です。 Q 学習（5-e で実装するもの）の Q がこれなので、ここを押さえておきます。

V(s) は状態だけを受け取りました。 行動価値関数 Q(s, a) は、状態と行動の組を受け取ります。

V(s)     = 状態 s から始めたときの収益の平均
Q(s, a)  = 状態 s で行動 a を取り、その後は同じ方策に従ったときの収益の平均

スタート地点 (3,0) での Q* を 4 方向すべてについて計算した実測値です。

行動Q*((3,0), a)動いた先
up0.59049(2,0) へ。ゴールまであと 5 歩
right0.59049(3,1) へ。こちらもあと 5 歩
down0.53144外なので動けない。1 歩損した
left0.53144外なので動けない。1 歩損した

最適な行動が 2 つあります up と right がまったく同じ値です。 マス目を見れば分かりますが、スタートからゴールへの最短経路は 2 通りある （上回りと右回り）ので、どちらを選んでも同じ。 最適方策は 1 つとは限りません。

動けなかった 2 つは 0.9 倍 0.53144 = 0.59049 × 0.9。 壁にぶつかって同じマスに留まったので、1 歩ぶん余計に γ が掛かっただけです。

V と Q の関係

表を見てください。Q* の 4 つの値のうちいちばん大きいものが 0.59049、これは §01 の表のスタート地点の値と同じです。

V*(s) = max over a  of  Q*(s, a)      # 最善を尽くすなら、一番良い行動の値
なぜ Q のほうが使いやすいのか

V しか持っていないと、行動を選ぶのに 「各行動でどこへ行くか」を知っている必要があります（＝ 遷移 P を知っている必要がある）。 Q を持っていれば、4 つの数字を見比べて大きいほうを選ぶだけ。 遷移を知らなくていい。 実機のロボットでは遷移（＝物理）を正確には知らないので、これは大きな差です。 5-e で Q 学習を実装するのは、この性質があるからです。

05

差だけを見るアドバンテージ

この節のねらい

3 つ目の A を出します。V と Q が分かっていれば引き算するだけです。 Step 8 の PPO で主役になる量なので、名前と意味だけ押さえます。

アドバンテージ（advantage）は、その名のとおり「どれだけ得か」です。

A(s, a) = Q(s, a) - V(s)      # その行動は平均よりどれだけ良いか

スタート地点で計算すると（実測値）、

行動Q*V*A* = Q* − V*
up0.590490.590490.00000
right0.590490.590490.00000
down0.531440.59049−0.05905
left0.531440.59049−0.05905

符号だけ見れば良し悪しが分かります A > 0 なら「平均より良い行動」、A < 0 なら「平均より悪い行動」。 最適方策では、最善の行動の A がちょうど 0 になります （それが平均そのものだから）。

なぜわざわざ引き算するのか（Step 8 の伏線）

Q の値は 0.59 と 0.53 で、1 割しか違いません。 この 2 つを見比べて「上のほうが良い」と学習するのは、数字が近すぎて難しい。 引き算して 0.00 と −0.06 にすると、 違いがそのまま浮き上がります。

ニューラルネットを使う学習では、この「どれだけ差があるか」の信号の鮮明さが 学習の速さを直接左右します。PPO が Q ではなく A を使うのはこのためです。

3 つの関係を 1 行で
  1. V(s) — この場所はどれくらい良いか
  2. Q(s,a) — この場所でこの行動を取るとどれくらい良いか
  3. A(s,a) = Q(s,a) − V(s) — その行動は平均と比べてどれくらい良いか

この段階ですること 5-b で書いたループを関数に包み、開始地点を選べるようにするだけです。

def value_of(s0, gamma=0.9, n_ep=20000, seed=2):
    rng = np.random.default_rng(seed)
    if s0 == GOAL:
        return 0.0                 # ゴールは着いた時点で終わりなので 0

5-b では state, rewards = START, [] と書いていました。 今回は「好きなマスから始められる」ようにしたいのですが、どう変えますか。

答えと解説を見る
        state, rewards = s0, []

変更はこれだけです START という固定の値を、引数 s0 に置き換えるだけ。 価値関数が「状態を受け取る関数」だというのが、 コードの形としてここに現れています。

print(value_of((0, 2)))      # -> 0.4993  ゴールの隣（理論値 0.5000）

段階 3

表を読む

この段階ですること コードは書きません。 作った表を見て 2 つの問いに答えてください。 これが今回いちばん大事な作業です。

問い 1. ゴールの隣 (0,2) の値が 0.504 です。 最適方策なら 1.000 のはずなのに、なぜ半分になっているのでしょうか。

答えを見る

ランダム方策はゴール方向（右）を選ぶ確率が 1/4 しかないから。 残り 3/4 は別方向へ行き、戻ってくるまでに γ が何度も掛かって値が目減りします。 良い場所にいることと、良い行動を取れることは別です。

問い 2. 左下のスタート地点 0.053 と、 右下の (3,3) の 0.179。3 倍以上の差があります。 どちらもゴールまで歩数は 6 歩と 3 歩です。この差は何を意味していますか。

答えを見る

歩数が近いほど価値が高い、というだけではありません。 ランダムに動いたときに「ゴールへ向かいやすいか」が効いています。 (3,3) は右端の列にいるので、上に動く行動がそのままゴール方向に繋がる。 スタート地点は反対の角にあり、壁 (3,2) にも進路を塞がれている。

ここが本質です 価値の表は「マス目の地形」と「方策」の両方を反映しています。 同じ地形でも方策が変われば表は変わる（§03 の 2 枚の比較）。 価値関数は、環境と方策の相互作用を 1 枚に要約したものだと考えてください。

07

まとめ

今回で分かったこと
  1. V(s) ＝ その状態から始めたときの収益の平均。最後まで歩かなくても行動を選べるようにするための表
  2. 価値はマスの性質ではない。「マスと方策の組」の性質。 同じマスでもランダム方策なら 0.053、最適方策なら 0.590
  3. Q(s,a) は行動まで込み。遷移を知らなくても行動を選べるので実用上こちらが便利
  4. A(s,a) = Q(s,a) − V(s)。差だけを取り出して信号を鮮明にする。PPO の主役
  5. V*(s) = maxa Q*(s,a)
