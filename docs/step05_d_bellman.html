02

それがベルマン方程式

この節のねらい

§01 で完成した式に名前をつけます。新しい計算は出ません。

§01 の式が ベルマン最適方程式（Bellman optimality equation）です。 強化学習の本で最初の山場として扱われますが、言っていることは 1 行です。

ベルマン方程式が言っていること

「ここの価値は、今もらう報酬と、次の場所の価値を割り引いたものの合計である」

それだけです。難しいのは式ではなく、 「価値の定義の中に価値が出てくる」という自己参照の形に慣れることです。

いちばん大事な語ベルマン方程式
何をするもの
ある状態の価値を、隣の状態の価値で言い換える関係式。 収益の定義（最後まで足す）を、1 歩ぶんの関係に畳み込んだもの。
なぜ今出るか
5-c のモンテカルロは最後まで歩く必要があった。 ベルマン方程式は「1 歩先の情報」だけで価値を更新できるので、 エピソードが終わるのを待たなくていい。
どこに効くか
次回 5-e の Q 学習 は、この式を 1 行に写しただけのもの。 Step 8 の PPO でも、Critic の学習目標はベルマン方程式から作られる。 ここから先の手法は、ほぼ全部これの変種。

自己参照は循環論法ではないのか V を求めるのに V を使っている、というのは一見おかしく見えます。 しかしゴールの隣だけは、右辺に V が出てきません （着いたら終わりなので次の価値が 0）。 そこだけは他に頼らず確定できる。 そこから 1 マスずつ外へ広がっていきます。次の節でそれを見ます。

表のいちばん下の行が理由です。ベルマン方程式を直接解くには、 「この状態でこの行動を取ると、次はどうなるか」を全部知っている必要があります。 マス目なら知っています。実機のロボットでは知りません。

05

max を平均に変えると

この節のねらい

ここまでは最適方策の価値 V* を求めてきました。 5-c で作ったもう 1 枚の表——ランダム方策の Vπ——も ベルマン方程式で求まります。違いは 1 箇所だけです。

V*(s)   = max over a of [ r + γ·V*(次) ]        # 最善を選ぶ
Vπ(s)   = sum over a of  P(a)×[ r + γ·Vπ(次) ]   # 方策の確率で平均する

max が重み付き平均に変わっただけです。 ランダム方策なら 4 方向とも確率 1/4 なので、単純な平均になります。

スイープ数時間V(START)
V*（max）40.1 ms0.590490
Vπ（平均）1414.0 ms0.053213

5-c の答え合わせになっています 0.053213 が正確な値です。 あなたがモンテカルロで出した 0.0523、5-b で出した 0.0535—— どちらも正解の周りでぶれていたことが確認できます。

ランダム方策のほうが 141 スイープもかかるのはなぜか max はいちばん良い経路だけを通して情報を流すので、波が速く広がります。 平均だと壁にぶつかる行動も 1/4 の重みで混ざるため、値がじわじわとしか動きません。 「良い方だけ見る」ほうが収束が速い——直感に合うはずです。

この課題のねらい

なぜこの課題をやるのか ベルマン方程式をコードとして 1 行書くため。 式を読んで納得することと、その 1 行を自分で書けることの間には差があります。 次回の Q 学習は、この 1 行を書き換えるだけなので、ここが土台になります。

やり終えたとき言えること ——「歩いて測る」と「計算で求める」の違いを、自分が出した 2 つの数字で説明できる。

段階 1

1 マスぶんの更新を書く

この段階ですること 「あるマスの新しい値を計算する」関数を 1 つ書きます。スイープはまだしません。

def backup(s, V, gamma=0.9):
    # s の新しい値を、4 方向すべて試して計算する
    candidates = []
    for a in range(4):
        nxt, reward, done = step(s, a)
        candidates.append(???)        # ← ここだけ考える
    return max(candidates)

§01 で完成させた式は r + γ × V(次のマス) でした。 ただし 1 つ注意があります—— ゴールに着いた場合（done が True）は、 そこで終わりなので次のマスの価値を足してはいけません。 これを if で場合分けして 1 行にしてください。

答えと解説を見る
        candidates.append(reward + (0.0 if done else gamma * V[nxt]))

なぜ done の場合分けが要るのか ゴールに着いた瞬間に報酬 +1 をもらってエピソードが終わります。 その先は存在しないので、未来の価値は 0。 これを忘れて reward + gamma * V[nxt] と書くと、 V[GOAL] を足してしまいます。今回は V[GOAL] = 0 のままなので たまたま同じ答えになりますが、 ゴールで終わらない設定に変えた瞬間に壊れます。

この場合分けは実装でよく忘れられます Step 7 で SB3 を使うと terminated と truncated という 2 つのフラグが出てきますが、区別が要るのはまさにこの行のためです。 「ゴールした（先が無い）」のか「時間切れで打ち切った（先はあった）」のかで、 未来の価値を足すかどうかが変わります。

確認方法 全マス 0 の状態から、ゴールの隣だけ計算してみます。

V = {(r, c): 0.0 for r in range(N_ROW) for c in range(N_COL) if GRID[r][c] != "#"}
print(backup((0, 2), V))    # -> 1.0   ゴールに入れるので報酬がもらえる
print(backup((3, 0), V))    # -> 0.0   周りが全部 0 なのでまだ何も分からない
段階 2

スイープを繰り返して収束させる

この段階ですること 段階 1 の関数を全マスに当てはめ、 変化がなくなるまで繰り返します。写経で構いません。

def value_iteration(gamma=0.9, tol=1e-10):
    V = {(r, c): 0.0 for r in range(N_ROW) for c in range(N_COL) if GRID[r][c] != "#"}
    for sweep in range(1, 1000):
        delta = 0.0
        for s in V:
            if s == GOAL:
                continue                   # ゴールの価値は 0 のまま動かさない
            new = backup(s, V, gamma)
            delta = max(delta, abs(new - V[s]))
            V[s] = new                     # その場で書き換える（次のマスにすぐ伝わる）
        print(f"{sweep} スイープ後  V(START)={V[START]:.5f}  最大変化={delta:.2e}")
        if delta < tol:
            break
    return V

V_star = value_iteration()

2 スイープ後  V(START)=0.00000  最大変化=9.00e-01
3 スイープ後  V(START)=0.59049  最大変化=8.10e-01
4 スイープ後  V(START)=0.59049  最大変化=0.00e+00

3 スイープ目で突然 0.59049 になります §03 の絵のとおり、波がスタート地点に到達した瞬間です。 しかも一気に最終値になります—— 途中の半端な値を経由しません。マス目のように遷移が決まりきっている場合、 値は「まだ届いていない 0」か「正しい値」のどちらかになるためです。

段階 3

ランダム方策版を作って 5-c と比べる

この段階ですること max を平均に変えるだけです。 そして 5-c のモンテカルロの結果と突き合わせます。

def policy_evaluation(gamma=0.9, tol=1e-12):
    V = {(r, c): 0.0 for r in range(N_ROW) for c in range(N_COL) if GRID[r][c] != "#"}
    for sweep in range(1, 100000):
        delta = 0.0
        for s in V:
            if s == GOAL:
                continue
            total = 0.0
            for a in range(4):
                nxt, reward, done = step(s, a)
                total += 0.25 * (reward + (0.0 if done else gamma * V[nxt]))
            delta = max(delta, abs(total - V[s]))
            V[s] = total
        if delta < tol:
            break
    print(f"{sweep} スイープで収束")
    return V

V_pi = policy_evaluation()
print(f"正確な値       V(START) = {V_pi[START]:.6f}")
print(f"モンテカルロ推定 V(START) = {value_of(START):.6f}")

06.5

なぜ片方だけが「正確」なのか

この節のねらい

§06 段階 3 の 2 行は、今回いちばん大事な結果です。 なぜそうなるのかを 3 つに分けて掘り下げます。 ここを理解しておくと、次回以降に出てくる手法が「どの壁を回避しているのか」で整理できます。

その 1: 「測る」と「解く」は質が違う

モンテカルロがやっているのは測定です。サイコロを 2 万回振って出目の平均を測るのと同じで、 何回やっても真の値にぴったりは届きません。

試行回数推定値真の値との誤差
2000.0577950.004582
2,0000.0550700.001857
20,0000.0522940.000919
200,0000.0532670.000055

誤差は試行回数の平方根に反比例してしか減りません 10 倍がんばって誤差が約 1/3。桁を 1 つ増やしたければ 100 倍必要です。 一方ベルマンがやっているのは方程式を解くこと。 0.053213 は測った値ではなく満たすべき条件から導いた値で、 誤差という概念がそもそもありません。

その 2: ベルマン方程式は連立一次方程式

ランダム方策のベルマン方程式を 14 マス分すべて書き並べると、 未知数 14 個の連立一次方程式になります。

V(3,0) = 0.25×[0 + 0.9×V(2,0)] + 0.25×[0 + 0.9×V(3,1)] + ...
V(3,1) = ...
（14 本）

つまり np.linalg.solve で一発で解けます。実測すると 1.1 ms で V(START) = 0.053212770 が出ます。141 スイープの繰り返しすら不要でした。

ではなぜ反復法を使ったのか 次回の Q 学習がこの反復の形をしているからです。 また連立方程式として解く方法は、状態が増えると行列が巨大になって使えなくなります （14 マスなら 14×14 ですが、状態が 100 万個なら 100 万×100 万）。

その 3: 「遷移を知っている」の正確な意味

両方とも同じ step() を呼んでいますが、呼び方が決定的に違います。

# モンテカルロ
state = s0
for t in range(500):
    state, reward, done = step(state, rng.integers(4))
    #                       ^^^^^ 今いる場所。前の結果で決まる

# ベルマン
for s in V:                # 14 マス全部について
    for a in range(4):     # 4 方向全部について
        nxt, reward, done = step(s, a)
        #                         ^ 任意の場所を指定できる

ここが本質です モンテカルロは「今いる場所」からしか次に進めません。 ベルマンは「もしここにいたら」を自由に問い合わせられます。 一度も訪れていないマスについても「ここで上に行ったらどうなる？」と聞ける。 これが「遷移を知っている」ということです。

step() の呼び出し回数
モンテカルロ（14 マス × 2 万回）12,313,457 回
ベルマン（141 スイープ × 13 マス × 4 方向）7,332 回

1,600 倍の差です。しかも少ないほうが正確。

振り子で使えない理由は 2 つあり、別物です

壁内容対処
A. 遷移を知らない 本物の振り子に「もし角度 1.2 rad・角速度 3.0 で トルク 0.3 を入れたら？」と問い合わせることはできない。 実際にその状態を作って試すしかない 歩いた結果からベルマン方程式を当てはめる
→ 次回の Q 学習
B. 状態が無限にある MuJoCo なら qpos / qvel に好きな値を入れて mj_step を呼べるので遷移は知っている。 だが角度は連続値なので状態が無限個あり、14 行の表に相当するものが作れない ニューラルネットで表を近似する
→ Step 8 の Critic

強化学習という分野の見取り図 大雑把に言えば、この 2 つの壁を回避するための工夫の集積です。 5-d でやった「遷移を知っていて、状態が有限」という状況は 壁が 1 枚もない理想郷でした。だからあれほど速くて正確だったわけです。 これから出てくる手法は「どちらの壁に対処しているのか」で整理できます。

次回の出発点

次回の Q 学習が扱うのは壁 A だけです。 状態は 14 個のままなので、表はそのまま使えます。 「遷移を知らないのに、ベルマン方程式の恩恵を受けたい」—— この欲張りな要求に答えます。

07

まとめ

今回で分かったこと
  1. ベルマン方程式＝「ここの価値 ＝ 今もらう報酬 ＋ γ × 次の場所の価値」。それだけ
  2. 価値の定義の中に価値が出てくるが、ゴールの隣だけは他に頼らず確定できる。 そこから波のように外へ広がる
  3. max を使えば最適方策の価値、確率で平均すればその方策の価値
  4. モンテカルロの 28 万エピソード・16.9 秒が、4 スイープ・0.1 ミリ秒になった。 ただし遷移 P を知っている必要がある
