01

遷移を知らないふりをする

この節のねらい

5-d のコードから「任意の場所を問い合わせる」能力を取り上げると、 何が書けなくなるかを見ます。そこが今回の出発点です。

5-d の backup() はこう書けました。

for a in range(4):
    nxt, reward, done = step(s, a)      # 4 方向すべてを試せる
    candidates.append(reward + (0.0 if done else gamma * V[nxt]))
return max(candidates)

実機ではこれが書けません。「もし左に行ったら」を試すには、実際に左に行くしかない。 そして左に行ってしまったら、もう元の場所には戻れません。

実機で何が起きるか

振り子を角度 1.2 rad・角速度 3.0 rad/s の状態にして 「トルク +0.3 なら？」「−0.3 なら？」と両方試すことはできません。 片方を試した瞬間、振り子は別の状態に移ってしまう。 同じ状態に戻す手段がないのが実機の本質的な制約です。

使える情報は 4 つだけ

1 歩あるくと、手に入るのはこれだけです。

s      いた場所
a      選んだ行動
r      もらった報酬
s'     着いた場所

この 4 つ組を 遷移サンプル と呼びます。 ベルマン方程式をこの 4 つだけで当てはめられないか——それが今回の課題です。

幸い、ベルマン方程式の右辺を見るとほとんど揃っています。

Q(s,a) = r + γ × max Q(s', a')
         ^        ^          ^^
         |        |          これは表を引けば分かる
         |        いま着いた場所 s' がそれ
         いまもらった報酬がそれ

max が残っているのがポイントです max Q(s', a') は「着いた場所での 4 方向の値を見比べる」だけで、 実際にそこで 4 方向を試す必要はありません。表を引くだけ。 つまり1 歩あるいた情報だけで右辺が計算できます。

02

1 つのサンプルで書き換えない

この節のねらい

前回の宿題の答え合わせです。 右辺が計算できたからといって、そのまま代入してはいけない理由を押さえます。

前回の宿題はこれでした。

宿題

1 歩あるいて得られるのはたった 1 つのサンプルです。 それを使って表の値をいきなり書き換えてしまって良いでしょうか。 問題があるとしたら何で、どう対処しますか。

答え：書き換えてはいけません。理由は 2 つあります。

理由 1：サンプルはぶれる

5-c で見たとおりです。ランダムな行動が混ざると、同じ場所から出発しても結果は毎回違う。 1 回の結果は、真の値の周りで大きくぶれた 1 点にすぎません。 それをそのまま代入すると、表がぶれに振り回されます。

理由 2：右辺の Q 自体がまだ間違っている

更新に使う max Q(s', a') は学習途中の表から引いた値です。 最初は全部 0。間違った値を根拠に、全力で書き換えてしまうことになります。

対処：少しだけ近づける

そこで、いきなり置き換えず、今の値と新しい値の間を少しだけ動かします。

新しい値 = 今の値 + α × (こうあるべき値 - 今の値)

α（アルファ）は 学習率（learning rate）と呼ばれる、 0 から 1 の間の小さい数です。

α意味結果
1.0新しい値で完全に置き換える1 回のぶれをそのまま信じる
0.1差の 1 割だけ近づく10 回ぶんくらいの平均になる
0.01差の 1% だけ近づく安定するが遅い
0.0まったく動かさない何も学習しない

これは「少しずつ平均を取る」のと同じことです たくさんのサンプルを溜めて平均する代わりに、 来るたびに少しずつ寄せていく。結果として平均に近づきます。 メモリに何も溜めずに平均が取れるのが利点で、 だからこそ何百万ステップも学習できます。

いちばん大事な語学習率 α
何をするもの
「1 回の経験をどれだけ信じるか」を決める数。 大きいほど新しい経験を重視し、小さいほど過去の蓄積を重視する。
なぜ今出るか
5-d までは正確な計算だったので、置き換えて良かった。 今回からぶれるサンプルを扱うので、緩衝材が要る。
どこに効くか
ニューラルネットの学習でも同じ名前・同じ役割で出てきます （Step 7 で SB3 を使うとき learning_rate という引数がそれ）。 今日の α と、そこで指定する値は、まったく同じ概念です。
03

Q 学習の更新式

この節のねらい

§01 と §02 を合体させます。これが Q 学習のすべてです。

§01 で「1 歩あるけば右辺が計算できる」と分かりました。 §02 で「いきなり代入せず少しだけ近づける」と決めました。合わせるとこうなります。

target = r + γ × max Q(s', a')          # こうあるべき値（1 サンプルによる推定）
Q(s,a) = Q(s,a) + α × (target - Q(s,a))  # そこへ少しだけ近づける

これで終わりです。Q 学習という名前のアルゴリズムは、この 2 行しかありません。

2 行の出どころ

1 行目は 5-d のベルマン方程式そのものです。 違うのは、4 方向を試す代わりに実際に歩いた 1 方向だけを使うこと。

2 行目は §02 の「少しずつ寄せる」です。 新しい発想はひとつも入っていません。

target - Q(s,a) には名前があります TD 誤差（Temporal Difference error）と呼びます。 「予想していた値」と「1 歩あるいて分かった値」のズレのこと。 ズレが大きいほど大きく修正する、という自然な作りになっています。 この量は Step 8 の PPO でも中心的な役割を果たします。

なぜ V ではなく Q なのか

5-c で触れたとおりです。V しか持っていないと、 行動を選ぶのに「各行動でどこへ行くか」を知る必要があります—— つまり遷移を知っている必要がある。 今回は遷移を知らないという前提なので、V では詰みます。 Q なら 4 つの数字を見比べるだけで行動が選べます。

04

どう歩くかを決める

この節のねらい

更新式はできました。あと 1 つ決めることがあります——そもそもどう歩くのか。 自明に見えて、間違えると一切学習できません。実測で確かめます。

素直に考えると「表を見て、いちばん良い行動を選ぶ」でよさそうです。 これを 貪欲（greedy）な選び方と呼びます。

a = argmax Q[s]        # 4 つのうち最大のものを選ぶ

これだけだと、まったく学習できません。実測すると 20 回試して 0 回成功です。

なぜ失敗するのか 表は最初全部 0 です。4 つとも同じなので argmax は常に 最初の行動（上）を返します。 スタートから上へ 3 回進むと左上の角に着き、そこで上は壁。 以後ずっと同じ場所で上を選び続けます。 ゴールに一度も着かないので報酬が入らず、表は 0 のまま。永久に何も起きません。

ときどきでたらめに動く

対処は単純です。確率 ε ででたらめな行動を選びます。 これを ε-greedy（イプシロン・グリーディ）と呼びます。

if 乱数 < ε:
    a = でたらめな 4 方向のどれか      # 探索（exploration）
else:
    a = argmax Q[s]                    # 活用（exploitation）
ε意味結果（20 回試行）
0.0常に最善を選ぶ0/20 成功（一度もゴールしない）
0.0520 回に 1 回でたらめ20/20 成功
0.110 回に 1 回でたらめ20/20 成功
1.0常にでたらめ（＝ランダム方策）20/20 成功

ε=1.0 でも学習できるのは驚きかもしれません 歩き方がでたらめでも、更新式の中の max が「最善を選んだ場合」を計算しているからです。 でたらめに歩き回って集めた経験から、最善の方策を学べる。 これが off-policy と呼ばれる性質で、次回 5-f の主題です。

探索と活用のジレンマ

活用＝今知っている中で最善を選ぶ。探索＝知らないことを試す。 この 2 つは同時にできません。探索に使った 1 手は活用に使えない。

今回のマス目は小さいので ε が何でも成功しますが、 問題が大きくなるとここが最大の難所になります。 Step 9 で振り子の学習が進まないとき、真っ先に疑う場所のひとつです。

段階 2

更新式を書く

この段階ですること §03 の 2 行をコードにします。 今回の本題はここだけです。

def update(Q, s, a, r, s_next, done, alpha=0.1, gamma=0.9):
    target = r + (0.0 if done else gamma * max(Q[s_next]))
    Q[s][a] = ???              # ← ここだけ考える

target はもう計算してあります。 §02 で決めた「今の値と target の間を α だけ動かす」を 1 行で書いてください。 今の値は Q[s][a] です。

答えと解説を見る
    Q[s][a] = Q[s][a] + alpha * (target - Q[s][a])

書き方は 2 通りあります 展開すると Q[s][a] = (1 - alpha) * Q[s][a] + alpha * target とも書けます。 こちらのほうが「古い値と新しい値の重み付き平均」だとはっきり見えます。 α=0.1 なら「今までを 9 割、新情報を 1 割」。数学的には同じものです。

done の場合分けは 5-d と同じ理由 ゴールに着いたらその先は無いので、未来の価値を足しません。 ここを忘れると、ゴール後も価値が続くことになって表が壊れます。

確認方法 全部 0 の表に対して、ゴールに入る 1 歩を与えてみます。

Q = make_Q()
update(Q, (0, 2), 1, 1.0, GOAL, True)     # (0,2) から右へ。ゴールして報酬 1.0
print(Q[(0, 2)])                          # -> [0.0, 0.1, 0.0, 0.0]

0.1 という数字を見てください 本来の値は 1.0 です。1 回の経験ではその 1 割しか動きません。 これが α の働きです。 何度も同じ経験をすれば、少しずつ 1.0 に近づいていきます。

段階 3

ε-greedy で行動を選ぶ

この段階ですること §04 の選び方を関数にします。写経で構いません。

def choose(Q, s, rng, eps=0.1):
    if rng.random() < eps:
        return int(rng.integers(4))        # 探索: でたらめ
    return int(np.argmax(Q[s]))            # 活用: 表で最大のもの

確認方法 表が全部 0 のとき、eps=0.0 なら必ず 0（上）が返ります。 eps=1.0 なら毎回バラバラになります。

rng = np.random.default_rng(0)
print([choose(Q, START, rng, eps=0.0) for _ in range(8)])   # -> 全部 0
print([choose(Q, START, rng, eps=1.0) for _ in range(8)])   # -> バラバラ

上の行が §04 で見た失敗そのものです 全部 0 の表で貪欲に選ぶと、いつまでも上を選び続けます。 np.argmax は同点のとき最初のインデックスを返すので。

段階 4

学習ループを回す

この段階ですること 段階 1〜3 を繋いで、実際に学習させます。 写経で構いません。

def q_learning(n_ep=500, alpha=0.1, eps=0.1, gamma=0.9, seed=0, cap=500):
    rng = np.random.default_rng(seed)
    Q = make_Q()
    lengths = []
    for ep in range(n_ep):
        s = START
        for t in range(1, cap + 1):
            a = choose(Q, s, rng, eps)
            s_next, r, done = step(s, a)
            update(Q, s, a, r, s_next, done, alpha, gamma)
            s = s_next                     # 次のマスへ移る
            if done:
                break
        lengths.append(t)
    return Q, lengths

Q, lengths = q_learning()
print("最初の 10 エピソードの歩数:", lengths[:10])
print("最後の 10 エピソードの歩数:", lengths[-10:])

1 行ずつが §01〜§04 に対応しています choose が §04、step が環境、 update が §03 の更新式、s = s_next が「1 歩進んだ」。 この 4 行が強化学習の基本ループで、 Step 7 で SB3 が内部でやっているのも構造としては同じです。

確認方法 こういう出力になります。

最初の 10 エピソードの歩数: [211, 67, 11, 6, 6, 6, 6, 8, 6, 7]
最後の 10 エピソードの歩数: [6, 6, 6, 6, 6, 6, 7, 7, 6, 6]

4 エピソード目でもう最短に届いています 1 回目は 211 歩さまよいましたが、そこで得た経験だけで一気に縮みます。 14 マスしかないので、一度ゴールに着けば価値がすぐ全体に伝わるためです。

最後まで 6 歩で揃わないのはなぜか ときどき 7 歩や 8 歩が混ざります。ε=0.1 で 10 回に 1 回でたらめに動くからで、 表が間違っているわけではありません。 学習中の成績は、方策の実力より必ず悪く出ます—— Step 7 で学習曲線を読むとき、これを知らないと過小評価します。

段階 5

学習した方策で歩かせる

この段階ですること 学習が終わったら探索をやめて、 表を信じて歩かせます。これが「学習結果を使う」ということです。

def run_greedy(Q, cap=100):
    s, path = START, [START]
    for t in range(1, cap + 1):
        s, r, done = step(s, int(np.argmax(Q[s])))    # eps なし
        path.append(s)
        if done:
            return t, path
    return None, path

steps, path = run_greedy(Q)
print(f"{steps} 歩でゴール")
print(path)

確認方法 6 歩でゴール と出れば成功です。 5-a で測ったランダム方策の 64.6 歩から、最短の 6 歩まで来ました。

Step 5 全体がここで閉じます
  1. 5-a: ランダム方策は 64.6 歩。「これを 6 に近づけるのが強化学習」と言った
  2. 5-e: 6 歩になった

なぜ最後は ε を外すのか 探索は学習のためのコストです。学習が終わったら払う必要がありません。 実機に載せるときも同じで、本番では探索を切ります （切り忘れるとロボットがときどきでたらめに動きます）。

答えと解説を見る

ゴールした回数は 0。表は全部 0 のままです。 歩数は全エピソードで上限の 500。

スタートから上へ 3 回進むと左上の角 (0,0)。 そこで上は壁なので動けず、以後ずっと同じ場所で上を選び続けます。 ゴールに一度も着かないので報酬が発生せず、target は常に 0 + 0.9 × 0 = 0。更新しても値が変わりません。

これは「バグが無いのに学習しない」状態です 更新式も環境も正しい。歩き方だけが間違っている。 Step 7 以降で「報酬が一度も入らないので学習が始まらない」という事態に遭遇しますが、 原因はたいていこれか、報酬設計のどちらかです。

06

まとめ

今回で分かったこと
  1. Q 学習は 2 行。target = r + γ max Q(s',a') と Q(s,a) += α(target − Q(s,a))。新しい発想はひとつも無い
  2. 1 行目はベルマン方程式を 1 サンプルで置き換えたもの（壁 A への対処）
  3. 2 行目の α は「1 回の経験をどれだけ信じるか」。 メモリに溜めずに平均を取る仕掛け
  4. target − Q(s,a) ＝ TD 誤差。予想と実際のズレ。PPO でも中心的な量
  5. ε-greedy が無いと一度もゴールせず、何も学習しない。バグが無くても学習は失敗する
  6. ランダム方策の 64.6 歩が 6 歩になった
次回（5-f）でやること

Step 5 の最終回です。§04 で触れた 「ε=1.0 の完全にでたらめな歩き方でも、最善の方策が学べる」—— この不思議な性質を掘り下げます。off-policy と呼ばれるもので、 「集めたデータを何度も使い回せるか」という実用上とても重要な違いに繋がります。

先に考えておいてください—— 更新式のどこが「でたらめに歩いても最善が学べる」ことを可能にしているでしょうか。 ヒント: §03 の 1 行目に、実際に選んだ行動 a とは無関係な部分があります。
