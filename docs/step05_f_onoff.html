on-policy と off-policy

Q 学習の更新式を 1 箇所だけ変えると、性格がまったく違う手法になる。 その違いが「集めたデータを使い回せるか」を決める。

前回までと、今回の問い

前回までで分かっていること
  1. Q 学習は 2 行。target = r + γ maxa' Q(s',a') と Q(s,a) += α(target − Q(s,a))
  2. α は「1 回の経験をどれだけ信じるか」、ε-greedy が無いと一切学習しない
  3. ランダム方策の 64.6 歩が 6 歩になった
この教材が答える問い

1. なぜ「でたらめに歩いても最善の方策が学べる」のか？

2. on-policy と off-policy の違いは、実際に何を変えるのか？

今回の進め方。 宿題の答え合わせから始めて、更新式を 1 箇所だけ変えた別手法を並べます。 違いは崖のあるマス目ではっきり出ます。 最後に Step 5 全体を振り返り、Step 6 へ繋ぎます。

01

宿題の答え合わせ

この節のねらい

前回の宿題に答えます。Q 学習の 1 行目にある小さな非対称性が、 今回のすべての出発点です。

宿題

更新式のどこが「でたらめに歩いても最善が学べる」ことを可能にしているでしょうか。 ヒント: §03 の 1 行目に、実際に選んだ行動 a とは無関係な部分があります。

答え：max です。

target = r + γ × max_{a'} Q(s', a')
                        ^^^^^^^^^^^^
                        ここに a は出てこない

更新式を左から右まで読むと、実際に選んだ行動 a が出てくるのは左辺の Q(s,a) だけです。右辺は「s' に着いた」という事実しか使っていません。

つまり、こう言っています 「どうやってここに来たかは問わない。ここから最善を尽くしたらいくらになるか」。 でたらめに歩いてたまたま s' に来たのだとしても、 そこから先は最善の方策の話をしている。 だから歩き方がどれだけ下手でも、学ばれるのは最善の方策になります。

言い換えると

Q 学習は「歩くための方策」と「学んでいる方策」が別物です。 ε-greedy で歩きながら、学んでいるのは ε を含まない完全に貪欲な方策。 このズレがあることが、今回のキーワード off-policy の意味です。

02

1 箇所変えると SARSA になる

この節のねらい

「ズレをなくしたらどうなるか」を試します。 更新式の max を別のものに置き換えるだけで、 まったく性格の違う手法になります。

ズレをなくすには、「最善を尽くしたら」ではなく「実際に次に選ぶ行動で」 計算すればいい。

Q 学習  target = r + γ × max_{a'} Q(s', a')     # 次に最善を尽くしたら
SARSA   target = r + γ ×     Q(s', a')     # 次に実際こう動くなら
                                        ^^
                              実際に選んだ次の行動

この手法を SARSA と呼びます。名前の由来は、更新に使う 5 つ組 s, a, r, s', a' をそのまま並べたものです。

a' をどこから持ってくるか Q 学習では「次の行動」を更新時に決める必要がありませんでした。 SARSA では先に決めておく必要があります。 ε-greedy で選ぶので、10 回に 1 回はでたらめな a' が入ります。 つまり SARSA の target には「たまに失敗する自分」が織り込まれます。 これが次の節の違いを生みます。

Q 学習SARSA
次の価値の見積もりmaxa' Q(s',a')Q(s',a')
学んでいる方策完全に貪欲な方策ε-greedy な自分自身
歩く方策との関係別物（off-policy）同じ（on-policy）
学ぶもの理想的な最善失敗も込みの現実的な最善

なぜこうなるのか

Q 学習は max を使うので、「自分は絶対に間違えない」という前提で 価値を見積もります。崖の真上を歩くのは、間違えなければ最短です。 ——しかし実際には ε=0.1 で 10 回に 1 回でたらめに動くので、 学習中は何度も崖に落ちます。それが −22.84 の正体です。

SARSA は Q(s',a') を使うので、 その ε でたらめ行動が見積もりに入ってきます。 崖の隣にいると「たまにでたらめに動いて落ちる」という事実が価値を押し下げ、 結果として崖から離れた経路を選びます。

どちらを使うべきか

本番で探索を切るなら Q 学習——学習後は間違えないので、崖の真上が正しい。

学習中の失敗に実コストがあるなら SARSA—— 実機のロボットが崖から落ちたら壊れます。 Step 12 で実機に載せるとき、この選択は現実的な問題になります。

04

データを使い回せるか

この節のねらい

ここが on/off-policy のいちばん実用的な違いです。 Step 7 でアルゴリズムを選ぶとき、判断の軸になります。

まず「使い回す」とは何をすることか

いまのコードは、1 歩あるくたびに1 回だけ更新して、その経験を捨てています。

s_next, r, done = step(s, a)          # 環境を 1 歩進める（ここがコスト）
Q[s][a] += alpha * (target - Q[s][a]) # 1 回だけ使う
s, a = s_next, a_next                 # もう振り返らない

「使い回す」とは、これを箱に溜めておいて、あとで何度でも取り出すことです。 この箱を リプレイバッファ（replay buffer）と呼びます。

buffer = []

# 集めるとき: 環境を 1 歩進める
s_next, r, done = step(s, a)
buffer.append((s, a, r, s_next, done))      # 捨てずに保存

# 学習するとき: 環境は進めない。ただの計算
for _ in range(10):
    s, a, r, s_next, done = random.choice(buffer)   # 過去の経験を引き直す
    target = r + gamma * max(Q[s_next])
    Q[s][a] += alpha * (target - Q[s][a])

1 歩あるくごとに 10 回学習することになるので、 同じ学習量に必要な「実際に歩く回数」が減ります。

なぜ Q 学習だと成立するのか

保存した 5 つ組 (s, a, r, s_next, done) を見てください。 方策に関係する情報がひとつも入っていません。 これは「世界がこうなっている」という物理的な事実だけで、 方策をどう更新しようが古くなりません。

そして target は学習する瞬間に、そのときの Q から計算し直します。

target = r + gamma * max(Q[s_next])
                         ^^^^^^^^^^ 今の最新の表を引く

なぜ SARSA だと困るのか

SARSA の target には a_next が必要です。

target = r + gamma * Q[s_next][a_next]
                              ^^^^^^^^ これは誰が決めた？

a_next は「集めた時点の方策の判断」です choose() がそのときの Q を見て選んだ行動なので、 保存した 5 つ組に「あのときの方策」が焼き付いています。 Q を更新すると choose() の返す行動も変わり、 保存してある a_next は「今の自分ならもう選ばない行動」になる。 それを根拠に学習すると、存在しない方策の価値を計算していることになります。

実測: データ効率がどれだけ変わるか

崖のマス目で「環境を何歩あるけば学習できるか」を測りました（10 シード中の成功数）。

正直なところ: このマス目では SARSA にリプレイを付けても大体動く

理屈のうえでは不正なのですが、実際に試すと 10 シード中 9 つは動いてしまいます （壊れたのは 1 つだけ）。

Q 学習 + リプレイ    成功 10/10   歩数 [7,7,7,7,7,7,7,7,7,7]
SARSA + リプレイ     成功  9/10   歩数 [9,9,9,9,9,30,9,9,9,9]

18 マスしかなく方策があまり変わらないので、a_next が古くなっても大差ないためです。 差が効いてくるのは規模が大きいとき—— 方策がニューラルネットで大きく変化し、バッファに何十万件も溜まっている状況では、 古い a_next は現在の方策とかけ離れます。

どんな集め方のデータでも使える

保存した 5 つ組に方策の情報が入っていない、ということは—— 誰がどう集めたデータでも構わないということです。

データの出どころQ 学習（off-policy）SARSA（on-policy）
いま歩いて集めたばかり使える使える
1 時間前の自分が集めた使える使えない
完全にでたらめな歩行使える使えない
人間が操作した記録使える使えない
同じデータを 100 回使う使える使えない

なぜこれが実機で決定的なのか シミュレーションなら 4,000 歩も 600 歩も一瞬です。実機では違います。

  • 振り子を 1 歩進める ＝ 実時間 0.01 秒。4,000 歩で 40 秒（これは軽いほう）
  • だがエピソードごとに人が手で初期姿勢に戻すなら、1 エピソード数十秒
  • 崖に相当する失敗がハードウェアの破損なら、試行回数そのものに上限がある

「実際に動かす回数」が高価な場面では、 1 回の経験を何度も使えるかどうかが決定的になります。 実機寄りの研究で off-policy 手法（SAC など）が好まれるのはこのためです。

いちばん大事な語on-policy / off-policy
何が違うのか
「データを集めた方策」と「学習している方策」が同じか違うか。 同じなら on-policy、違ってよければ off-policy。
実際に何が変わるか
データを使い回せるかどうか。 off-policy は過去のデータをリプレイバッファ（＝経験を溜めておく箱）に貯めて 何度も学習に使える。on-policy は使い捨て。
どこに効くか
Step 7 でアルゴリズムを選ぶとき。 PPO は on-policy、SAC と DQN は off-policy。 実機では 1 歩が高価（時間がかかる・壊れる）なので、 データを使い回せる off-policy が有利になりやすい。
では on-policy は劣っているのか

そうではありません。off-policy は学習が不安定になりやすいという弱点があります。 古いデータと今の方策がかけ離れていると、見当違いな更新をしてしまう。

PPO が on-policy なのに広く使われているのは、安定して学習が進むからです。 シミュレーションならデータは安く大量に作れるので、使い捨てても困りません。 「シミュレータがあるなら PPO、実機データが貴重なら off-policy」 というのが大まかな住み分けです。

05

方策を直接いじる道

この節のねらい

Step 8 で実装する PPO は、ここまでとは発想が違う系統に属します。 名前と考え方だけ先に置いておきます。実装は Step 8 です。

ここまでの手法はすべて価値の表を作り、そこから行動を決めていました。 Q を学び、argmax で方策を導く。方策は結果として出てくるものでした。

もうひとつの道があります。価値を経由せず、方策そのものを直接いじる—— 方策勾配法（policy gradient）と呼ばれる系統です。

価値ベース   Q を学ぶ → argmax で方策が決まる        # Q 学習、DQN
方策ベース   方策を直接いじる                          # 方策勾配、PPO

考え方は拍子抜けするほど素朴です 「うまくいった行動の確率を上げ、うまくいかなかった行動の確率を下げる」。 それだけです。「うまくいった」の度合いを測るのに何を使うかというと—— 5-c で出てきたアドバンテージ A = Q − V です。 平均よりどれだけ良かったか、その分だけ確率を動かす。

なぜ振り子では方策ベースが要るのか

振り子のトルクは連続値です。 argmax を取ろうにも、無限にある選択肢を全部比べることができません。 方策ベースなら「トルクを直接出力する関数」を学べばよいので、この問題が起きません。 連続的な行動を扱うロボット制御で方策ベースが主流なのは、これが理由です。

手を動かす

この課題のねらい

なぜこの課題をやるのか §03 の 2 枚の経路図を自分で再現するため。 更新式を 1 箇所変えるだけで行動が変わるのを見ると、 「アルゴリズムの違い」が具体物になります。

やり終えたとき言えること ——Step 7 で PPO / SAC / DQN のどれを使うか選ぶとき、 on-policy か off-policy かを判断軸にできる。

進め方

穴埋めは 段階 2 の 1 箇所だけです。 新しいファイル toy/cliff.py を作ってください。 5-e の gridworld_q.py は残しておいてください。

段階 1

崖のあるマス目を作る

この段階ですること 環境を作るだけ。写経で構いません。 5-e までのマス目と違うのは報酬の付け方です。

import numpy as np

CLIFF = [
    "......",
    "......",
    "S!!!!G",
]
DELTA = [(-1, 0), (0, 1), (1, 0), (0, -1)]
N_ROW, N_COL = 3, 6
START, GOAL = (2, 0), (2, 5)
STATES = [(r, c) for r in range(N_ROW) for c in range(N_COL)]


def step(s, a):
    dr, dc = DELTA[a]
    r, c = s[0] + dr, s[1] + dc
    if not (0 <= r < N_ROW and 0 <= c < N_COL):
        r, c = s                                  # 外に出ようとしたら留まる
    nxt = (r, c)
    if CLIFF[nxt[0]][nxt[1]] == "!":
        return START, -100.0, False               # 崖: 大損してスタートに逆戻り
    return nxt, (0.0 if nxt == GOAL else -1.0), nxt == GOAL


def make_Q():
    return {s: [0.0] * 4 for s in STATES}


def choose(Q, s, rng, eps=0.1):
    if rng.random() < eps:
        return int(rng.integers(4))
    return int(np.argmax(Q[s]))

報酬が変わっています 5-b で比べた案 A（1 歩ごとに罰）を使っています。 ゴールで 0、それ以外は −1、崖は −100。 ゴールすれば必ず終わるので γ = 1.0 でも発散しません。 割引せずに済むぶん、経路の長さが収益にそのまま出ます。

崖に落ちてもエピソードは終わりません return START, -100.0, False の False に注目してください。 スタートに引き戻されるだけで、やり直しになります。 落ちるたびに −100 が積み上がるので、「落ちやすい経路」は収益が大きく下がります。

確認方法 崖に落ちる 1 歩を試します。

print(step((2, 0), 1))    # スタートから右へ -> ((2, 0), -100.0, False)
print(step((2, 0), 0))    # スタートから上へ -> ((1, 0), -1.0, False)
段階 2

2 つの更新式を書き分ける

この段階ですること §02 の 2 行をコードにします。 今回の本題はここだけです。

def learn(kind, n_ep=3000, alpha=0.1, eps=0.1, gamma=1.0, seed=0, cap=200):
    rng = np.random.default_rng(seed)
    Q = make_Q()
    returns = []
    for ep in range(n_ep):
        s = START
        a = choose(Q, s, rng, eps)          # 最初の行動を先に決めておく
        total = 0.0
        for t in range(cap):
            s_next, r, done = step(s, a)
            total += r
            a_next = choose(Q, s_next, rng, eps)    # 次の行動も先に決める

            if kind == "q":
                target = r + (0.0 if done else gamma * max(Q[s_next]))
            else:
                target = ???                # ← ここだけ考える（SARSA）

            Q[s][a] += alpha * (target - Q[s][a])
            s, a = s_next, a_next
            if done:
                break
        returns.append(total)
    return Q, returns

Q 学習の行がすぐ上にあります。§02 の表を見ながら、 maxa' Q(s_next) を何に置き換えればいいかを書いてください。 使える変数は a_next です。

答えと解説を見る
                target = r + (0.0 if done else gamma * Q[s_next][a_next])

違いは max(Q[s_next]) と Q[s_next][a_next] だけ 前者は「4 つのうち最大」、後者は「実際に次に選ぶ 1 つ」。 a_next は choose() が返したものなので、 10 回に 1 回はでたらめな行動です。 その「たまに失敗する自分」が価値の見積もりに混ざります。

s, a = s_next, a_next の行に注目 SARSA では次の行動を先に決めてしまうので、 次のループではそれをそのまま使います。 Q 学習だけなら a_next は不要ですが、 ここでは 2 つを同じループで書き分けたいので両方用意しています。

段階 3

経路を比べる

この段階ですること 両方を学習させ、 ε を切って歩かせた経路を見比べます。写経で構いません。

def greedy_path(Q, cap=30):
    s, path = START, [START]
    for t in range(cap):
        s, r, done = step(s, int(np.argmax(Q[s])))
        path.append(s)
        if done:
            return path
    return path


for kind, name in (("q", "Q 学習  (off-policy)"), ("sarsa", "SARSA  (on-policy)")):
    Q, returns = learn(kind)
    path = greedy_path(Q)
    print(f"{name}")
    print(f"  経路         : {path}")
    print(f"  歩数         : {len(path) - 1}")
    print(f"  学習中の平均収益: {np.mean(returns[-500:]):.2f}")
