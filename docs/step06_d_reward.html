報酬とベースライン

仮置きのままだった報酬を設計し、環境を自己診断して、 Step 7 で学習結果を比べるための基準線を先に作る。

00

前回までと、今回の問い

前回までで分かっていること
  1. 観測は [cosθ, sinθ, ω]、行動は [-1, 1]
  2. terminated は常に False（継続タスク）。 truncated は TimeLimit ラッパーに任せる
  3. reward = 0.0 のまま放置してある。今回それを設計する
この教材が答える問い

1. 「上端にいたら +1」という素朴な報酬の何が問題なのか？

2. 学習が成功したかどうかを、何と比べて判断するのか？

今回の進め方。 宿題に答えて報酬を設計し、check_env で環境を点検します。 最後にStep 4 で書いた古典制御を、この環境の上で採点します—— それが Step 7 で学習結果を比べるときの基準線になります。

01

宿題の答え合わせ

この節のねらい

素朴な報酬がなぜダメなのかを、実測で確かめます。 5-e で見た失敗とまったく同じ構造です。

宿題

振り子を上端に立たせたい。報酬をどう定義しますか。 「上端にいたら +1、それ以外は 0」で良いでしょうか。

答え：ダメです。報酬が一度も発生しません。

この報酬でランダム方策を 500 ステップ × 10 エピソード回した結果です（実測）。

方策合計報酬上端にいたステップ数
ランダム方策0.000.0 / 500
古典制御（Step 4）216.20216.2 / 500

文字通りゼロです Step 4 で確かめたとおり、この振り子はトルクが重力の 1/3 しかないので、 でたらめに押しても上端付近には一度も到達しません。 報酬が 0 のままでは、何を改善すればいいのか分かりません。

5-e の ε=0 とまったく同じ構造です

5-e で ε=0 にしたとき、Q テーブルは全部 0 のままでした。 一度もゴールしないので報酬が入らず、更新しても値が変わらない。

今回も同じです。違うのは原因の場所だけ—— あのときは歩き方が悪かった。今回は報酬の設計が悪い。 どちらも「バグが無いのに学習しない」に見えます。

こういう報酬を「疎」と呼びます 疎な報酬（sparse reward）＝ほとんどの時間はゼロで、たまにしか発生しない報酬。 タスクの定義としては正しいのですが、学習の手がかりが無い。 「正しい報酬」と「学習できる報酬」は別物です。

02

密な報酬にする

この節のねらい

疎な報酬の対極を作ります。どの状態にいても、良し悪しが数字で返るようにします。

欲しいのは「上に近いほど高い」が連続的に変わる量です。 観測にすでにそういう数字があります——cosθ です。

姿勢θcosθ−cosθ
真下（ぶら下がり）0+1−1
水平π/200
真上（目標）π−1+1

−cosθ は真下で −1、真上で +1 と、 ちょうど欲しい形になっています。これを土台にします。

reward = -cos(theta) - 0.01 * omega**2 - 0.001 * torque**2
         ^^^^^^^^^^^   ^^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^
         上に近いほど高い  暴れると減点        力を使うと減点
項役割これが無いと
-cosθ上を向かせる何を目指すか分からない
-0.01·ω²静止させる上端をぐるぐる高速で通過して稼ごうとする
-0.001·τ²省エネにする常に全力を出す。実機ではモータが焼ける

2 項目が特に重要です -cosθ だけだと、上端を猛スピードで通り過ぎるだけでも点が入ります。 「通過」ではなく「静止」させたいので、角速度に罰を与えます。 報酬に書いていないことは、方策はやってくれません。

係数はどう決めたのか

正直に言うと目分量です。-cosθ が ±1 の範囲なので、 他の項がそれを上回らないように小さくしてあります。 角速度が 10 rad/s のとき 0.01 × 100 = 1.0 で、ちょうど同じ桁。

係数の決め方そのものが Step 9 の主題です。 今は「桁を揃える」という発想だけ持っておいてください。

03

お手本の点数を先に測る

この節のねらい

Step 6 でいちばん実用的な節です。 学習を始める前に「何点取れれば成功なのか」を決めておきます。 これが無いと、Step 7 で出た数字の良し悪しが判断できません。

幸い、あなたはすでに動く制御器を持っています—— Step 4 で書いたエネルギー整形 + PD です。 それをこの環境の上で採点すれば、基準線になります。

方策合計報酬（500 ステップ × 10 回の平均）上端にいたステップ数
ランダム方策−499.500.0 / 500
古典制御（Step 4）+28.31216.2 / 500

この 2 つの数字が Step 7 で効いてきます 学習した方策が −498 のあたりから動かないなら、何も学べていない。 +28 を超えたなら、人が設計した制御器に並んだということ。 比較対象があるかないかで、同じ数字の意味がまったく変わります。

216/500 という数字も読んでください 古典制御でも上端にいられるのは全体の 43% です。 残りは振り上げに使っています。Step 4 で測った到達時間 2.89 秒が、 100Hz なら 289 ステップ。500 − 289 = 211 とほぼ一致します。 これ以上は物理的に伸びません。

Phase A をやった意味がここで出ます

Step 4 の冒頭で「古典制御は RL の前座ではなく、RL の結果を評価する唯一の物差し」 と書きました。それが具体的に +28.31 という数字になった、ということです。

この基準線が無いと、Step 7 で「報酬が −100 まで上がりました」と言われても、 喜んでいいのか分かりません。

通れば何も表示されません。問題があれば例外か警告が出ます。

05

観測の範囲を測り直す

この節のねらい

6-b で「範囲はランダム方策で回して測ればいい」と書きました。 それが罠だったので訂正します。

同じ環境で、方策を変えて観測の実測範囲を取ったものです。

測り方ω の実測範囲
ランダム方策で測る−1.88 ∼ +1.77
古典制御で測る−10.54 ∼ +10.67
宣言している値±20

ランダム方策では 1/5 しか出ません でたらめに押しても振り子はほとんど動かないからです。 これを信じて ±2 と宣言すると、 学習が進んだ途端に申告違反になります—— そして 6-b で見たとおりエラーは出ません。

正しい測り方

「うまくいっている方策」で測るのが正解です。 今回は Step 4 の古典制御があるので、それで測れば ±10.7 と分かります。 宣言値 ±20 はその約 2 倍で、妥当でした。

お手本が無い場合は物理から見積もるしかありません。 振り子なら「上端に達するのに必要なエネルギー」から最大角速度が計算できます （Step 4 の sqrt(4mgl/I) = 10.7）。

これも「比較対象があると強い」の一例です ランダム方策しか持っていなければ、この間違いに気づけませんでした。 古典制御を書いておいたことが、ここでも効いています。

段階 1

報酬を実装する

この段階ですること step() の reward = 0.0 を置き換えます。

  def step(self, action):
    torque = self._scale(np.clip(action, -1.0, 1.0))[0]
    self.data.ctrl[0] = torque
    for _ in range(self.frame_skip):
      mujoco.mj_step(self.model, self.data)

    theta = self.data.qpos[0]
    omega = self.data.qvel[0]
    reward = ???                      # ← ここだけ考える

    return self._obs(), reward, False, False, {}

§02 で決めた 3 項を書いてください。 係数は 0.01 と 0.001 です。 戻り値は float にしておきます（NumPy のスカラーだと後で警告が出ることがあります）。

答えと解説を見る
    reward = float(-np.cos(theta) - 0.01 * omega**2 - 0.001 * torque**2)

torque を使う点に注意 action ではなく変換後のトルクを使っています。 action（[-1,1]）で罰を与えても意味は通りますが、 実機で気にするのは実際の電流・トルクなので、物理量で書くほうが素直です。

符号を間違えると静かに壊れます +np.cos(theta) と書くと真下にいるほど高得点になり、 方策は下でじっとしていることを学びます。 エラーは出ません。 報酬の符号は、実装後に必ず「真下と真上で値を print して確かめる」こと。

確認方法 真下と真上で報酬を比べます。

import numpy as np
from envs.pendulum_env import PendulumEnv

env = PendulumEnv()
env.reset(seed=0)

for theta, name in ((0.0, "真下"), (np.pi / 2, "水平"), (np.pi, "真上")):
    env.data.qpos[0] = theta
    env.data.qvel[0] = 0.0
    obs, reward, te, tr, info = env.step(np.array([0.0], dtype=np.float32))
    print(f"{name}: reward = {reward:+.4f}")

真下が負、真上が正になっていれば符号は合っています。

段階 3

ランダム方策のベースラインを測る

この段階ですること 下限の基準線を作ります。 学習した方策がこれを超えなければ、何も学べていないということです。

import numpy as np
from gymnasium.wrappers import TimeLimit
from envs.pendulum_env import PendulumEnv


def evaluate(policy, n_ep=10, steps=500):
    totals, ups = [], []
    for ep in range(n_ep):
        env = TimeLimit(PendulumEnv(), max_episode_steps=steps)
        obs, info = env.reset(seed=ep)
        env.action_space.seed(ep)        # これが無いと毎回結果が変わる
        total, up = 0.0, 0
        for t in range(steps):
            obs, reward, terminated, truncated, info = env.step(policy(env, obs))
            total += reward
            if -np.cos(env.unwrapped.data.qpos[0]) > 0.95:
                up += 1
            if terminated or truncated:
                break
        totals.append(total)
        ups.append(up)
    return np.mean(totals), np.mean(ups)


random_policy = lambda env, obs: env.action_space.sample()
total, up = evaluate(random_policy)
print(f"ランダム方策: 合計報酬 {total:.2f}   上端にいたステップ {up:.1f}/500")

確認方法 合計報酬 -499.50 上端にいたステップ 0.0/500 前後になります。

evaluate() は今後ずっと使います Step 7 で学習した方策も、まったく同じ関数で採点します。 採点方法を固定しておくのが実験管理の基本です。

env.action_space.seed(ep) を忘れないでください reset(seed=ep) が seed するのは環境の乱数だけで、 action_space.sample() は別の乱数生成器を使います。 seed しないと実行のたびに結果が変わり、 「前回より良くなった」が本物か偶然か区別できなくなります。 実測では seed 無しだと −499.29 / −499.44 / −499.51 とばらつきました。

段階 4

古典制御を採点して上限の基準線を作る

この段階ですること Step 4 で書いたスイングアップを、 この環境の [-1,1] 形式に合わせて載せます。 新しい制御は書きません——式はそのままです。

I, MGL, TAU = 0.056743, 1.623135, 0.5
E_STAR = 2 * MGL


def wrap(x):
    return (x + np.pi) % (2 * np.pi) - np.pi


def expert(env, obs):
    theta = env.unwrapped.data.qpos[0]
    omega = env.unwrapped.data.qvel[0]
    phi = wrap(theta - np.pi)
    if abs(phi) < 0.3:
        u = np.clip(-8.0 * phi - 1.0 * omega, -TAU, TAU)      # PD
    else:
        E = 0.5 * I * omega**2 + MGL * (1 - np.cos(theta))
        u = np.clip(1.0 * omega * (E_STAR - E), -TAU, TAU)    # エネルギー整形
    return np.array([u / TAU], dtype=np.float32)              # [-1,1] に直す


total, up = evaluate(expert)
print(f"古典制御    : 合計報酬 {total:.2f}   上端にいたステップ {up:.1f}/500")

確認方法 合計報酬 28.31 上端にいたステップ 216.2/500 前後です。

最後の u / TAU が肝心です Step 4 の制御器はN·m を出しますが、 この環境の action は [-1,1] です。 TAU で割って戻しています—— 6-b で環境側に入れた変換の、ちょうど逆をやっていることになります。

この 2 つの数字を記録しておいてください −499.50（何もしない）と +28.31（人が設計した制御）。 Step 7 で学習曲線を見るとき、この 2 本の線を引きます。

07

Step 6 のまとめ

今回で分かったこと
  1. 疎な報酬（上端で +1）ではランダム方策の報酬が文字通り 0。学習の手がかりが無い
  2. 「正しい報酬」と「学習できる報酬」は別物。 -cosθ を土台に密な報酬を作る
  3. 角速度とトルクの罰を足す。報酬に書いていないことは方策はやってくれない
  4. check_env は申告違反を捕まえてくれる唯一の道具。書き換えたら毎回通す
  5. 観測の範囲をランダム方策で測ると 1/5 に過小評価する。 うまくいく方策か、物理から見積もる
  6. 基準線: ランダム −499.50 ／ 古典制御 +28.31
Step 6 全体で手に入れたもの
  1. 6-a 観測は [cosθ, sinθ, ω]。角度をそのまま渡すと上端で数字が飛ぶ
  2. 6-b 行動は [-1,1]。Box の範囲は申告であって強制ではない
  3. 6-c terminated と truncated。混同すると最大 65% 過小評価
  4. 6-d 密な報酬と2 本の基準線
Step 6 の落とし穴は、どれもエラーを出しません

範囲外の観測、truncated の混同、疎な報酬、符号の間違い—— 全部エラー無しで動きます。学習が進まないか、性能が伸びないだけ。

だから仕組みを知っていることと、check_env を通す習慣が 唯一の防御になります。Step 7 で学習が期待どおりにならないとき、 まず環境を疑ってください——アルゴリズムより環境のほうがはるかに壊れやすい。

次は Step 7 — ついに学習を回します

環境ができました。Step 7 では SB3（Stable-Baselines3）を使って PPO で学習させます。あなたが書くのは数十行です。

見るべきものは決まっています——学習曲線が −498 から上がり、+28 を超えるか。 超えれば強化学習が人の設計した制御器に並んだということです。

先に考えておいてください—— 学習がうまくいかなかったとき、何から疑いますか。 Step 6 で見た落とし穴を思い出して、チェックする順番を決めておいてください。
