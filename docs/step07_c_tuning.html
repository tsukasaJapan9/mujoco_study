01

宿題の答え合わせ

この節のねらい

宿題の後半——「まだ伸びる余地があるか」を指標のどれで判断するか——に答えます。 ここが今回いちばん実用的な部分です。

宿題

7-a で 30 万ステップでは届きませんでした。単にステップ数を 3 倍にしたらどうなると思いますか。 そしてそれを試す前に、指標のどれを見れば「まだ伸びる余地があるか」が分かるでしょうか。

答え：3 つの指標が「まだ伸びる」と言っていました。

指標30 万時点読み方
ep_rew_mean−222.9 で上昇中 グラフの右端が上を向いている＝まだ登っている途中
std0.602 で下降中 探索が生きている＝方策がまだ変化する余地がある
explained_variance0.994 Critic は完成している＝更新方向は信用できる

3 つが揃って初めて「増やせば伸びる」と言えます 報酬が上昇中でも、std が 0.05 まで落ちていたら 探索をやめているので、そこから先は伸びません（§05 の「早すぎる収束」）。 explained_variance が 0.2 なら、 更新方向が信用できないので、増やしても迷走するだけです。

そして実際そのとおりでした

100 万ステップまで伸ばすと 報酬 +24.55 / 上端 207.5。 古典制御（+28.31 / 216.2）にほぼ並びます。 何も調整していません。ステップ数を 3.3 倍にしただけです。

なぜこれを先に確認するのか

ハイパーパラメータの調整は組み合わせが無限にあります。 「学習量が足りないだけ」の状態で調整を始めると、 何を変えても少し良くなるので、 効いたのがその変更なのか偶然なのか判断できません。

7-a のチェックリストで6 番が 7 番より先なのは、この順序でしか切り分けられないからです。

02

ハイパーパラメータの地図

この節のねらい

PPO には 20 以上の引数がありますが、最初に触るのは 5 つだけです。 7-b の指標と 1 対 1 で対応させます。

パラメータ既定値何を決めるか触る根拠になる指標
learning_rate3e-41 回の更新の大きさ approx_kl が大きすぎ／小さすぎ
ent_coef0.0探索を続ける圧力 std が早く落ちきる
n_steps20481 回の更新に使うデータ量 explained_variance が低い
batch_size64勾配 1 回あたりのサンプル数 学習が不安定
gamma0.99どこまで先を見るか ——（5-b の実効地平で決める）

gamma だけ性質が違います 他の 4 つは学習のやり方の設定ですが、 gamma は何を最適化するかそのものを変えます。 5-b で計算したとおり γ=0.99 の実効地平は 100 ステップ＝1 秒。 スイングアップに 2.89 秒かかることを思うと、 γ を上げる（0.995 など）ほうが理屈に合います。 ただし上げると学習は不安定になります——遠い未来まで見るぶん、価値の分散が増えるので。

動かし方の作法
  • 1 度に 1 つだけ変える。2 つ変えるとどちらが効いたか分かりません （Step 3 の課題 1 で「1 変数だけを振る」と書いたのと同じ）
  • 2〜3 倍単位で動かす。3e-4 → 1e-3 のように。 10% の調整には意味がありません
  • 必ず複数シードで比べる。次回 7-d の主題ですが、 1 シードの差は偶然かもしれません
03

VecNormalize — 定番が効かない実例

この節のねらい

VecNormalize は連続制御の定番として、多くの解説で「まず入れろ」と書かれています。 この環境では効きません。 なぜ効かないのかを考えることが、他人の設定をそのまま使う危うさの教材になります。

何をするものか

環境を包んで、観測と報酬を「平均 0・標準偏差 1」に揃え続けるラッパーです。 学習中の値を使って平均と分散を推定し、随時更新します。

from stable_baselines3.common.vec_env import VecNormalize

venv = make_vec_env(make_env, n_envs=4, seed=0)
venv = VecNormalize(venv, norm_obs=True, norm_reward=True)

なぜ一般に効くとされるのか ニューラルネットは入力の桁が揃っているときに学習しやすいからです。 関節角が ±3、角速度が ±50、 力センサが ±500 のように桁がばらばらの観測を そのまま入れると、大きい成分に引きずられます。 多関節ロボットではこれが普通に起きるので、定番になっています。

3 シードで測った結果

seed 0seed 1seed 2平均上端滞在
既定値−227.51−299.10−236.45 −254.3546.2
VecNormalize あり−345.05−334.32−215.36 −298.2445.2

平均で 44 ポイント悪化しています 各シードはばらつきますが（seed 2 だけは正規化ありのほうが良い）、 平均では明確に負けています。 1 シードだけ見ていたら、seed 2 を引いた人は 「VecNormalize は効く」と結論したでしょう。

なぜこの環境では効かないのか

6-a で観測を設計したときのことを思い出してください。

観測の要素実際に取る範囲正規化で改善するか
cosθ±1すでに揃っている
sinθ±1すでに揃っている
ω±11（実測）10 倍程度の差しかない
報酬±1 程度すでに揃っている

揃えるべきものが、もともと揃っていました 6-a で角度を cos と sin に変換した時点で、 観測の 2/3 は ±1 に収まっています。 角速度だけ 10 倍ほど大きいですが、それは桁違いというほどではありません。 得るものが小さいのに、正規化には固有のコストがあります——次の段落。

報酬の正規化には副作用があります

norm_reward=True は報酬を動く標準偏差で割ります。 学習が進むと報酬の分布が変わるので、割る数も変わり続けます。 つまり同じ状態の価値が、学習の段階によって違う数字になります。

7-b で見たとおり、この環境の explained_variance は既に 0.994 でした。 Critic が完璧に当てている状態で、目標を動かす理由はありません。

持ち帰ってほしい判断基準

「観測の各成分の桁が揃っているか」を先に確かめる。 6-d の §05 でやったように、 うまくいく方策で回して実測範囲を取るのが確実です。

揃っていなければ VecNormalize は効きます。 揃っているなら入れる理由がありません。 「定番だから」で入れるのが、いちばん判断を放棄した使い方です。

なお norm_obs と norm_reward は別々に指定できます。 観測だけ正規化して報酬は生のまま、という選択も可能です。

評価するときの落とし穴

VecNormalize を使うと、評価時にも同じ正規化を通す必要があります。 生の観測を学習済み方策に渡すと、ネットが見たことのない桁の入力になり、 性能が出ません。

venv.training = False        # 統計の更新を止める
venv.norm_reward = False     # 報酬は生で測る
obs_norm = venv.normalize_obs(obs)
action, _ = model.predict(obs_norm, deterministic=True)

さらに統計そのものを保存・復元する必要があります （venv.save() / VecNormalize.load()）。 モデルだけ保存して統計を忘れると、読み込んだ方策は動きません。 これも「入れるコスト」の一部です。

04

実測で比べる

この節のねらい

§02 の地図で挙げたパラメータを、実際に振った結果を並べます。 すべて 30 万ステップ × 3 シード。比べ方そのものが今回の学習内容です。

設定seed 0seed 1seed 2 平均ばらつき幅上端滞在
既定値−227.51−299.10−236.45 −254.3571.646.2
VecNormalize あり−345.05−334.32−215.36 −298.24129.745.2
lr=1e-3−358.67−113.62−122.19 −198.16245.177.5
ent_coef=0.01−227.49−299.07−224.58 −250.3874.545.3

ばらつき幅の列を必ず見てください lr=1e-3 は平均で 56 ポイント改善し、 上端滞在も 46.2 → 77.5 と 1.7 倍になりました。 7-b で approx_kl が 0.002〜0.008 と 健全範囲（0.005〜0.02）の下寄りだったので、 学習率を上げる余地があると読んだとおりです。

しかし、ばらつきが 3.4 倍になっています 71.6 → 245.1。seed 0 だけが −358.67 と大きく外れています。 平均は良くなったが、当たり外れが大きくなった—— 実務で頻繁に遭遇する形です。

ent_coef は「効かない」ことが予測できていました

ent_coef=0.01 は平均 −250.38。 既定値の −254.35 とほぼ同じで、 ばらつき幅も 74.5 対 71.6 と変わりません。

7-b の指標から予測できていました ent_coef は §02 の地図で 「std が早く落ちきる」ときに触るものでした。 7-b の実測では 30 万ステップ時点で std = 0.602、 まだ下降中で、探索は十分生きていました。 探索が足りていないという症状が無いのに探索の薬を出しても、効くはずがありません。

これが「指標を根拠に選ぶ」ということです

3 つのパラメータを闇雲に試せば、3 回とも 2 分ずつ × 3 シード＝18 分かかります。 7-b の指標を読んでいれば、ent_coef は試すまでもないと分かり、 learning_rate だけに絞れました。

パラメータが 20 個ある中で全部試すのは不可能です。 指標は「試す価値のある 1〜2 個」に絞り込むための道具です。

1 シードだけ見ていたら、どんな結論になっていたか
もし引いたのが出る結論
lr=1e-3 の seed 1「学習率を上げると劇的に改善する」
lr=1e-3 の seed 0「学習率を上げると悪化する」
VecNormalize の seed 2「VecNormalize は効く」

同じ実験から、正反対の結論が引けます。 これが「1 シードの結果を信じない」の意味で、次回 7-d の主題です。

で、結局どうすればいいのか

やったこと報酬かかった時間
既定値・30 万ステップ−254.35約 2 分
lr=1e-3・30 万ステップ−198.16約 2 分
既定値・100 万ステップ+24.55約 19 分
古典制御（基準線）+28.31——

調整より、ステップ数のほうが圧倒的に効きました lr の調整で稼げたのは 56 ポイント。 ステップ数を 3.3 倍にして稼げたのは 279 ポイントです。 桁が違います。

これが 7-a のチェックリストの順番の意味です 6 番（学習量）が 7 番（ハイパーパラメータ）より先なのは、 効果が大きく、判断が簡単だから。 学習量が足りない状態で調整を始めると、 何を変えても少し良くなるので、効いたのが何なのか分かりません。

両方やればもっと良いのでは

そのとおりで、lr=1e-3 で 100 万ステップ回せば 既定値より速く到達する可能性があります。 ただしばらつきも大きいので、何シードか回して確かめる必要があります。

時間があるなら試してみてください。7-d の課題で扱います。

05 · 課題

手を動かす

この課題のねらい

なぜこの課題をやるのか 自分の環境で「調整より学習量」を確かめるため。 教材の表を読むのと、自分の実験で 100 万ステップが調整を上回るのを見るのとでは違います。

やり終えたとき言えること ——パラメータを触る前に、まずステップ数を疑える。 そして1 シードの結果で判断しなくなる。

進め方

穴埋めは 段階 2 の 1 箇所だけです。 段階 3 は 19 分かかるので、走らせている間に 7-d を読み始めて構いません。

段階 1

設定を引数で切り替えられるようにする

この段階ですること 実験のたびにファイルを書き換えるのをやめます。 何を変えたかがコマンドに残るので、あとで追えます。

import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--steps", type=int, default=300_000)
parser.add_argument("--lr", type=float, default=3e-4)
parser.add_argument("--seed", type=int, default=0)
parser.add_argument("--tag", default="ppo")
args = parser.parse_args()

venv = make_vec_env(make_env, n_envs=4, seed=args.seed)   # ← ここも忘れずに

model = PPO("MlpPolicy", venv, verbose=1, seed=args.seed, device="cpu",
            learning_rate=args.lr, tensorboard_log="tb_logs")
model.learn(total_timesteps=args.steps, tb_log_name=args.tag)
model.save(f"train/ppo_{args.tag}_s{args.seed}")
seed は 2 箇所に書きます

PPO(seed=...) だけ変えて make_vec_env(seed=0) を そのままにしても、実は結果は変わります—— SB3 は初期化時に環境の seed も設定し直すので、 make_vec_env 側の指定が上書きされるからです（実測で確認）。

それでも両方に書いてください。理由は 3 つ。

  • コードが嘘をつく。seed=0 と書いてあれば読み手は 「環境は 0 で固定」と理解しますが、実際は上書きされています
  • SB3 の内部動作に依存している。API として保証されたものではなく、 バージョンが変われば挙動が変わりえます
  • ラッパーを挟むと話が変わる。VecNormalize のように 環境を包むと、seed の伝わり方が変わる可能性があります

確認方法 既定値のまま実行して 7-b と同じ動きをすれば OK です。

uv run python -m train.train_ppo --steps 10000 --tag smoke

保存名にも設定を入れています ppo_smoke_s0.zip のようになります。 ファイル名を見れば何の実験か分かるようにしておくと、 2 週間後の自分が助かります。

段階 2

学習率を上げて 3 シード回す

この段階ですること §04 の lr=1e-3 の行を再現します。

for seed in 0 1 2; do
  uv run python -m train.train_ppo --lr ??? --seed $seed --tag lr1e-3
done

§02 の作法「2〜3 倍単位で動かす」に従うと、 既定の 3e-4 からいくつにすべきでしょうか。

答えと解説を見る
  uv run python -m train.train_ppo --lr 1e-3 --seed $seed --tag lr1e-3

3e-4 → 1e-3 は約 3.3 倍 5e-4（1.7 倍）でも構いませんが、差が出にくくなります。 3e-3（10 倍）まで行くと approx_kl が跳ね上がって壊れる可能性が高い。 7-b で読んだ approx_kl = 0.002〜0.008 が 健全範囲の下寄りだった、という根拠があるから 3 倍を選べます。

学習後に approx_kl を必ず確認してください 0.02 を超えていたら上げすぎです。 「報酬が良くなったからOK」ではなく、指標で裏を取るのが 7-b を学んだ意味です。

確認方法 3 シードの平均が −200 前後、 ただし1 つは大きく外れるはずです。§04 の表と見比べてください。

段階 3

既定値のまま 100 万ステップ回す

この段階ですること 今回の結論を自分で確かめます。 19 分かかります。

uv run python -m train.train_ppo --steps 1000000 --tag long

確認方法 学習後に evaluate() で採点すると、 報酬 +20 前後、上端滞在 200 前後になります。 古典制御（+28.31 / 216.2）にほぼ並びます。

TensorBoard で 30 万と重ねて見てください tb_log_name を変えてあるので、同じグラフに 2 本並びます。 30 万で切ったときにどこにいたのかが一目で分かります。

上端滞在 207 が上限に近い理由

Step 4 で測ったスイングアップ所要時間は 2.89 秒。 100Hz なら 289 ステップです。500 − 289 = 211。 PPO の 207.5 は、物理的な上限にほぼ達しています。 ここから先はスイングアップ自体を速くするしかありません。

06

まとめ

今回で分かったこと
  1. 調整より学習量のほうが圧倒的に効いた。 lr 調整で 56 ポイント、ステップ数 3.3 倍で 279 ポイント
  2. VecNormalize はこの環境では悪化させた（−254 → −298）。 6-a で cos/sin にした時点で観測が揃っていたから
  3. lr=1e-3 は平均を改善したが、ばらつきが 3.4 倍になった
  4. ent_coef は効かないと事前に予測できた。 7-b で std = 0.602 と探索が生きていたから。 指標は「試す価値のある 1〜2 個」に絞り込む道具
  5. 触るパラメータは指標が根拠を出してから選ぶ。 approx_kl が小さめ → learning_rate、という対応
  6. 1 シードの結果からは正反対の結論が引ける。同じ実験でも
次回（7-d）でやること

Step 7 の最終回です。今回何度も「1 シードでは判断できない」と書きました。 では何シード回せばいいのか、 どう比べれば「本当に良くなった」と言えるのかを扱います。

そして Step 7 の完了条件——古典制御との比較——をきちんと締めます。

先に考えておいてください—— §04 の表で lr=1e-3 は平均 −198、既定値は −254 でした。 この 56 ポイントの差は「本物」でしょうか。 ばらつき幅が 245 あることを踏まえて考えてみてください。
