  2. ただし lr=1e-3 はばらつき幅が 245。seed 0 だけ大きく外れた

この教材が答える問い

今回の進め方。 宿題の答えは「言えない」です。まずそれを数字で示します。 そのうえで何シード必要なのか、 比較のとき何を固定すべきかを決め、 最後に Step 7 の完了条件——古典制御との比較——を締めます。

今回は強化学習に固有の話ではありません

「差が本物か」を判断する作業は、実験科学一般の話です。 ただし強化学習は乱数の影響が異常に大きいので、 他の分野より厳しく扱う必要があります。 同じコード・同じ設定で、シードを変えるだけで結果が倍違う—— それが普通に起きる分野です。

01

宿題の答え合わせ

この節のねらい

「56 ポイントの差は本物か」に答えます。 答えは「本物とは言えない」。その判断の仕方を身につけます。

宿題

§04 の表で lr=1e-3 は平均 −198、既定値は −254 でした。 この 56 ポイントの差は「本物」でしょうか。 ばらつき幅が 245 あることを踏まえて考えてみてください。

答え：本物とは言えません。数字で確かめます。

設定平均標準偏差標準誤差95% の目安
既定値−254.3539.0122.52±63
lr=1e-3−198.16139.0780.29±223

誤差範囲が差より大きいのです lr=1e-3 の真の平均は −198 ± 223、 つまり −421 から +25 のどこかとしか言えません。 既定値の −254 ± 63 と完全に重なっています。

検定の形で書くと

差            = +56.19
差の標準誤差   =  83.39
t             =   0.67        # 有意と言うには 2.78 以上が必要（自由度 4）

t = 0.67 は「差が無い」と言われても反論できない水準です。 56 ポイントという数字自体は正しいのですが、 それが設定の差によるものか、乱数の綾かを区別できていません。

では何シード必要だったのか

この差（56）とばらつき（標準偏差 104 程度）で検出するのに必要なシード数を計算しました。

シード数検出できる最小の差56 の差を検出できるか
3169.8できない
5131.6できない
1093.0できない
2065.8できない
5041.6できる

50 シード必要です。1 本 2 分として 100 分 × 2 条件。 この差を確かめるだけで 3 時間以上かかります。

これが強化学習の実験の現実です 小さな差を証明するのは、非常に高くつきます。 論文で「3 シードの平均」という書き方をよく見ますが、 3 シードで言えるのは「大きな差がある」ことだけです。 数十ポイントの違いを語るには足りません。

02

何シード回せばいいのか

この節のねらい

§01 の結論は「50 シード必要」でしたが、現実には回せません。 では実務でどうするのか。諦め方を含めた判断基準を持ちます。

シード数言えること使いどころ
1何も言えない動くかどうかの確認だけ
3大きな差（100 以上）なら言える普段の実験。最低ライン
5〜10中くらいの差なら言える重要な判断のとき
20 以上小さな差も言える論文、最終決定
実務的な判断基準

3 シードで差がはっきりしないなら、その変更は採用しない。

理由は単純で、3 シードで見えない程度の差は、実用上どうでもいいからです。 同じ時間を「学習量を増やす」に使ったほうが確実に効きます—— 7-c で見たとおり、ステップ数は 279 ポイント稼ぎました。 あちらは 3 シードどころか 1 シードでも明らかな差です。

差の大きさで扱いを変えます 「効くものは、少ないシードでも明らかに効く」。 逆に言えば、何シードも回して初めて見える差は、追う価値が低い。 限られた計算時間を何に使うかの判断として、これは合理的です。

シードを固定することと、複数回すことは別の話です

seed=0 を指定するのは再現性のため—— 同じコードを走らせたら同じ結果が出るように。

複数シードを回すのは一般化のため—— たまたまうまくいっただけでないことを確かめるために。

両方必要です。「seed を固定したから大丈夫」は、 再現性の話を一般化の話とすり替えています。

03

評価プロトコルを固める

この節のねらい

シード数の話とは別に、1 回の評価をどう測るかにも決めごとが要ります。 測り方が揺れていると、シードを増やしても意味がありません。

Step 6 以降、実は少しずつ決めてきました。まとめます。

決めること今回の設定決めた場所揺れると何が起きるか
エピソード数106-d少ないと運の影響が残る
1 エピソードの長さ500 ステップ6-c長いほど上端滞在が稼げる
初期状態の乱数seed=ep（0〜9）6-d固定しないと毎回違う条件
行動空間の乱数seed=ep6-dランダム方策の結果が揺れる
探索切る（deterministic=True）7-a実力より低く出る
報酬生の値7-c正規化すると基準線と比較不能

すべて「比較可能にするため」の決めごとです どれも単独では性能を変えません。 変えるのは比較できるかどうかです。 測り方が違う 2 つの数字を並べても意味がありません。

いちばん間違えやすいのは評価エピソード数です

10 エピソードの平均は、それ自体がばらつきます。 同じ方策を別の 10 エピソードで測れば違う値が出ます。

つまりばらつきが 2 段階あります。

  • 学習のばらつき（シードごとに方策が違う）← §01 で扱ったもの
  • 評価のばらつき（同じ方策でも測るたびに違う）← こちら

評価エピソードを増やせば後者は減りますが、前者は減りません。 評価を 100 エピソードにしても、1 シードは 1 シードのままです。

評価用の関数は 1 つに固定する

6-d で書いた evaluate() を、 ランダム方策・古典制御・学習した方策のすべてに同じものを使ってきました。 これが効いています——3 つの数字が同じ土俵の上にあります。

train/eval.py として切り出し、 他のファイルから import する形にしておくことを勧めます。 コピーして少し変えたものが増えると、比較できない数字が混ざります。

「RL が勝った」という話ではありません 1 自由度の振り子では、古典制御のほうが圧倒的に安上がりです。 2.89 秒で解く式を、19 分の計算で再発見しただけとも言えます。

だから Phase A をやりました

古典制御の基準線が無ければ、+24.55 という数字を評価できませんでした。 「まあまあ良さそう」で終わっていたはずです。

そして物理的な上限 211 を計算できたのも Phase A のおかげです。 「これ以上は伸びない」と分かることは、「まだ伸びる」と分かることと同じくらい重要です—— 伸びない場所にステップ数を注ぎ込まずに済みます。

05 · 課題

手を動かす

この課題のねらい

なぜこの課題をやるのか 「差が本物か」を自分で判定できるようにするため。 平均を並べるだけなら誰でもできますが、 ばらつきを見て「まだ言えない」と判断するほうが難しい。

やり終えたとき言えること ——実験結果を見せられたとき、シード数とばらつきを最初に確認するようになる。 これは論文を読むときにも効きます。

進め方

穴埋めは 段階 2 の 1 箇所だけです。 段階 1 は評価コードの整理、段階 3 は時間があるときにで構いません。

段階 1

評価コードを 1 箇所にまとめる

この段階ですること try_env.py に書いた evaluate() を train/eval.py に移し、どこからでも import できるようにします。

# train/eval.py
import numpy as np
from gymnasium.wrappers import TimeLimit

from envs.pendulum_env import PendulumEnv


def evaluate(policy, n_ep=10, steps=500):
    """方策を採点する。すべての比較でこの関数だけを使うこと。"""
    totals, ups = [], []
    for ep in range(n_ep):
        env = TimeLimit(PendulumEnv(), max_episode_steps=steps)
        obs, info = env.reset(seed=ep)
        env.action_space.seed(ep)
        total, up = 0.0, 0
        for t in range(steps):
            obs, reward, terminated, truncated, info = env.step(policy(env, obs))
            total += reward
            if -np.cos(env.unwrapped.data.qpos[0]) > 0.95:
                up += 1
            if terminated or truncated:
                break
        totals.append(total)
        ups.append(up)
    return np.mean(totals), np.mean(ups)

docstring に「この関数だけを使うこと」と書いておく 2 週間後の自分は、手元でちょっと変えたコピーを作りがちです。 そうすると比較できない数字が混ざります。 §03 で決めた 6 つの設定は、この関数の中にしか無いようにしておきます。

確認方法 try_env.py から import して、 古典制御が 28.31 / 216.2 と出れば移行成功です。

段階 2

複数シードの結果を統計として出す

この段階ですること 平均だけでなくばらつきも出します。 これが無いと §01 の判断ができません。

import numpy as np


def summarize(label, scores):
    scores = np.array(scores)
    mean = scores.mean()
    sd = scores.std(ddof=1)               # 標本標準偏差
    se = ???                              # ← ここだけ考える
    print(f"{label:<12} 平均={mean:8.2f}  標準偏差={sd:7.2f}  "
          f"標準誤差={se:6.2f}  幅={scores.max()-scores.min():7.2f}")
    return mean, se

標準誤差（standard error）は「平均そのもののばらつき」です。 標準偏差をシード数で調整すると出ます。 §01 の表で、既定値は 標準偏差 39.01 に対して 標準誤差 22.52 でした。 3 シードのとき、どういう計算をすればこうなるでしょうか。

答えと解説を見る
    se = sd / np.sqrt(len(scores))

検算 39.01 / sqrt(3) = 22.52。一致します。

標準偏差と標準誤差は別物です 標準偏差＝個々のシードがどれだけばらつくか。 シードを増やしても減りません（そういう性質の量なので）。
標準誤差＝平均がどれだけ信用できないか。 シードを増やすと 1/√n で減ります。

だから「シードを増やす」意味があります 個々の学習のばらつきは変わりませんが、 平均の精度は上がる。§01 の「50 シード必要」はこの計算から出ています。

確認方法 7-c で取った 3 シードの結果を入れて、§01 の表と一致するか確かめます。

summarize("既定値",  [-227.51, -299.10, -236.45])
summarize("lr=1e-3", [-358.67, -113.62, -122.19])

既定値        平均= -254.35  標準偏差=  39.01  標準誤差= 22.52  幅=  71.59
lr=1e-3      平均= -198.16  標準偏差= 139.07  標準誤差= 80.29  幅= 245.05

この 2 行を見て判断してください lr=1e-3 の標準誤差が 80.29。 差の 56.19 より大きい。 これだけで「まだ言えない」と分かります。 検定の計算をしなくても、標準誤差と差を見比べるだけで判断できます。

段階 3 · 時間があるとき

シードを増やして結論が変わるか見る

この段階ですること §01 の「3 シードでは足りない」を、 実際にシードを増やして確かめます。1 本 2 分 × 10 本で 20 分。

for seed in 3 4 5 6 7; do
  uv run python -m train.train_ppo --seed $seed --tag base
  uv run python -m train.train_ppo --lr 1e-3 --seed $seed --tag lr1e-3
done

8 シードぶんの結果を summarize() に入れて、 標準誤差がどれだけ減ったかを見てください。

予想を立ててから実行すること 3 → 8 シードで標準誤差は √(3/8) = 0.61 倍になるはずです。 80.29 × 0.61 = 49 前後。 差の 56 より小さくなるので、ぎりぎり「差がありそう」と言える水準に届きます。

ただし平均自体も動きます 新しい 5 シードが良い方に出るか悪い方に出るかで、差そのものが変わります。 「標準誤差が下がる」ことと「差が有意になる」ことは別です。 結論が変わる可能性も含めて、それが実験というものです。
