GAE — アドバンテージの作り方

「1 歩先まで見る」と「最後まで見る」の間を、 つまみ 1 つで連続的に選ぶ。それが GAE。

00

前回までと、今回の問い

前回までで分かっていること
  1. アドバンテージの 1 歩先推定は A ≈ r + γV(s') − V(s)。 5-e の TD 誤差そのもの
  2. ただし実際の報酬を 1 個しか使っていない。残りは全部 V の予想頼み
  3. PPO の 5 部品のうち、今回は部品 3（アドバンテージ計算）
この教材が答える問い

1. 何歩先まで実際の報酬を使うべきか。多いほど良いのか？

2. λ というつまみは、何を調整しているのか？

今回の進め方。 宿題の答えから始めて、「n 歩先まで使う」という考え方を作ります。 そのあと n を 1 つに決めないという発想で GAE に到達します。 小さな具体例の数字を最後まで追いかけます。

01

宿題の答え合わせ

この節のねらい

宿題は「2 歩先まで使うとどうなるか」「最後まで使うと何と同じか」でした。 どちらも、もう知っているものに行き着きます。

宿題

A ≈ r + γV(s') − V(s) は 1 歩先まで実際の報酬を使いました。 2 歩先まで使うとどういう式になるでしょうか。 そして最後まで使ったら、それは何と同じになるでしょうか。

答え 1: 2 歩先まで使う

1 歩先の式で V(s') を使っていた部分を、もう 1 歩ぶん実際の値で置き換えます。

1 歩: A = r₁ + γV(s₁)                        - V(s₀)
2 歩: A = r₁ + γr₂ + γ²V(s₂)                - V(s₀)
3 歩: A = r₁ + γr₂ + γ²r₃ + γ³V(s₃)        - V(s₀)

実際の報酬が 1 個ずつ増え、V が後ろにずれていきます 予想に頼る割合が減っていくわけです。

答え 2: 最後まで使う

最後まで: A = r₁ + γr₂ + γ²r₃ + ... + γⁿ⁻¹rₙ  - V(s₀)
              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
              これは 5-b の収益 G そのもの

V が完全に消えます 残るのは G − V(s₀)——実際にもらった収益と、予想の差。 5-c でモンテカルロと呼んだ測り方です。

何歩先まで使うか予想（V）への依存5-c の言葉では
1 歩強い。V が外れると全部外れるTD
n 歩中間——
最後までなし。実測だけモンテカルロ
02

どこまで実際の報酬を使うか

この節のねらい

「最後まで使えばいい」と思えますが、そうではありません。 5-c と 5-d で見たトレードオフが、ここでも出てきます。

1 歩だけ使う最後まで使う
正しさ（偏り）V が外れると偏る偏らない
ばらつき（分散）小さい大きい
いつ使えるか1 歩ごとエピソードが終わってから

ばらつきが大きいのはなぜか 最後まで使うと、途中で起きた偶然が全部混ざります。 5-c でモンテカルロの誤差を測ったとき、 試行回数を 1000 倍にしても誤差が 1/80 にしかならなかったのを思い出してください。

偏るのはなぜか 1 歩しか使わないと、残りは全部 V の予想です。 学習途中の V は外れている（8-a の実測トレース）ので、 その誤差をまるごと引き継ぎます。

これは 5-c と 5-d の対立の再演です

モンテカルロ（歩いて測る、正確だが遅い・ぶれる）と ベルマン（予想を使う、速いが予想次第）—— Step 5 で 2 本の教材をかけて対比したものが、 ここでは連続的に選べるつまみになります。

ではどの n を選ぶのか

選びません。GAE の発想はここです—— 全部の n を計算して、重みを付けて混ぜます。

03

GAE — 全部を混ぜる

この節のねらい

GAE（Generalized Advantage Estimation）の式を出します。 見た目より単純で、実装は 5-b で書いた G() とほぼ同じ形です。

まず記号を 1 つ決めます。1 歩ぶんの TD 誤差を δ（デルタ）と書きます。

δₜ = rₜ + γV(sₜ₊₁) - V(sₜ)

すると GAE はこう書けます。

Aₜ = δₜ + (γλ)δₜ₊₁ + (γλ)²δₜ₊₂ + (γλ)³δₜ₊₃ + ...

この形、見覚えがあるはずです 5-b の収益 G = r₁ + γr₂ + γ²r₃ + ... と同じ形です。 違うのは足すものが報酬ではなく δ、 割引が γ ではなく γλ という点だけ。

だから実装も 5-b と同じです

5-b で「後ろから畳む」書き方を学びました。GAE もまったく同じです。

# 5-b の収益
g = 0.0
for r in reversed(rewards):
    g = r + gamma * g

# GAE のアドバンテージ
a = 0.0
for delta in reversed(deltas):
    a = delta + gamma * lam * a

掛ける数が gamma から gamma * lam に変わっただけです。

05

エピソードの切れ目

この節のねらい

実装でいちばん間違えやすい箇所です。 6-c の terminated / truncated がここで効いてきます。

まず前提: バッファには複数のエピソードが入っています

n_steps=8192 ぶん集めますが、エピソードは 500 歩で切れます。 つまりバッファの中身はこうなっています。

バッファ（1 本の配列）
[ エピソード1 ][ エピソード2 ][ エピソード3 ] ...
  ↑リセット    ↑リセット     ↑リセット

別々の試行が、ただ並べて詰め込まれているだけです エピソード 2 は env.reset() した別の世界で、 エピソード 1 とは何の因果関係もありません。

ところが GAE は配列を後ろから畳んでいくので、 放っておくとこの境界を平気で越えます。

実例: 6 歩のバッファ（3 歩ずつ 2 エピソード）

エピソード 1 では何も起きていないのに、高いアドバンテージが付いています アドバンテージは「その行動は平均よりどれだけ良かったか」でした。 誤ったほうではエピソード 1 の行動が「良かった」と学習されます—— 良いことが起きたのはリセット後の別の試行なのに。

§04 の「ニュースが遡る」で言うと

λ は「良いことが起きたとき、その手柄を何歩前まで配るか」を決めていました。 切れ目を止めないと、その配布が別のエピソードまで届いてしまいます。

別の世界のニュースが、こちらの世界に遡ってきて、無関係な行動を褒めている—— そういう状態です。

a = 0.0
for t in reversed(range(T)):
    delta = r[t] + gamma * next_value[t] - V[t]
    a = delta + gamma * lam * (1 - end[t]) * a     # end なら畳み込みを打ち切る
    adv[t] = a

end[t] は終端でも打ち切りでも 1 にします。 どちらもそこでエピソードが切れているので、 次のエピソードの δ を混ぜてはいけません。

ところが next_value の扱いは 2 つで違います
next_valueend
terminated（タスクとして終了）01
truncated（打ち切り）V(最後の観測)1
継続中V(次の観測)0

6-c で「打ち切りでは未来の価値を足す」と学んだのがこれです。 畳み込みは止めるが、その 1 歩ぶんの未来の価値は足す—— 2 つを別々に扱う必要があります。

打ち切り時の観測を取っておく必要があります

打ち切ると env.reset() して新しい観測に切り替わります。 その前に、打ち切り時点の観測で V を計算しておく必要があります。

ここを忘れると、次のエピソードの最初の状態の価値を使ってしまいます。 エラーは出ません。アドバンテージが静かに狂うだけです。

段階 1

GAE を書く

この段階ですること §03 の「後ろから畳む」をコードにします。 5-b の G() と見比べながら書いてください。

import numpy as np


def gae(rewards, values, next_values, ends, gamma=0.99, lam=0.95):
  """後ろから畳んでアドバンテージを作る

  next_values[t] : そのステップの「次の状態の価値」
                   終端なら 0、打ち切りなら打ち切り時点の観測の価値
  ends[t]        : エピソードがそこで切れたか（終端でも打ち切りでも 1）
  """
  T = len(rewards)
  adv = np.zeros(T, dtype=np.float32)
  running = 0.0
  for t in reversed(range(T)):
    delta = rewards[t] + gamma * next_values[t] - values[t]
    running = ???                       # ← ここだけ考える
    adv[t] = running
  return adv

§03 の畳み込みに、§05 の「エピソードの切れ目で止める」を足した 1 行です。 使える変数は delta, gamma, lam, ends[t], running。

答えと解説を見る
    running = delta + gamma * lam * (1.0 - ends[t]) * running

3 つの部品でできています delta（今のステップの TD 誤差）、 gamma * lam（§03 の割引）、 (1.0 - ends[t])（切れ目なら 0 を掛けて畳み込みを断つ）。

5-b の G() と並べると

g = r + gamma * g                              # 5-b の収益
a = delta + gamma * lam * (1 - end) * a        # GAE

足すものが r から delta に、 割引が gamma から gamma*lam に変わり、 切れ目を断つ項が増えただけです。

確認方法 §04 の例で検算します。

段階 2

両端が既知のものと一致することを確かめる

この段階ですること λ=0 と λ=1 が、 それぞれ TD 誤差とモンテカルロに一致することを検算します。 これが GAE を理解した証拠になります。

G = np.zeros(5); acc = 0.0
for t in reversed(range(5)):

    G[t] = acc
print("G - V      :", np.round(G - V, 4))

段階 3

エピソードの切れ目で止まることを確かめる

この段階ですること §05 の話を検算します。 切れ目を無視するとどうなるかを見ておきます。

# 3 ステップ目でエピソードが切れる場合
E2 = np.array([0.0, 0.0, 1.0, 0.0, 1.0])

print("切れ目あり:", np.round(gae(r, V, NV, E2, 0.99, 0.95), 4))
print("切れ目なし:", np.round(gae(r, V, NV, np.zeros(5), 0.99, 0.95), 4))

先に予想してください t=0,1,2 の値はどちらが大きくなるでしょうか。

答えと解説を見る

切れ目なしのほうが大きくなります。 t=2 で切れているのに畳み込みを続けると、 次のエピソードの δ が混ざって上乗せされるからです。

これが「静かに壊れる」パターンです アドバンテージが実際より大きく見積もられ、 方策が「この行動は良かった」と誤って学習します。 エラーは出ません。学習が少し下手になるだけです。

実際のデータではもっと深刻です 今回は 5 ステップの例なので影響が小さく見えますが、 実際は n_steps=2048 の中にエピソードが 4 個ほど入ります。 切れ目を無視すると、全部が繋がった 1 本の軌跡として扱われます。

07

まとめ

今回で分かったこと
  1. アドバンテージは何歩先まで実際の報酬を使うかで作り方が変わる。 1 歩なら TD、最後までならモンテカルロ
  2. どちらにも欠点がある。 1 歩は V の誤差を引き継ぎ、最後まではばらつきが大きい
  3. GAE は全部を重み付きで混ぜる。重みが (γλ) の累乗
  4. 実装は5-b の G() とほぼ同じ。 足すものが δ、割引が γλ になっただけ
  5. λ=0 は TD 誤差そのもの、λ=1 はモンテカルロ（実測で確認）
  6. γ と λ は役割が違う。 γ は何を最適化するか、λ はそれをどう推定するか
