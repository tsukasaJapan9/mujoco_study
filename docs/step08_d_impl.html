01

宿題の答え合わせ

この節のねらい

宿題は「環境 1 つでも同じ結果になるか」でした。 答えは「ならない」で、しかもその差は非常に大きいです。

宿題

7-a では環境を 4 つ並べました（n_envs=4）。 自作実装では環境 1 つで書きます。 同じ総ステップ数なら、結果は同じになるでしょうか。

答え：なりません。同じにするには n_steps を調整する必要があります。

7-a の設定を思い出してください。n_envs=4、n_steps=2048。 SB3 の n_steps は環境 1 つあたりなので、 1 回の更新に使うデータは 4 × 2048 = 8192 です。

1 更新あたりのデータ20 万ステップでの更新回数
SB3（4 環境 × 2048）819224 回
自作（1 環境 × 2048）204897 回

実測: これだけで結果が変わります

n_steps20 万ステップ後の報酬上端滞在最終 std
2048−473.030.0 / 5000.385
8192−225.8664.5 / 5000.627

2048 では局所解にはまりました 診断を見ると approx_kl が 0.0001 まで落ち、 std が 0.385 まで縮んでいました。 更新が止まり、探索も死んでいる状態です。

データが少ないまま何度も更新すると、そのデータに過剰に合わせます 結果としてエントロピーが早く落ち、探索をやめてしまいます。 8-c で見たとおり PPO は同じデータを 10 エポック使い回すので、 データが少ないとその影響が強く出ます。

7-b で読んだ指標がそのまま診断に使えます

approx_kl が小さすぎる、std が早く落ちる—— 7-b で学んだ読み方が、自作実装のデバッグでもそのまま効きます。 「式は合っているのに学習しない」を切り分けられたのは、指標があったからです。

2 箇所だけ注意が要ります

① torch.no_grad() で囲む
収集中は学習しないので勾配が不要です。 これが 8-a で触れた「明示的な detach が要らない」理由—— ここで作った値は最初から履歴を持ちません。

② リセット前に next_value を取る
env.reset() すると観測が変わってしまいます。 打ち切り時点の観測で V を計算してからリセットします （8-b §05）。

unsqueeze(0) の意味 obs は (3,) ですが、ネットはバッチ次元を期待します （network_shapes_explained.html）。 (1, 3) にしてから渡し、返ってきた (1, 1) から [0] で取り出しています。

学習ループ（部品 5）

この節のねらい

5 部品をつなぐ順番を決めます。ここも新しい概念はありません。

for update in range(n_updates):
    ① データを集める（n_steps ぶん）           # 部品 2
    ② GAE でアドバンテージを作る               # 部品 3
    ③ アドバンテージを正規化する
    ④ 同じデータで epochs 回、損失を最小化      # 部品 4
       └ ミニバッチに分けて勾配降下

    idx = np.arange(n_steps)
    for _ in range(epochs):                     # 既定 10 回
        np.random.shuffle(idx)
        for s in range(0, n_steps, batch_size): # 既定 64 ずつ
            b = idx[s:s + batch_size]
            d, v = net.dist(Ot[b])
            lp = d.log_prob(At[b]).sum(-1)

            ratio = (lp - LPt[b]).exp()
            a1 = ratio * ADVt[b]
            a2 = torch.clamp(ratio, 1 - clip, 1 + clip) * ADVt[b]
            pg = -torch.min(a1, a2).mean()

            vl = ((v - RETt[b]) ** 2).mean()
            ent = d.entropy().sum(-1).mean()
            loss = pg + vf_coef * vl - ent_coef * ent

            opt.zero_grad()
            loss.backward()
            nn.utils.clip_grad_norm_(net.parameters(), max_grad)
            opt.step()

二重ループの意味 外側がエポック（同じデータを何周するか）、内側がミニバッチ。 n_steps=8192、batch_size=64、epochs=10 なら、 1 更新あたり 1,280 回の勾配降下を行います。

毎エポックでシャッフルします 同じ順番で回すと、データの並び順に依存した学習になります。 軌跡は時間順に並んでいるので、シャッフルしないと偏ります。

ここが 5-f の「使い捨て」との折り合いです

on-policy なら本来 1 回使ったら捨てるべきでした。 PPO は10 エポック使い回す代わりに、クリップで方策が離れないようにしています。 8-c で作った仕組みが、ここで効いています。

04

論文に書かれていない実装詳細

この節のねらい

PPO の論文に書かれていない、しかし性能を大きく左右する処理をまとめます。 「式は合っているのに学習しない」の主犯です。

処理やること無いとどうなるか
アドバンテージ正規化(adv - mean) / std 報酬スケールごとに lr 調整が必要になる
勾配クリップclip_grad_norm_(params, 0.5) たまに出る大きな勾配で方策が壊れる
十分な n_steps1 更新あたり 8192 程度 §01 の実測: −473 で停滞
エピソード境界の処理8-b §05 アドバンテージが静かに狂う
行動のスケーリング環境の action_space に合わせる 実測: 学習がまったく進まない
この教材を作る過程で 2 回やらかしました

① 行動のスケーリング忘れ
標準の Pendulum-v1 は行動範囲が [-2, 2] なのに、 [-1, 1] で切っていました。 エラーは出ず、学習だけが進まない。

② エピソード境界の取り違え
打ち切り時に次のエピソードの最初の観測で V を計算していました。 8-b §05 で「ここを忘れると静かに狂う」と書いたところを、自分で踏みました。

どちらも 7-b の指標を見て初めて切り分けられました。

勾配クリップについて

nn.utils.clip_grad_norm_(net.parameters(), 0.5)

8-c のクリップとは別物です 8-c は方策の変化量を制限しました。 こちらは勾配そのものの大きさを制限します。 名前が似ていますが、かかる場所が違います。

たまたま大きなアドバンテージが出たとき、 1 回の更新でネットが壊れるのを防ぎます。 効くのは稀ですが、効くときは致命傷を防ぎます。

段階 1

データ収集を書く

この段階ですること §02 のループを algos/ppo_min.py に足します。 写経で構いません。

def collect(env, net, obs, n_steps, obs_dim, act_dim, lo, hi):
  O = np.zeros((n_steps, obs_dim), dtype=np.float32)
  A = np.zeros((n_steps, act_dim), dtype=np.float32)
  LP = np.zeros(n_steps, dtype=np.float32)
  R = np.zeros(n_steps, dtype=np.float32)
  V = np.zeros(n_steps, dtype=np.float32)
  NV = np.zeros(n_steps, dtype=np.float32)
  E = np.zeros(n_steps, dtype=np.float32)
  ep_rets, ep_ret = [], 0.0

  for t in range(n_steps):
    ot = torch.as_tensor(obs, dtype=torch.float32).unsqueeze(0)
    with torch.no_grad():
      a, lp, v = net.act(ot)
    O[t], A[t], LP[t], V[t] = obs, a.numpy()[0], lp.item(), v.item()

    raw = np.clip(a.numpy()[0], -1.0, 1.0)
    nxt, r, term, trunc, _ = env.step(lo + (raw + 1.0) * 0.5 * (hi - lo))
    R[t] = r
    ep_ret += r

    if term:
      NV[t] = 0.0
    else:
      with torch.no_grad():
        _, nv, _ = net(torch.as_tensor(nxt, dtype=torch.float32).unsqueeze(0))
      NV[t] = nv.item()
    E[t] = float(term or trunc)

    if term or trunc:
      ep_rets.append(ep_ret); ep_ret = 0.0
      obs, _ = env.reset()
    else:
      obs = nxt

  return obs, (O, A, LP, R, V, NV, E), ep_rets

行動のスケーリングを入れてあります lo + (raw + 1) * 0.5 * (hi - lo) は 6-b で環境側に入れたものと同じ式です。 自作の振り子は [-1,1] なので実質そのままですが、 他の環境で試すときに必要になります（§04 の失敗例）。

def train(env_fn, obs_dim, act_dim, total_steps=1_000_000, n_steps=8192,
          epochs=10, batch_size=64, lr=3e-4, gamma=0.99, lam=0.95,
          clip=0.2, vf_coef=0.5, ent_coef=0.0, max_grad=0.5, seed=0):
  torch.manual_seed(seed); np.random.seed(seed)
  env = env_fn()
  lo, hi = env.action_space.low, env.action_space.high
  net = ActorCritic(obs_dim, act_dim)
  opt = torch.optim.Adam(net.parameters(), lr=lr)
  obs, _ = env.reset(seed=seed)

  for update in range(total_steps // n_steps):
    obs, (O, A, LP, R, V, NV, E), rets = collect(
        env, net, obs, n_steps, obs_dim, act_dim, lo, hi)

8-c §05 の 3 項を 1 つにまとめる行です。符号に注意してください。

答えと解説を見る
        loss = pg + vf_coef * vl - ent_coef * ent

pg はすでに符号が反転しています pg = -torch.min(...) の時点で「小さくしたい量」になっているので、 ここでは足すだけです。

ent は引きます エントロピーは大きいほうが良い（探索が続く）ので、 損失としては引き算で入れます。 既定の ent_coef=0.0 では効きませんが、 7-c で試したとおり必要になれば上げられます。

vf_coef=0.5 はなぜ 0.5 か 方策の損失と価値の損失の桁を合わせるためです。 価値の損失は 2 乗なので大きくなりがちで、 そのまま足すと Critic の学習が支配してしまいます。
