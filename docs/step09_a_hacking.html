01

宿題の答え合わせ

この節のねらい

「係数はどう決めるべきだったか」に答えます。 答えは「桁を揃える」ですが、その意味を数字で確かめます。

宿題

いまの報酬は -cosθ - 0.01ω² - 0.001τ² でした。 この係数はどうやって決めたでしょうか。 6-d で正直に「目分量です」と書きました。 では、どうやって決めるべきだったのでしょうか。

答え：各項が実際に取る値を計算して、桁を揃えます。

いまの報酬が、代表的な場面でどういう値になるか出しました（実測）。

状況−cosθ−0.01ω²−0.001τ²合計
真下で静止−1.0000.0000.000−1.000
真上で静止（目標）+1.0000.0000.000+1.000
真上を高速通過+1.000−1.000−0.00030.000
振り上げ中−0.071−0.360−0.0003−0.431

3 行目が設計の意図です 「真上を高速通過」が 0.000 になり、「真上で静止」の +1.000 と明確に差がつく。 ω=10 のとき 0.01×100 = 1.0 で、 ちょうど -cosθ の最大値と同じ桁になっています。

これが「桁を揃える」の意味です 止めたい行動が、報酬を稼げなくなるように係数を選ぶ。 6-d では「目分量」と書きましたが、実はこの計算をしていました—— ただ、その根拠を書いていませんでした。

トルクの項だけ桁が違います

-0.001τ² は最大でも -0.00025（τ=0.5 のとき）。 他の項の 1/4000 しかありません。

これは意図的です。トルクの罰は「同じくらいうまくいくなら省エネな方を選べ」 という優先順位の低い希望なので、主目的を邪魔しない大きさにしてあります。

ただし実機では話が変わります——モータの発熱は現実の制約なので、 もっと重くする必要が出てきます。9-d で扱います。

04

本物のハッキングを起こす

この節のねらい

§03 で「項を消しても大事故にはならない」と分かりました。 本物の事故は、項を足したときに起きます。 ここで実際に壊します。

よくある動機

学習を眺めていると、こう思う瞬間が必ず来ます。

「振り上げがなかなか始まらない。動くこと自体にご褒美をあげて、 振り上げを促してやろう」

そこで角速度にプラスの報酬を足します。

reward = -cos(theta) + 0.1 * abs(omega) - 0.001 * torque**2
                      ^^^^^^^^^^^^^^^^^^
                      「動いたら褒める」つもりで足した項

悪意はありません 報酬整形（reward shaping）と呼ばれる、ごく普通の手法です。 「探索を助けるヒントを報酬に混ぜる」——教科書にも載っています。

運悪く起きたのではありません。 この報酬を書けば、必ずこうなります。

普通、ばらつきが小さい = 安定していて良いと読みます。 ここでは逆です。

再現性は「正しさ」の証明ではありません。 何が再現しているのかを見てください。

ランダム方策より悪くなりました

−632.94 は、何も学習していないランダム方策の −499.50 を下回ります。

ランダムはほとんど動かないので角速度の罰をほぼ受けません。 この方策は全力で回り続けるので、罰を稼ぎ続けます。 「学習したせいで、何もしないより悪くなった」状態です。

学習は成功しています

この方策は自分の報酬をきちんと最大化しました。 学習曲線も右肩上がりです。PPO は何ひとつ間違っていません。

間違っていたのは「動いたら褒める」と書いた人間です。

これは学習前に予測できました

足した項がどれくらいの大きさになるか、§01 と同じ計算をするだけです。

方策−cosθ の平均0.1|ω| の平均500 歩の合計
上端で静止する+1.000.00+500.0

回転が 315 点も有利です 回り続けると -cosθ の平均は 0 になります （上半分と下半分が打ち消すので）。 +1.00 を捨ててでも、+1.631 を取ったほうが得——これが方策の計算です。

覚えておく式回転が静止に勝つ境界
条件
0.1 × |ω| > 1.0、つまり |ω| > 10 rad/s。 この振り子は 16.3 rad/s まで出せます——境界を越えています。
言い換えると
足した項の最大値が、主目的の項の最大値を超えた瞬間、 主目的が主目的でなくなります。
だから
報酬に項を足すときは、その項が取りうる最大値を必ず計算する。 3 行の算数で、15 分の学習を無駄にせずに済みます。
係数を小さくすれば直るのか

0.1 を 0.01 にすれば 0.01×16.3 = 0.163 < 1.0 なので、 境界は越えません。この事故は防げます。

ただし「回転したほうが少し得」という歪みは残ります。 だから実務では「探索を助けたい」を報酬で解決しないのが定石です。 初期状態をばらけさせる（9-e）ほうが副作用がありません。

05

どうやって気づくか

この節のねらい

§03 §04 でハッキングは起きると分かりました。 ではどうやって気づくのか。ここが実務でいちばん効く話です。

まず、いちばん大事なこと

学習報酬のグラフを見ても、絶対に気づけません。

ハッキングしている方策は、自分の報酬をちゃんと上げています。 学習曲線はきれいに右肩上がりです。それが問題なのです。

さらに厄介なのが、報酬関数を変えたら数字を比べられないことです。

§04 でやった数字のトリック

+0.1|ω| 版の「学習報酬」は当然高く出ます。 足し算の項が増えているのだから当たり前で、強さとは何の関係もありません。

だから §03 §04 の表では全部「本来の報酬」で採点し直しました。 報酬を変えた実験では、採点用のものさしを固定する——これが鉄則です。

3 つの武器

武器やること見つかるもの
1. 動きを見る学習後の方策を必ず可視化する ほぼ全部。最強で最速
2. 別のものさしで採点報酬とは別に「本当に欲しい量」を測る 上端にいる時間、終盤の |ω|
3. 報酬の内訳をログ各項を個別に足して記録する どの項が効いているか

3 番目は特に見落とされます 報酬は合計しか記録しないのが普通なので、 内訳は誰も見ていません。見ると驚くことがあります。

内訳を見て驚いた例

Step 7 で学習した方策（ppo_semi_long_s0、合計 −109.77）の 報酬を、項ごとに分けて足しました（実測）。

項学習済み PPO割合ランダム方策
-cosθ（角度）−12.04 11%−498.76
-0.01ω²（角速度）−97.65 89%−0.70
-0.001τ²（トルク）−0.08 0.1%−0.04
合計−109.77 −499.50

主役が入れ替わっています -cosθ が主目的のはずなのに、 この方策の失点の89% は角速度の罰です。 「まだ動き回っている」ことが、この方策の弱点そのものだと数字が言っています。

ランダム方策と比べると意味がはっきりします ランダムの失点は99.9% が角度（−498.76）で、 角速度はたった −0.70。ランダムはほとんど動かないからです。 つまりこの 2 列は「立てていない」と「立ったが揺れている」の違いを見せています。

内訳が読めると、次の一手が決まります

角度で失点 → そもそも立てていない。学習量か報酬設計の問題。

角速度で失点 → 立つが暴れている。ω の係数を上げるか、学習を延ばす。

トルクで失点 → 力を使いすぎ。実機なら要対処（9-d）。

課題 3 — 自分でハッキングを起こす

§04 を再現します。報酬を書き換えるのではなく、 gym.Wrapper で上から差し替えてください。 元の環境を壊さずに実験できます。

import gymnasium as gym

class RewardVariant(gym.Wrapper):
  """報酬だけ差し替える。観測も物理もそのまま"""
  def __init__(self, env, mode):

+ であることが全てです -0.01 * omega**2 を +0.1 * abs(omega) に変えます。罰ではなく報酬にするのがこの実験の要点です。
