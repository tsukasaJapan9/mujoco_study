01

桁合わせは破綻する

この節のねらい

手で桁を揃える方法がなぜ破綻するのかを、2 つの理由で示します。 2 つ目は 9-a の実測データから出てきます。

理由 1 — 単位が違うものは直接比べられない

四足歩行ロボットの報酬は、たとえばこうなります。

項単位だいたいの範囲
前進速度が目標に近いかm/s0 〜 1.5
胴体の高さm0.2 〜 0.4
胴体の傾きrad0 〜 0.5
関節の角速度rad/s0 〜 20
関節トルクN·m0 〜 30
足が滑った量m0 〜 0.05

範囲が 0.05 から 30 まで、600 倍の開きがあります これを二乗して足すので、実際の開きは 36 万倍。 係数でこれを揃えるには、6 個の数字を同時に当てる必要があります。 1 個直すと他が崩れます。

理由 2 — 各項の大きさは、学習中に入れ替わる

ここが本当に厄介なところです。9-a §05 で測った内訳をもう一度見ます。

項ランダム方策学習済み PPO変化
-cosθ（角度）−498.76−12.04 41 分の 1に激減
-0.01ω²（角速度）−0.70−97.65 140 倍に激増

主役が完全に入れ替わっています 学習開始時は角度が 99.9%。学習が終わると角速度が 89%。 係数を「学習開始時の値」で揃えると、終盤には合っていません。 逆も同じです。

つまり「正しい係数」は存在しません

各項が取る値が学習中に何十倍も動く以上、 全期間で桁が揃う係数は原理的に作れません。

だから発想を変えます。係数で揃えるのをやめて、 項そのものを最初から同じ範囲に押し込みます。

02

指数型報酬

この節のねらい

§01 の「項そのものを同じ範囲に押し込む」を実行します。 道具はひとつの式だけです。

今回の新しい道具指数型報酬
式
r = exp(-k × e²)。 e は目標からのズレ（誤差）、k は厳しさ。
何が嬉しいか
必ず 0 〜 1 に収まります。 e=0（ぴったり）で 1、e が大きいと 0 に近づく。 単位が何であっても、出てくる数字は 0〜1 です。
なぜ 0〜1 だと嬉しいか
項をいくつ足しても暴走しません。 重みを足して 1 にしておけば、報酬全体も 0〜1。 重みは「単位合わせ」ではなく、純粋に「重要度」になります。
どこで使われているか
四足歩行の学習ではほぼ標準です。 Step 10 で触る MuJoCo Playground の報酬も、この形が中心です。

形を数字で見る

k を変えると、どう変わるか（実測値）。

e=0e=0.05e=0.1 e=0.2e=0.5e=1.0
k=1（ゆるい）1.00000.9975 0.99000.96080.77880.3679
k=51.00000.9876 0.95120.81870.28650.0067
k=201.00000.9512 0.81870.44930.00670.0000
k=100（厳しい）1.00000.7788 0.36790.01830.00000.0000

どの行も左端は必ず 1.0000、右に行くほど 0 に向かいます 違うのは「どのくらいの誤差で 0 に落ちるか」だけ。 k が大きいほどせっかち——少しズレただけで点をくれません。

なぜ二乗なのか

e² なので符号が消えます。 目標より上でも下でも、同じだけズレていれば同じ点。

それとe=0 でなめらかに天井に届く形になります。 |e| だと e=0 で尖ってしまい、学習が振動しやすくなります。

3 項を指数型で書くとこうなる

r_angle  = exp(-5.0  * e_theta**2)     # e_theta = 上端からの角度のズレ [rad]
r_omega  = exp(-0.2  * omega**2)       # omega   = 角速度 [rad/s]
r_torque = exp(-11.0 * torque**2)      # torque  = トルク [N*m]

reward = 0.6 * r_angle + 0.3 * r_omega + 0.1 * r_torque
         ^^^   ^^^^^^^   ^^^   ^^^^^^^   ^^^   ^^^^^^^^
         重みの合計が 1.0 -> reward も必ず 0 〜 1 に収まる

重みの意味が変わっています 0.6 / 0.3 / 0.1 は単位合わせではありません。 「角度が 6 割、静止が 3 割、省エネが 1 割 大事」という優先順位そのものです。 足して 1 なので、割合として読めます。

上限がはっきりします

1 歩の最大が 1.0 なので、500 歩の合計は最大 500。 「満点が何点か」が最初から分かります。

元の報酬（-cosθ - 0.01ω² - ...）は 下限が無いので、−637 のような値も出ました（9-a §04）。 指数型なら、どんなに下手でも 0 より下には行きません。

03

k の決め方

この節のねらい

k=5 や k=20 をどこから持ってきたのか。 当てずっぽうではなく、逆算します。

決め方はひとつだけです。 「どれくらいの誤差までなら許すか」を先に決めて、k を逆算します。

覚えておく式半分になる誤差
定義
報酬が半分（0.5）になる誤差を e_half と呼びます。 「ここまでズレたら、半分しか点をあげない」の境目です。
式
exp(-k × e_half²) = 0.5 を解いて e_half = sqrt(ln2 / k)。
逆に解けば k = ln2 / e_half²（ln2 = 0.6931）。
使い方
許したい誤差を決めて、下の式に入れるだけ。 k を直接いじる必要はもうありません。
ke_half角度なら感覚
10.832647.70 度とてもゆるい
50.372321.33 度ゆるい
200.186210.67 度実用的な既定値
1000.08334.77 度厳しい

振り子の 3 項を、この式で決める

項許したい誤差k = ln2 / e_half²採用した k
角度20 度 = 0.35 rad まで5.75.0
角速度2 rad/s まで0.170.2
トルク0.25 N·m（最大の半分）まで11.111.0

ここが一番の利点です 決めているのは k ではなく「20 度」「2 rad/s」「最大の半分」という、 物理的に意味のある数字です。 ロボットの仕様書から直接読める値なので、当て推量が要りません。

04

二次罰とどう違うのか

この節のねらい

元の報酬の -0.01ω² は二次罰です。 指数型に変えると何が変わるのか。 良いことばかりではありません。

方策が感じるのは「傾き」です

方策が知りたいのは点数そのものではなく、 「少し動かしたら点がどれだけ増えるか」——傾きです。 傾きが 0 なら、どっちに動いても同じなので学びようがありません。

誤差 e二次罰 -e² の傾き 指数型 exp(-20e²) の傾き
0.050.10001.9025
0.100.20003.2749
0.1580.31603.8360（最大）
0.300.60001.9836
0.501.00000.1348
1.002.00000.0000
2.004.00000.0000

正反対の性格です 二次罰は遠いほど傾きが急（どこまでも増える）。 指数型は遠いと真っ平らで、e=0.158 付近がいちばん急です。

二次罰 -k·e²指数型 exp(-k·e²)
範囲下限なし（いくらでも悪くなる）必ず 0〜1
遠いとき強く引っ張る傾き 0。何も教えない
近いとき傾きが消える。詰めが甘いいちばん強く効く
項を増やすと1 項が全体を支配しうる支配されない
指数型の弱点：遠いと何も教えてくれない

k=5 の角度項は、真下（e = π = 3.14）では exp(-5 × 9.87) ≈ 0。傾きもゼロです。

つまり振り上げの最中、報酬は「何をやっても 0 点」と言い続けます。 振り上げを学ぶ手がかりがありません。

実際にこれで学習が失敗するのか——§05 で確かめます。

実務での使い分け

「そこに到達すること」が難しい課題（振り上げ、歩き出し） → 遠くから引っ張る力が要る。二次罰や -cosθ が向く。

「到達した後の精度」が問題の課題（姿勢維持、速度追従） → 指数型が向く。

だから混ぜるのが普通です。 「近づける係」を 1 項だけ二次罰で置き、残りを指数型にします。

役割を分けるという考え方

3 回目でうまくいった構造は、2 つの係に分けたことです。

この節のねらい

課題 1 — e_half から k を出す 
import numpy as np

def k_from_half(e_half):
  """報酬が半分になる誤差 e_half から、指数型報酬の k を返す"""
  return ???                          # ← ここだけ考える

print(k_from_half(0.35))   # -> 5.66    角度 20 度
print(k_from_half(2.0))    # -> 0.17    角速度 2 rad/s
print(k_from_half(0.25))   # -> 11.09   トルク 0.25 N*m
答えと解説を見る
def k_from_half(e_half):
  """報酬が半分になる誤差 e_half から、指数型報酬の k を返す"""
  return np.log(2) / e_half**2

導き方 exp(-k × e_half²) = 0.5 の両辺の対数を取ると -k × e_half² = ln(0.5) = -ln2。両辺を -e_half² で割れば出ます。

np.log は自然対数です np.log10 や np.log2 ではありません。np.log(2) は 0.6931。k_from_half(0.35) が 5.66 になれば合っています。

この課題のねらい k を直接さわる習慣を捨てます。 これ以降、考えるのは「何度まで許すか」だけになります。

課題 2 — 3 状態チェックを関数にする

§05 の表を作る関数です。報酬を書いたら必ずこれを通すようにします。

import numpy as np

def check3(reward_fn):
  """「何もしない」「途中」「成功」の 3 点で報酬を出し、差を表示する

  reward_fn(theta, omega, torque) -> float
  """
  rest = reward_fn(0.0, 0.0, 0.0)                 # 真下でじっと静止
  swing = reward_fn(np.pi - 1.8, 6.0, 0.5)        # 振り上げの最中
  top = reward_fn(np.pi, 0.0, 0.0)                # 上端でじっと静止
  gap = ???                                       # ← ここだけ考える
  print(f"静止 {rest:+.4f}  途中 {swing:+.4f}  成功 {top:+.4f}   差 {gap:+.4f}")
  if gap <= 0:
    print("  危険: 動き出すこと自体が損になっている")
  elif gap < 0.05:
    print("  危険: 差が小さすぎる。学習しない可能性が高い")
  return gap
答えと解説を見る
  gap = swing - rest

引く順番を間違えないでください 「やってほしい動作」−「何もしない」です。逆にすると符号が反転し、危険な報酬を「安全」と判定します。

top は判定に使いません top（成功時の点）が一番高いのは当たり前で、そこは問題になりません。問題は、そこに行き着くまでの道のりです。§05 の 2 回目は top が正しかったのに失敗しました。

この課題のねらい 報酬を書いた直後に、学習させずに判定できるようにします。 §05 の 3 回の実験は合計 40 分かかりましたが、 この関数なら1 秒で同じ結論が出ます。

答え合わせ

元の報酬で check3 を回すと 差 +0.4125。 §05 の expo なら −0.3934、 expo2 なら +0.0078 になります。

まとめ

この教材で分かったこと
  1. 係数の手調整は原理的に破綻する。 各項の大きさは学習中に何十倍も動く（角度 41 分の 1、角速度 140 倍）（§01）
  2. exp(-k·e²) は必ず 0〜1。 重みを足して 1 にすれば、重みは純粋な優先順位になる（§02）
  3. k = ln2 / e_half²。 決めるのは k ではなく「何度まで許すか」（§03）
  4. 指数型は遠いと傾き 0。近づく力がない（§04）
  5. その弱点で、学習が 2 回丸ごと失敗した。 3 シードとも一度も動かなかった（§05）
  6. 失敗は 1 つの数字で予測できた—— 「やってほしい動作」と「何もしない」の 1 歩あたりの報酬差（§05）
  7. ばらつきが小さいことは、良いことを意味しない。 失敗した報酬の標準偏差は 0.00〜0.03、 まともな報酬は 206〜217（§05）
いちばん持ち帰ってほしい一文

報酬を書いたら、学習させる前に「動き出す得」を計算する。

「何もしない」と「やってほしい動作」の 1 歩あたりの差。 これが 0 以下なら、絶対に学習しません。 小さすぎても学習しません。1 秒でできる検査です。

指数型は使うなということではありません

指数型は「到達した後の精度」を上げる道具として優秀です。 Step 10 で触る MuJoCo Playground の報酬も、この形が中心です。

ただし「そこに到達する」仕事は別の項に任せる必要があります。 役割を分ける——これが §05 の結論です。
