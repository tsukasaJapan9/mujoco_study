  2. 報酬を書いたら「動き出す得」を計算してから学習させる（9-b）

この教材が答える問い

2. 測った数字を、いつ信じていいのか？

この教材は、失敗の記録です

実際に ablation を走らせたところ、「全部入りの報酬がいちばん悪い」 という結果が出ました。

それが本当なのか、測り方が悪いのか。そこを見分けるのが今回の中身です。

01

ablation とは

この節のねらい

やり方そのものはとても単純です。まずそこを押さえます。

今回の新しい語ablation（アブレーション）
やること
部品を 1 つずつ取り外して、性能がどう変わるかを測る。 報酬の項、観測の要素、ネットワークの層——何にでも使えます。
何が分かるか
その部品が本当に仕事をしているか。 外しても変わらないなら、その部品は要りません。
なぜ必要か
報酬の項は足すのは簡単、外すのは怖いので、 誰も使っていない項が残り続けます。 項が増えるほど 9-b の問題（桁合わせ）が悪化します。
鉄則
採点は常に「全部入りの報酬」で行う。 学習に使う報酬は変えますが、ものさしは絶対に変えません（9-a §05）。

振り子で外せる項

reward = -cos(theta) - 0.01 * omega**2 - 0.001 * torque**2
                       ^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^
                       外せる 1          外せる 2
条件名学習に使う報酬
full-cosθ - 0.01ω² - 0.001τ²（全部入り）
noOmega-cosθ               - 0.001τ²
noTau-cosθ - 0.01ω²
onlyCos-cosθ

-cosθ は外せません これを外すと目標そのものが消えます。 ablation は「あっても無くてもいいかもしれない部品」に対してやるものです。

04

平均が嘘をつく理由

この節のねらい

標準偏差が大きい、で終わらせません。 数字の中身を見ると、もっと大事なことが分かります。

12 個の数字を並べ直す

+48.9  +41.7  +36.6  +34.5  +32.1  +16.5     <- 成功した 6 本
-347.4  -364.1  -364.8  -417.8  -473.0  -473.0   <- 失敗した 6 本
中間がありません

+16.5 の次が −347.4。その間には何もありません。

つまりこの学習は連続的に良し悪しが変わるのではなく、 「振り上げを覚えたか、覚えなかったか」の 2 つに割れています。

いちばん大事な気づき二値の結果に平均を使ってはいけない
何が起きているか
結果が +30 付近か −400 付近のどちらかしかありません。 平均 −268 という方策は 1 つも存在しません。
だから平均は何を表しているか
ほぼ成功率だけです。 3 本中 1 本成功なら約 −268、2 本成功なら約 −88。 成功したときの出来の良さは、ほとんど反映されていません。
測るべきもの
成功率と成功したときの点数を分けて報告します。

分けて書き直す

条件成功率成功時の平均 失敗時の終盤 |ω| 最大
full1/3+32.13.86
noOmega2/3+41.711.05
noTau1/3+16.55.01
onlyCos2/3+39.212.50

ここで初めて、意味のありそうな形が見えます 失敗したときの暴れ方には、はっきり差があります。 ω の罰がある条件は 3.86 / 5.01、 無い条件は 11.05 / 12.50。2〜3 倍違います。

これは 9-a §03 の答え合わせでもあります ω の罰は成功率を上げる道具ではなく、 こけ方をおとなしくする道具でした。 実機ではこちらのほうが重要かもしれません。

ただし、これも 3 本ずつです

まだ結論ではありません。 「意味のありそうな形が見えた」段階です。§05 で本数を計算します。

今回いちばん重要な副産物

ablation をやろうとして分かったのは、 「ベースライン自身が 3 回に 1 回しか成功していない」ことでした。

これは報酬の項の問題ではありません。 比べる前に直すべきものが見つかった、ということです。 9-e でこれを直します。

手を動かす

この節のねらい

ablation を回す仕掛けと、結果を正しくまとめる関数を作ります。

課題 1 — 条件を係数で切り替える

9-a 課題 3 の RewardVariant を発展させます。 条件ごとに if を書くのではなく、係数の表にします。

W = {"full":    (1, 1),
     "noOmega": (0, 1),
     "noTau":   (1, 0),
     "onlyCos": (0, 0)}

class Ablate(gym.Wrapper):
  def __init__(self, env, mode):
    super().__init__(env)
    self.w = W[mode]

  def step(self, action):
    obs, reward, terminated, truncated, info = self.env.step(action)
    u = self.env.unwrapped
    theta, omega = u.data.qpos[0], u.data.qvel[0]
    torque = float(u.data.ctrl[0])
    reward = ???                      # ← ここだけ考える（self.w を使う）
    return obs, float(reward), terminated, truncated, info
答えと解説を見る
    reward = (-np.cos(theta)
              - self.w[0] * 0.01 * omega**2
              - self.w[1] * 0.001 * torque**2)

係数を 0 にするのであって、項を消すのではありません self.w[0] が 0 なら、その項は常に 0 になります。式の形は 4 条件すべてで同じなので、書き間違いが入りません。

full で元の報酬と一致するか確かめてください W["full"] = (1, 1) のとき、envs/pendulum_env.py の報酬と 1 ビットも違わないはずです。ここがずれていると、ablation 全体が無意味になります。

この課題のねらい 条件を増やすときに 1 行足すだけで済む形にします。 if を並べると、条件を足すたびにバグが入ります。

課題 2 — 成功と失敗を分けてまとめる

§04 の表を作る関数です。平均だけを出す関数を書いてはいけません。

import numpy as np

def summarize(results, threshold=100):
  """results: [(seed, score, upright), ...]

  上端にいた歩数が threshold を超えたら「成功」とみなす
  """
  ok = [r for r in results if r[2] > threshold]
  ng = [r for r in results if r[2] <= threshold]
  print(f"成功率      {len(ok)}/{len(results)}")
  print(f"成功時の平均 {???}")           # ← ここだけ考える
  print(f"全体の平均   {np.mean([r[1] for r in results]):+.2f}  "
        f"(標準偏差 {np.std([r[1] for r in results]):.2f})")
  if ng:
    print(f"失敗したシード: {[r[0] for r in ng]}")
答えと解説を見る
  print(f"成功時の平均 {np.mean([r[1] for r in ok]):+.2f}" if ok else "成功時の平均 —")

ok が空のときに注意 全シード失敗すると np.mean([]) は nan と警告を出します。0 本のときは平均を出さないのが正解です。

r[1] が点数、r[2] が上端の歩数 タプルの順番は (seed, score, upright)。成功判定は r[2]、平均を取るのは r[1] です。混同するともっともらしい嘘の数字が出ます。

この課題のねらい 「全体の平均」も出しますが、必ず成功率と並べて出します。 平均だけ見ると §03 の罠にはまります。

課題 3 — 自分で 12 本回す（時間があるとき）

4 条件 × 3 シード。2〜3 時間かかります。 CPU コアが余っていれば 3 本ずつ並列に回せます。

# 1 本あたり 2 スレッドに制限して、3 本並列
import os
os.environ["OMP_NUM_THREADS"] = "2"
import torch
torch.set_num_threads(2)

スレッド数を絞る理由 PyTorch は既定で全コアを使おうとします。 3 本同時に走らせると奪い合って全部遅くなります。

答えと解説を見る
full     seed 0 +32.11   seed 1 -473.03   seed 2 -364.06
noOmega  seed 0 +48.86   seed 1  +34.54   seed 2 -347.44
noTau    seed 0 +16.51   seed 1 -473.03   seed 2 -364.77
onlyCos  seed 0 +41.66   seed 1  +36.64   seed 2 -417.78

完全一致はしません PyTorch のスレッド数や版が違うと足し算の順序が変わり、結果がずれます。同じ数字を狙わないでください。

一致していてほしいのは傾向のほうです (1) どの条件も成功と失敗しかない、(2) 標準偏差が 200 前後、(3) full が最良にならない。この 3 つが出れば §03〜§05 の議論は再現できています。

注意 スレッド数を変えると同じシードでも結果が変わります （足し算の順序が変わるため）。 比較する実験は、必ず同じスレッド数で回してください。

07

まとめ

この教材で分かったこと
  1. ablation = 項を 1 つずつ外して測る。 採点は必ず全部入りの報酬で（§01）
  2. 1 シードの結果はきれいに見える。 順位も付く。そして全部間違っている（§02）
  3. 3 シードにすると、全部入りが最下位になった。 ただし標準偏差 217 なので何も言えない（§03）
  4. 結果は二値だった（+30 付近か −400 付近か）。 平均 −268 という方策は存在しない（§04）
  5. 成功率と成功時の点数を分けて報告する（§04）
  6. 1/3 と 2/3 を見分けるには約 50 本必要。3 本では 27.8%（§05）
いちばん持ち帰ってほしい二文

1. 差を主張する前に、ばらつきを測る。 標準偏差より小さい差は、何本並べても差ではありません。

2. ばらつきが大きいなら、比べるより先に減らす。 50 本走らせるより、学習を安定させるほうが圧倒的に安い。
