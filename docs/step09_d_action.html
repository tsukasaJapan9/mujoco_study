行動空間の選択肢

この節のねらい

Step 3 で motor / position / velocity の 3 つのアクチュエータを触りました。 学習ではどれを使うのか、その判断基準を持ちます。

方策が出す値MJCF中で何が起きるか
トルク（いまこれ）motor そのまま関節に加わる
目標角度position 内部の PD が kp(q*-q) - kv·ω を計算してトルクにする
目標角速度velocity 内部の P 制御が kv(ω*-ω) を計算する
いちばん大事な違い制御周期の差
方策が動く速さ
100 Hz（CTRL_HZ = 100）。frame_skip = 10 なので 物理 10 歩ごとに 1 回しか指令を変えられません。
内部 PD が動く速さ
1000 Hz（物理と同じ）。方策の 10 倍細かく働きます。
だから何が違うのか
トルク指令だと、方策が指令を変えるまでの 10 歩は同じトルクが出っぱなし。 目標角度なら、その 10 歩の間も内部 PD が状態を見て補正し続けます。
実機での意味
目標角度方式は方策が多少雑でも、内部 PD が滑らかにしてくれる。 四足歩行の実機研究で目標角度方式が主流なのはこれが理由です。
トルク方式が悪いわけではありません

トルク方式は方策が物理を直接さわれるので、 素早い動き（跳躍、受け身）では有利です。 内部 PD は「目標に追従する」ことしかできません。

問題はトルク方式だと方策の粗さがそのまま関節に出ること。 §02 以降で、それがどれくらいの量なのかを測ります。

02

いまの方策は滑らかか

この節のねらい

「方策がガタガタする」とよく言われます。 本当にそうなのか、自分の方策で測ります。

何を測るか

指標意味実機で何に効くか
平均|at − at-1|1 歩でどれだけ指令が動くか モータの発熱、消費電力
符号反転回数指令の増減が逆転した回数 ギアのバックラッシュ、異音、摩耗

符号反転が効く理由 力の向きが変わる瞬間にギアの歯が当たり直します。 これが 1 秒に何十回も起きると、ガタガタという音と摩耗になります。 報酬にはまったく現れません。

観測ノイズで豹変する

この節のねらい

§02 の測定は観測が完璧という前提の上にありました。 実機のセンサに完璧はありません。 ノイズを足すだけで何が起きるか見ます。

実機では観測が必ず汚れます

エンコーダの分解能、角速度の差分計算で増える雑音、通信の遅れ、温度ドリフト。 どれも避けられません。

なぜこうなるのか

方策は観測から行動への関数です。 この方策は観測の細かい変化に敏感に作られていました。

シミュレータ実機
観測完璧に滑らか毎ステップ揺れる

モータ—1 秒に 19 回 向きが変わる

ノイズが探索の役割をして、たまたま少し得をしているだけです。 「ノイズを足したら点が上がった、よかった」と読んではいけません。 見る指標を間違えると、逆の結論に着地します。

対策 2 — 目標位置で指令する

この節のねらい

§01 で挙げた目標角度方式を実際に試します。 期待した効果は出ませんでした。その理由が大事です。

やること

MJCF のアクチュエータを差し替えるだけです。

<!-- いま -->
<motor name="torque" joint="hinge" gear="1" ctrlrange="-0.5 0.5"/>

<!-- 目標角度方式 -->

方策の出力 a は [-1, 1] です。 同じ a・同じノイズを両方式に与え、 実際に関節にかかった力（d.qfrc_actuator）の滑らかさを測りました。

なぜか

指令のノイズがどう伝わるか
トルク指令 ノイズ δa はそのまま 0.5·δa のトルクになる。 それ以上には増えない
目標角度指令 ノイズ δa は π·δa の目標のズレになり、 kp 倍されてトルクになる。掛け算で増える

内部 PD は「ノイズを消す装置」ではありません PD は目標と現在値の差に比例した力を出すだけです。 目標が揺れれば、力も揺れます。 むしろ kp の分だけ増幅します。

正しい理解目標角度方式の本当の利点
利点ではないもの
指令ノイズの除去。上の実測のとおり、むしろ悪化します。
本当の利点 1
外乱に速く反応できる。 方策は 100 Hz でしか動けませんが、内部 PD は 1000 Hz。 押されたり滑ったりしたとき、方策を待たずに踏ん張ります。 指令が汚れる話ではなく、状態が乱れる話です。
本当の利点 2
探索が楽になる。 「目標姿勢」はでたらめな値でもそれなりの姿勢になりますが、 でたらめなトルクはただ暴れるだけ。 関節が 12 個ある四足では、この差が決定的です。
この振り子で効かない理由
関節が 1 つしかなく、外乱も無いから。 利点が発生する条件が揃っていません。
Step 12 に向けての結論

四足歩行では目標角度方式を使ってください。 実機研究でほぼ標準です。ただし理由は「滑らかになるから」ではありません。

この振り子で試しても利点は測れません。 効果が出る条件が無い課題で試して「効かなかった」と結論するのは、 9-c で見た測り方の失敗と同じです。

課題 1 — 行動の滑らかさを測る

train/eval.py に追加します。

def smoothness(policy, n_ep=10, steps=500, noise=0.0):
  """行動の滑らかさを測る。noise は観測に足す正規乱数の強さ"""
  rng = np.random.default_rng(0)
  deltas, reversals = [], []
  for ep in range(n_ep):
    env = TimeLimit(PendulumEnv(), max_episode_steps=steps)
    obs, info = env.reset(seed=ep)
    env.action_space.seed(ep)
    prev, ds, sign, n_rev = None, [], 0, 0
    for t in range(steps):
      noisy = obs + rng.normal(0, noise, size=obs.shape)
      a = float(np.asarray(policy(env, noisy)).ravel()[0])
      if prev is not None:
        ds.append(abs(a - prev))
        s = np.sign(a - prev)
        if ???:                          # ← ここだけ考える（符号が変わったか）
          n_rev += 1
        if s != 0:
          sign = s
      prev = a
      obs, reward, terminated, truncated, info = env.step(np.array([a], dtype=np.float32))
      if terminated or truncated:
        break
    deltas.append(np.mean(ds))
    reversals.append(n_rev)
  return np.mean(deltas), np.mean(reversals)
答えと解説を見る
        if s != 0 and sign != 0 and s != sign:
          n_rev += 1

3 つの条件が全部要ります s != 0：今回まったく動かなかったら数えない。
sign != 0：まだ 1 度も動いていなければ比べる相手がない。
s != sign：これが本題（向きが変わった）。

s == 0 を数えると壊れます np.sign(0.0) は 0.0 です。これを「符号が違う」と判定すると、止まっている方策が最大の反転回数を記録します。

ヒント 「前回と符号が違う」かつ「どちらも 0 でない」ときに数えます。 s が 0 のとき（まったく動かなかったとき）を数えると、数が壊れます。

答え合わせ

ppo_semi_long_s0 で回すと——

noise=0.01  ->  |da| 0.0285   反転 95.0
noise=0.10  ->  |da| 0.1351   反転 174.6

    high = np.concatenate([env.observation_space.high, [1.0]]).astype(np.float32)
    self.observation_space = gym.spaces.Box(low, high, dtype=np.float32)

  def reset(self, **kwargs):
    obs, info = self.env.reset(**kwargs)
    self.prev = 0.0
    return np.concatenate([obs, [self.prev]]).astype(np.float32), info

答えと解説を見る
    reward = float(reward) - self.w * (a - self.prev) ** 2

2 乗にするのは 9-b と同じ理由です 符号を消すため（上げるのも下げるのも同じだけ罰する）と、a = self.prev でなめらかに 0 になるためです。

self.prev を更新する位置に注意 罰を計算した後に self.prev = a します。先に更新すると a - self.prev が常に 0 になり、罰が一切効きません。

重みの目安 §04 のとおり 主目的の 100 分の 1 程度から始めます。Playground の Go1 も tracking_lin_vel +1.0 に対し action_rate -0.01 です（10-d）。

なぜ観測に前回の行動を足すのか 罰の大きさは at − at-1 で決まります。 at-1 が観測に無いと、方策は自分がいくら罰されるか分かりません。 「罰する量は、観測から分かるようにする」——これは一般則です。

w を大きくすると「行動を変えない」が最適になります。 9-b の「動き出す得」をそのまま使えます。

実際、w=0.5 で学習させたら行動がほぼ固まりました （|Δa| = 0.0014）。§04 で詳しく見ます。
