01

観測の 3 原則

この節のねらい

観測を決めるときの判断基準を 3 つだけ持ちます。

観測を決める基準3 つだけ
原則 1 — 実機で取れるか
センサで測れない量を入れてはいけません。 シミュレータでは何でも読めるので、うっかり入ります。 入れるとシミュレータでだけ動く方策ができます（§03）。
原則 2 — 判断に足りるか
方策は観測だけを見て行動を決めます。 必要な情報が観測に無ければ、絶対に正しく動けません。 報酬で罰する量は、観測から分かるようにする（9-d 課題 2）もこれです。
原則 3 — 不連続にならないか
同じ状態なのに数値が飛ぶ表現を使ってはいけません。 ニューラルネットは滑らかな関数しか素直に学べません（§02）。
いまの振り子の観測原則 1原則 2原則 3
cosθエンコーダで取れる 角度が分かる滑らか
sinθ同上 cos と組で向きが確定滑らか
ω差分で取れる（雑音は乗る） 速度が分かる滑らか

3 つとも通っています 6-a で何気なく決めた観測ですが、3 原則を満たしています。 なぜそれでよかったのかを、§02 以降で確かめます。

02

なぜ cos と sin なのか

この節のねらい

原則 3（不連続にしない）の実例です。 θ をそのまま入れると何が壊れるのか。

θ をそのまま入れた場合

物理的な状態θ の値 cosθsinθ
真上（少し右）+3.14−1.000+0.002
真上（少し左）−3.14 −1.000−0.002
ほとんど同じ状態なのに、θ は 6.28 も離れています

方策から見るとまったく別の状況に見えます。 右に少し傾いた真上と左に少し傾いた真上で、 学んだことが共有されません。

cos と sin なら0.004 しか違いません。 ほぼ同じ状態として扱われます。これが欲しい性質です。

覚えておく型角度は必ず cos と sin の組で入れる
なぜ 2 つ要るのか
cos だけだと上か下かは分かるが、右か左かが分からない （cos(+1.0) = cos(-1.0)）。2 つで向きが一意に決まります。
次元は増えるが
1 次元 → 2 次元に増えます。 それでも必ずこうします。 次元を 1 つ節約して学習を壊すのは割に合いません。
回らない関節では
ロボットの膝のように±90 度しか動かない関節なら、 不連続点に到達しないので角度をそのまま入れて構いません。 Go1 の観測も、関節角はそのまま入っています。
03

実機で取れない量

この節のねらい

原則 1です。Sim2Real で最も多い失敗がこれです。

今回の新しい語特権情報（privileged information）
何か
シミュレータでは読めるが、実機では測れない量。 摩擦係数、各リンクの正確な質量、外から加わっている力、地形の高さ、 他の物体の正確な位置など。
なぜ危険か
方策がそれを頼りに動くと、実機では入力が無くなります。 シミュレータでは完璧、実機ではまったく動かない—— いちばん徒労感のある失敗です。
うっかり入る例
self.data.qpos や self.data.qvel を 何も考えずに全部観測に入れる。 浮いている胴体の絶対位置は、実機では測れません。

それでも特権情報を使う方法がある

Critic にだけ見せます。

見せるもの実機で必要か
Actor（方策）実機で取れる量だけ 必要
Critic（価値関数）特権情報を含めてよい 不要（学習中しか使わない）

Critic は実機に載りません 8-a で学んだとおり、Critic は学習のためだけにあります。 実機で動くのは mu を出す Actor だけ。 だから Critic には何を見せても構いません。

Critic が賢くなると、Advantage が正確になります 8-b で見たとおり、Advantage = 実際の結果 − Critic の予想。 Critic が「この地面は滑りやすいから、こけても方策のせいではない」と分かれば、 ノイズの少ない学習信号になります。

Playground の Go1 がまさにこれです 
env.observation_size
# -> {'privileged_state': (123,), 'state': (48,)}

state が 48 次元——Actor が見る、実機で取れる量。
privileged_state が 123 次元——Critic が見る、シミュレータだけの量。

2.5 倍の情報を Critic だけが持っています。 この作りは「非対称 Actor-Critic」と呼ばれ、四足歩行では標準です。

振り子では要りません

観測 3 つが全部実機で取れるので、分ける必要がありません。

Step 12 で実機に向かうとき、この節に戻ってきてください。 「その観測、実機で取れますか」——これを毎回問うのが習慣です。

04

初期状態をばらけさせる

この節のねらい

9-c で見つけた「3 回に 1 回しか成功しない」を直します。 Step 9 でいちばん効果が大きかった 1 行です。

いまの初期状態

self.data.qpos[0] = self.np_random.uniform(-0.1, 0.1)    # 真下から ±0.1 rad
self.data.qvel[0] = self.np_random.uniform(-0.1, 0.1)

±0.1 rad は約 5.7 度です 毎回ほぼ同じ場所から始まります。 真下でぶら下がった状態から、自力で振り上げを発見しなければいけません。

なぜこれが問題なのか

方策は上端の近くに行ったことがないので、 上端でどう振る舞えばいいか、まったく学べません。

学習の順番はこうなります。 (1) 偶然、上端の近くに来る → (2) そこで報酬が高いと気づく → (3) 上端を目指すようになる。

(1) が起きるかどうかが、乱数任せです。これが 9-c で見た二値の正体です。

全周からスタートさせる

self.data.qpos[0] = self.np_random.uniform(-np.pi, np.pi)   # どの角度からでも
self.data.qvel[0] = self.np_random.uniform(-2.0, 2.0)

これだけです 学習中だけ、初期状態を全周に広げます。 上端の近くから始まる回が、最初から一定割合で混ざります。

採点は既定のまま（±0.1）でやります

学習条件を変えても、ものさしは変えません。 広い初期状態で採点すると、簡単な場所から始まる分だけ点が上がってしまいます。

9-a §05、9-c §01 と同じ鉄則です。

結果（実測、3 シード）

学習時の初期状態成功元の報酬（平均） 標準偏差上端にいた歩数（3 シード）
いまのまま ±0.11/3 −267.61218.04 221.1 / 0.0 / 0.0
全周 ±π3/3 −39.9242.87 207.5 / 183.7 / 120.7
9-c の問題が解けました

成功率 1/3 → 3/3。標準偏差 218.04 → 42.87（5 分の 1）。

9-c §05 で「50 シード必要」と計算した状況が変わります。 ばらつきが 5 分の 1 なら、必要なシード数は 25 分の 1（標準誤差は 標準偏差に比例し、シード数の平方根に反比例するため）。 50 本が 2 本で足りる計算になります。

ただし、いちばん良い回は悪くなりました

成功したときの上端時間を見てください。 いまのまま：221.1。全周：207.5 / 183.7 / 120.7。 最良の 1 回だけ比べると、負けています。

理由ははっきりしています。 方策が「全周のどこからでも立てる」ことに能力を使っているからです。 採点は真下付近からしか始まらないので、 その分は無駄になっています。

覚えておく取引確実さと、尖り
初期状態を広げると
確実に学習するようになる。ばらつきが激減する。
その代わり
特定の状況に特化した強さは落ちる。
どちらを取るか
ほぼ常に「確実さ」です。 1 回だけ強い方策は再現できないので価値がありません（9-c）。 それに実機では、そもそも初期状態を選べません。
Phase D への橋渡し
この「わざと条件をばらけさせて、確実さを買う」考え方が、 Step 11 のドメインランダム化そのものです。 ばらけさせるのが初期状態か、質量・摩擦かの違いだけです。
05

観測を削る・履歴を足す

この節のねらい

原則 2（判断に足りるか）を実験で確かめます。 ω を観測から抜いたら、どうなるか。

なぜこれを試すのか

ω（角速度）は実機でいちばん汚れる観測です。 多くのロボットは角度しか直接測れず、角速度は差分で作ります。 差分は雑音を増幅します。

omega = (theta_now - theta_prev) / dt     # 角度の雑音が 1/dt 倍される

dt = 0.01 なら 100 倍です 角度の測定誤差が 0.001 rad でも、角速度の誤差は 0.1 rad/s。 だから「角速度を観測に入れない設計」が検討されます。

2 つの案を試しました

案観測次元狙い
いまのままcosθ, sinθ, ω3—
ω を抜くcosθ, sinθ2 汚れる観測を使わない
履歴で代用cosθ, sinθ + 前回の cosθ, sinθ 42 時刻あれば速度が分かるはず
観測成功元の報酬（平均）標準偏差
いまのまま（3 次元）1/3−267.61218.04
ω を抜く（2 次元）0/3 −473.320.21
履歴で代用（4 次元）0/3 −473.320.21
どちらも 1 回も成功しませんでした

ω を抜くと学習できないのは予想どおりです。 速度が分からなければ、振り上げのタイミングを決められません。

予想外だったのは「履歴で代用」も失敗したことです。 cosθ が 2 時刻ぶんあれば、原理的には速度が分かるはずでした。

なぜ履歴では代用できなかったのか

ω を直接入れる2 時刻の角度を入れる
方策がやることそのまま使う 引き算して 100 倍するのを学習する
値の大きさω は ±10 程度 差は ±0.1 程度。他の入力に埋もれる
必要な学習なし速度の概念をゼロから

2 時刻の差は、とても小さい値です 制御周期 dt=0.01 で ω=10 でも、 角度の変化は 0.1 rad。 cosθ の変化はさらに小さくなります。 方策から見ると「ほとんど同じ 2 つの数字」で、 そこから速度を取り出すのは簡単ではありません。

覚えておく原則計算できる情報でも、計算済みで渡す
よくある勘違い
「情報が入っていれば、ネットワークが取り出してくれる」。 理論上は正しく、実務では間違いです。
実際に起きること
取り出すこと自体を学習しなければならず、 本来の課題を学ぶ前に、そこで詰まります。
だからどうするか
計算できるものは、こちらで計算して渡します。 速度、加速度、目標との誤差、接触の有無。 ネットワークに推理させないでください。
履歴が効く場面もあります
「何が起きたか分からないが、履歴には出ている」とき。 たとえば地面の滑りやすさは直接測れませんが、 過去の指令と実際の動きのズレに現れます。 履歴は「計算式が書けないもの」のための道具です。
実機で角速度が汚いときの正解

観測から抜くのではなく、ローパスフィルタをかけて渡します。 そのうえで、学習時に同じ性質のノイズを混ぜます（Step 11）。

「汚いから使わない」ではなく「汚いまま学習させる」のが Sim2Real の基本方針です。

envs/pendulum_env.py の reset を書き換えます。 いまは ±0.1 が直接書いてあります。

class PendulumEnv(gym.Env):
  def __init__(self, init_theta=0.1, init_omega=0.1):
    ...
    self.init_theta = init_theta        # 初期角度のばらつき幅 [rad]
    self.init_omega = init_omega        # 初期角速度のばらつき幅 [rad/s]

  def reset(self, *, seed=None, options=None):
    super().reset(seed=seed)
    mujoco.mj_resetData(self.model, self.data)
    self.data.qpos[0] = ???                        # ← ここだけ考える
    self.data.qvel[0] = self.np_random.uniform(-self.init_omega, self.init_omega)
    mujoco.mj_forward(self.model, self.data)
    return self._obs(), {}
答えと解説を見る
    self.data.qpos[0] = self.np_random.uniform(-self.init_theta, self.init_theta)

np.random ではなく self.np_random です Gymnasium が reset(seed=...) で管理している乱数です。np.random を使うと種が効かず、再現できなくなります（7-d）。

既定値を変えないでください __init__(self, init_theta=0.1, init_omega=0.1) のままにすれば、これまでの実験結果がそのまま再現できます。広げるのは呼び出し側の仕事です。

この課題のねらい 既定値を変えないことが大事です。 init_theta=0.1 を既定にしておけば、 これまでの実験結果がそのまま再現できます（9-c の教訓）。

採点用の環境は絶対に変えないでください

train/eval.py の evaluate() は 既定の ±0.1 のままにします。

学習時の初期状態を広げても、採点は同じ条件でやる。 9-a §05 の「ものさしを固定する」と同じ話です。 広い初期状態で採点すると、簡単な状態から始まる分だけ点が上がってしまいます。
