01

ギャップの 6 分類

この節のねらい

Phase D の背骨になる分類です。 実機で動かないとき、この 6 つのどれかを疑うところから始めます。

分類具体例主な対策扱う教材
1. 物理パラメータ 質量・慣性・重心・摩擦係数の誤差 ドメインランダム化、システム同定11-b, 11-d
2. アクチュエータ サーボの応答遅れ、トルク上限、バックラッシュ、減速比の損失 アクチュエータモデル、実測同定11-d
3. 遅延 センサ読み取り → 推論 → 指令送出（実機で 5〜30 ms） シミュに人工遅延、観測履歴11-c
4. 観測 センサノイズ、バイアス、ドリフト、量子化 ノイズ注入、非対称 Actor-Critic11-b, 9-e
5. 接触 地面の弾性、滑り、足裏形状 接触パラメータのランダム化11-b
6. 未モデル化 ケーブルの張力、たわみ、発熱によるトルク低下 頑健化（DR）、オンライン適応11-b, 11-e
あなたの振り子では 5 番が出ません

1 自由度の振り子は床に触れません。 接触は Step 12 で機体を作ってから扱います。

残り 5 つは全部この振り子で再現できます。 1 自由度だからこそ、原因が 1 つずつ切り分けられます。

Phase D の考え方ギャップは「消す」ものではない
よくある誤解
シミュを現実そっくりにすれば解決する。
なぜ無理か
完全に合わせることは原理的にできません。 質量は測れても、グリスの粘性は温度で変わります。 ケーブルの張力もモータの発熱も、毎回違います。
実際にやること
(a) 合わせられるところは合わせる（システム同定・11-d）
(b) 合わせられないところは、ばらけさせて耐えさせる（DR・11-b）
そのために最初に要るもの
「どれくらいズレたら壊れるか」を測る道具。 これが無いと、(a) をどこまで頑張るべきかも、(b) をどの範囲で振るべきかも決まりません。 §02 で作ります。
02

測る土台を作る

この節のねらい

実機を触らずに Sim2Real を練習する方法を作ります。 「わざとズラした別のシミュ」で採点するのがそれです。

今回の新しい語sim-to-sim テスト
何をするか
学習に使ったのとは違うパラメータのシミュで、方策を採点する。 質量を 10% 増やす、ダンピングを 2 倍にする、観測にノイズを載せる——といった具合です。
なぜこれが実機の代わりになるか
実機との違いは、結局「パラメータがズレている」ことです。 ズレの向きと大きさを自分で決められるぶん、実機よりずっと調べやすい。
実機と違うところ
未モデル化の要素（分類 6）は再現できません。 sim-to-sim を通ったからといって実機で動く保証はありません。 ただし sim-to-sim で落ちるなら、実機では確実に落ちます。
だから何のために使うか
実機に載せる前に落とすための関門です。 通過は保証ではなく、最低条件。

この課題のねらい 「1 つのつまみで、物理的に筋の通ったズレを作る」ことを覚えます。 質量だけ動かすと、現実に存在しない物体ができます（§02）。

答えと解説を見る
    self.model.body_mass[bid] *= mass
    self.model.body_inertia[bid] *= mass

密度を変えたのと同じ状況になります 形は変えずに中身の詰まり方だけ変える、ということです。 質量も慣性も同じ倍率で動きます。

body_inertia は 3 要素の配列です *= で3 つとも掛かります。 [0.01537822, 0.01537822, 0.00013103] がこの振り子の値です。

確かめ方 mass=1.0 にしたとき、公称モデルと 1 ビットも変わらないはずです。 §02 の校正がこれを見ています。

課題 2 — 観測のノイズと遅延

_sensed() を書きます。遅延は「古い観測を返す」だけで作れます。

  def _true_obs(self):
    theta = self.data.qpos[0]
    omega = self.data.qvel[0]
    return np.array([np.cos(theta), np.sin(theta), omega], dtype=np.float32)

  def _sensed(self):
    obs = self._true_obs()
    if self.obs_noise > 0:
      obs = (obs + self.rng.normal(0, self.obs_noise, 3)).astype(np.float32)
    self.buf.append(obs)
    return ???                           # ← ここだけ考える（delay ステップ前の観測）

ヒント self.buf はいままでの観測を順に貯めた配列です。 最後の要素がいまの観測。 エピソードの最初は貯まっていないので、そこをどうするかも考えてください。

答えと解説を見る
    return self.buf[max(0, len(self.buf) - 1 - self.delay)]

len(self.buf) - 1 がいまの観測 そこから delay 個さかのぼります。 delay=0 ならいまの観測がそのまま返り、 遅延なしと完全に同じになります。

max(0, ...) が要る理由 エピソードの最初は buf が 1 個しかありません。 max が無いと負のインデックスになり、 Python は末尾から数え始めてしまいます—— 「最新の観測」を返すという、遅延と正反対の動きです。 エラーにならないので気づけません。

reset で self.buf = [] を忘れずに 消さないと前のエピソードの観測が残ります。

課題 3 — 頑健性テストを回す

train/eval.py に追加します。 採点の中身は evaluate() と同じで、環境だけ差し替えます。

from envs.perturbed import PerturbedPendulum


def test_robust(policy, n_ep=10, steps=500, **kw):
  """kw をそのまま PerturbedPendulum に渡す"""
  totals, ups = [], []
  for ep in range(n_ep):
    env = TimeLimit(PerturbedPendulum(noise_seed=ep, **kw), max_episode_steps=steps)
    obs, info = env.reset(seed=ep)
    env.action_space.seed(ep)
    total, up = 0.0, 0
    for t in range(steps):
      obs, reward, terminated, truncated, info = env.step(policy(env, obs))
      total += float(reward)
      if -np.cos(env.unwrapped.data.qpos[0]) > 0.95:
        up += 1
      if terminated or truncated:
        break
    totals.append(total)
    ups.append(up)
  return np.mean(totals), np.mean(ups)
